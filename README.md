# MAI-Thinking-1 / Rocket RL 레시피 — 구현 가능한 정리 + numpy 레퍼런스

Microsoft AI가 사내 RL 인프라 **Rocket**으로 MAI-Thinking-1(MAI Base 1)과 MAI Base 2(3조 파라미터)를 증류 없이 후학습한 방법을, 다른 프레임워크로 옮길 수 있게 정리했다.

- `docs/METHOD.md` — 구현 사양서(수식·하이퍼파라미터·수치 불일치 해법·자기증류·미기재 항목·주장 강도).
- `src/mai_grpo.py` — 손실·제어기·필터·보상·staleness 를 토큰 로그확률 수준에서 구현(PyTorch/JAX 이식용). 원문에 없는 선택은 `ASSUMPTION:` 표시.
- `tests/test_mai_grpo.py` — 12개 단위테스트(유한차분 그래디언트 포함). `python3 tests/test_mai_grpo.py`.
- `src/demo_entropy_control.py`, `src/ablation_k_only.py` — 표 정책 메커니즘 점검(성능 판정 아님).
- `docs/PREREG.md` — GPU 소규모 LLM 재현 사전등록(튜닝된 DAPO·엔트로피 보너스 기준선, 같은 계산량).

## 핵심 (자세한 건 METHOD.md)
토큰 레벨 GRPO + **엔트로피 적분제어로 움직이는 상한 클립**(ε=0.6, k∈[0,2.5], H*=0.3) + **외부 비율 클립**(r_max=50) + early-exit(16개, 통과율 0.05–0.8)·통과율 필터(0.1–0.8, G=128) + **top-p 마스크 재생** + 길이 커리큘럼(8k→128k) + 5스텝/갱신·8갱신 staleness 상한 + bf16·라우팅 재생(→ Rocket 2는 학습–추론 **비트 일치**) + 붕괴 시 **자기증류 재시작**.

## 점검 결과 (정직하게)
- 단위테스트 12/12 통과.
- 표 toy에선 엔트로피 제어기가 사실상 개입하지 못했다: 통과율 필터가 먼저 학습을 멈추게 하거나(54–61% 반복), 상한이 안 걸려 k가 무효였다. 상한이 걸리는 조건에선 k를 키우면 엔트로피가 오히려 약간 줄었다(0.469→0.446, 5시드 동일 방향) — 상한 완화는 양의 어드밴티지 토큰을 키우므로, 그 토큰이 이미 우세한 답이면 쏠림을 가속한다.
- 즉 이 기법의 이득 여부는 LLM 규모에서 튜닝된 기준선과 같은 계산량으로만 판정 가능 → PREREG.md.
- "Opus 4.8 추월" 주장은 사내 집계 벤치의 자기보고(수치 미공개). 공개된 MAI-Thinking-1 벤치는 경쟁권이지 선두 아님.
