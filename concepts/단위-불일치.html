단위 불일치

한 줄

원문을 정확히 읽어도, 그 수가 세는 단위와 내가 필요한 단위가 다르면 틀린다. 파생표기-함정 이 “원문 대신 파생물을 읽어서” 틀리는 것이라면, 이것은 원문을 제대로 읽고도 틀리는 경우다. 읽기의 문제가 아니라 대응의 문제다.

왜 별개 개념인가 — 파생표기 함정과의 경계

  • 파생표기-함정: license.spdx_id: NOASSERTION 을 읽고 “라이선스 없음”이라 결론 → 원문(LICENSE 본문)을 안 봤다. 처방 = 원문을 봐라.
  • 단위 불일치: 모델카드 원문에 “552B” 라고 정확히 쓰여 있고 그걸 정확히 읽었다. 그런데 내가 필요한 건 체크포인트 크기(763B) 였다. 처방 = 원문을 보는 것으로 해결되지 않는다. “이 수가 무엇을 세는가”를 물어야 한다. → 🎯 두 함정은 처방이 다르므로 분리해야 한다. 원문 대조를 아무리 철저히 해도 단위 불일치는 잡히지 않는다.

2026-09-11 배치의 5개 사례 — 다섯 가지 다른 단위, 같은 실패

① 문서의 단위 ≠ 대상의 단위 — Nex-N2.5-Pro · Nex-N2.5-mini 두 모델의 README.md md5가 동일(볼트 실측 f706fcb33c93, 16,726B). 패밀리 공용 카드다. 카드 안 벤치 표에는 mini · Pro · Max · Opus 5 · GPT-5.6 Sol · Kimi-K3 · GLM-5.3 · DS-V4-Pro-0813 · Qwen3.8-Max 열이 나란히 있다. → 카드 1개가 모델 3개를 덮는다. “이 모델의 카드”라는 가정이 깨진다. 열 매핑을 확인하지 않으면 다른 모델의 점수를 인용한다.

② 백본 파라미터 ≠ 체크포인트 파라미터 — DeepSeek-V4.1-Flash 카드 “552B 백본” vs safetensors 실측 763,205,315,794(≈763B). 차이는 Engram 조건부 메모리 196B(별도 희소 접근 파라미터). 552 + 196 ≈ 748, 나머지는 비전·임베딩. → 둘 다 참인 수인데 세는 대상이 다르다. 어느 쪽을 쓰든 어느 쪽인지 밝혀야 한다.

③ 총 파라미터 ≠ 활성 파라미터 — Nex 패밀리 공통 qwen3_5_moe MoE인데 활성 파라미터가 카드에 없다. 총 35B/397B만으로는 추론 비용을 계산할 수 없다. → 그리고 이 부재가 ④를 만든다: “Max는 Pro보다 4배 크다” 는 총 파라미터 기준이고, 활성 기준으로는 다를 수 있다.

④ 비교 기준 모델이 다름 — NCP-ArchPreview “전체 토큰의 51.3% 만으로 OLMo-3-7B의 최종 손실 도달” — 강력해 보이지만 이 모델은 8.9B, 비교 대상은 7B다(파라미터 27% 많음). 논문이 별도로 제시한 공정 비교: “파라미터 정렬 8.9B 베이스라인 대비 연산 85%” → 이득 15%. → 51.3%와 85%는 다른 비교의 수다. 앞의 것만 인용하면 과장이 된다(논문 자체는 둘 다 게시했다 — 정직한 쪽).

⑤ 자기보고 요약 ≠ 자기 표 — vercel-skills 같은 README의 두 자동생성 블록이 서로 다르다: 산문 요약 “OpenCode, Claude Code, Codex, Cursor, and 75 more” = 79 / 표의 --agent 식별자 실카운트 = 78(69행, 다중 식별자 3행 포함). → 원문이 둘인데 값이 다르다. 볼트는 어느 쪽이 맞는지 판정하지 못했다(생성 스크립트 미확인). → 병기 외에 정직한 방법이 없다.

⑥ 보너스 — Clodds: GitHub description “1000+ markets” vs README “10 prediction markets + 7 futures exchanges”. 개별 계약 수 vs 거래소 수로 보이나 정의가 없다. 큰 숫자를 앞세우는 전형.

검증 규칙 (볼트 ingest 절차에 추가)

수치를 위키에 옮길 때 네 가지를 함께 적는다:

  1. 무엇을 세는가 — 백본인가 체크포인트인가, 총인가 활성인가, 거래소인가 계약인가
  2. 무엇과 비교했는가 — 같은 크기인가 다른 크기인가. 다르면 공정 비교 수치를 같이 찾는다
  3. 이 문서는 몇 개를 덮는가 — 모델카드·README가 패밀리 공용인지 확인(md5·열 헤더 확인)
  4. 같은 문서 안에 다른 값이 있는가 — 산문 요약과 표가 어긋날 수 있다 → 한 줄 요약: 수를 옮기기 전에 단위를 옮겨라.

왜 이 함정이 특히 위험한가

단위 불일치는 모든 검증을 통과한다. 원문 대조도 통과하고, API 실호출도 통과하고, 2회 측정 고정값도 통과한다. 수 자체는 정확하기 때문이다. → 파생표기-함정 은 원문을 보면 잡힌다. 이건 원문을 봐도 안 잡힌다 — 비교 대상이나 세는 범위는 다른 문서에 있거나 아예 없다(Nex의 활성 파라미터처럼). → 🎯 그래서 처방이 “더 열심히 읽어라”가 될 수 없다. “이 수가 내 질문에 답하는 수인가”를 묻는 별도의 단계가 필요하다. → 측정도구-먼저-반증 은 계측기를, 파생표기-함정 은 출력 포맷을, 이 개념은 눈금을 의심한다.

미해결 질문

⑤(vercel-skills 79 vs 78)처럼 원문이 복수이고 서로 모순될 때 볼트의 판정 절차가 없다. 현재 처방은 “병기”인데, 그건 판정 회피다. 어느 원문이 상위인지 정하는 규칙이 필요하다 — 후보: 생성 스크립트가 있으면 스크립트가 최상위 원문이다.

①번 재현 (패밀리 공용 카드) — MiniCPM5-2B-GGUF

09-11에 Nex-N2.5-Pro·Nex-N2.5-mini 의 README md5 동일로 잡아 이 개념으로 승격시킨 함정이, 하루 만에 OpenBMB 에서 다른 형태로 나왔다. 볼트 실측: GGUF 카드 md5 fee94d29d80b075eebbfc9282540f867(112,379B) vs 원본 BF16 카드 efedd1985b8b1ebe6877c25243feda1f(112,204B). 전체 diff 결과 실질 차이는 👈 you are here 마커가 167행 → 171행으로 옮겨간 것뿐(나머지는 빈 줄 1개와 표 공백 패딩). → 즉 카드 본문은 여전히 BF16 원본을 설명한다. 평균 53.9 · IFEval 86.7 · LCB v6 69.1 등은 전부 무양자화 모델 점수이고, 이 리포가 배포하는 Q4_K_M(4비트) / Q8_0 의 성능은 어디에도 없다. → 09-11 유형과의 차이: 저번은 카드 1개가 모델 3개를 덮는 형태(같은 표 안에서 열 매핑 문제), 이번은 카드 1개가 원본과 양자화본을 덮는 형태(같은 수치가 다른 아티팩트에 붙는 문제). → 🎯 규칙 추가: 양자화·변환 리포(GGUF · GPTQ · AWQ · NVFP4 · MLX)는 원본 카드를 복사한다고 기본 가정한다. 수치를 옮기기 전 원본 카드와 md5 비교, 같으면 “수치는 원본 것” 명시. → 벤더 패턴으로 기억: OpenBMB는 하나의 모델을 배포 형식별 리포로 쪼개고 카드를 공유한다(GGUF · GPTQ · DSpark-GGUF · 1B-GGUF). 같은 함정이 반복 예정.

②번 재현 (백본 ≠ 체크포인트) — VibeVoice-ASR-Streaming-7B

09-11 DeepSeek-V4.1-Flash(카드 552B 백본 vs safetensors 763B)와 같은 형태가 Microsoft 에서 나왔다. 볼트 실측: safetensors = {"BF16": 8674021857} → 8.67B. 모델명은 ...-7B. 차이 +24%. → MiniCPM5-2B 의 ‘2B’=2.52B 같은 반올림이 아니다. 추정 원인은 7B LM 백본 + 오디오 인코더 타워 이지만 — 카드가 2,236B밖에 안 되고 파라미터 설명이 전혀 없다. 즉 확인할 방법이 문서에 없다. → 실무 영향: VRAM을 7B로 잡으면 BF16 기준 약 17.3GB 필요한 모델을 14GB로 오산한다. → ⚠️ raw는 이 항목을 점검하지 않았다. 09-11에 볼트가 직접 실측했던 safetensors 총계 대조가 raw의 체크리스트에 없다. 다만 AgentGrad 순차 개입 원칙에 따라 이번 배치에서 raw에 추가 요청하지 않는다(요청은 quote-integrity 1건으로 고정).

⑤ 새 유형 후보 — 벤치마크 이름의 단위 (SWE-Bench-Pro-Verified)

“SWE-bench” 라는 이름은 최소 4~5개 변종을 가리킨다: 원조 · Verified · Pro · Pro Verified · Multimodal · SWE-bench-Science. 09-12 SWE-Bench-Pro-Verified 는 SWE-Bench Pro 가 유출·리워드 해킹으로 오염됐고 교정 후 일부 모델 점수가 크게 하락함을 보였다. → ⚠️ 볼트 기존 수치가 자동 무효가 되는 것은 아니다 — MiniCPM5-2B 가 인용한 것은 SWE-bench Verified 로 다른 벤치다. 여기서 혼동하면 이 교훈을 잘못 적용한다. → 🎯 그래서 규칙은 이것이다: 같은 이름의 벤치가 다른 것을 센다. 이름만으로 동일 벤치라고 가정하지 말고 변종·버전을 병기한다.
