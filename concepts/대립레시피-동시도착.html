대립 레시피 동시 도착

🔴 2026-10-04 "층간 동형 쌍" n=3 승격 보류 — 그리고 "동시도착 ≠ 대립" 사례 1건

① n=3 보류 (DMM)

수집기가 DMM 을 “층간 동형 쌍” 3번째 층(다중에이전트 조정) 으로 제안했다. 🔴 보류한다. 기록된 쌍(HC-DLM ↔ Beyond-Memory-PoS)의 공유 처방은 “지속되는 단일 상태” 이고, DMM 의 의도는 분산·이산이며 거부 대상이 일회 확정이다. ⇒ ⚖️ 정의를 “일회 확정 거부”로 넓히면 반복적 생성 절차 거의 전부가 들어온다(같은 배치 E-MoE 포함 — 마스크 확산 자체가 반복이다). n 을 키우는 대가로 “무관한 분야의 독립 도달”이라는 신호가 희석된다. ✅ 처리: n=2 유지 + 인접 패턴 “일회-확정-거부” 분리 기록. 📌 승격 조건: 같은 처방이 “지속 상태” 형태로 3번째 층에서 나오면 그때 n=3 으로 올린다. 🎯 확정적인 배치 수준 관측 1건: 확산의 “반복 정제” 착상이 오늘 두 층에서 나타난다 — E-MoE(확산 언어모델 본체) · DMM(확산 착상을 다중에이전트 조정으로 차용 · “inspired by denoising” · 확산 모델을 쓰지 않는다). ⇒ 🏆 “기법의 이식”이 관측된 사례이고, 이것은 동형 쌍과 다르다 — 한쪽이 다른 쪽을 명시적으로 참조한다(독립 도달이 아니다).

② 동시도착은 맞고 대립은 성립하지 않는다 (E-MoE ↔ HC-DLM)

✅ 전제 전건 확증: 같은 문제(위치별 인수분해의 소수 스텝 품질 저하) · 같은 벤치(LM1B) · 반대 처방(연속 잠재 ↔ 이산 MoE 라우팅 잠재) · 🏆 심지어 E-MoE 가 상대 계열을 명시 비판한다(“continuous Gaussian latent, trained as a VAE … prone to posterior collapse, where the latent is silently ignored”). 🔴 그런데 대조가 불가능하다 — E-MoE 초록에 정량 수치가 0개다. 볼트는 HC-DLM 쪽 수치를 갖고 있다(LM1B Gen PPL 75.5 @ 118M · 같은 표에서 자기회귀 Transformer 66.7 이 더 좋다). ⇒ ⚖️ 한쪽만 숫자가 있으면 대립 레시피가 아니라 짝이 안 맞는 비교다 → 비매칭-비교. 🏆 판정: “동시도착” 인정, “대립” 보류. 📌 E-MoE PDF 의 LM1B 수치를 얻는 순간 이 개념의 가장 깨끗한 사례가 된다 — 같은 벤치 · 같은 문제 · 반대 처방 · 명시적 상호 비판 ⇒ actionable 최우선. 🔴 그리고 비판 대상이 어제 수집분이다. HC-DLM 의 자기 차별점이 “잠재를 유일한 지속 생성 상태로 만든다” 이므로 posterior collapse 가 일어나면 이 설계에서 가장 치명적이다(백업 상태가 없다). ⚠️ 볼트 HC-DLM 페이지에 posterior collapse 언급이 0건이고 Gaussian 단정 근거도 없다 — “HC-DLM 이 이 문제를 무시했다”고 적지 않는다. 계열 소속은 높은 가능성 · 분포 형태 미확정이다.

🆕 2026-10-03 "직교 쌍"에 3번째 사례 + 새 유형 "층간 동형 쌍"

① 직교 쌍 3번째 — 같은 배치에서 비용을 깎는 쪽과 판단을 더하는 쪽이 동시 도착했다:

  • 깎는 쪽: caveman 출력 압축(자기 주장 65%) · ★109,249 · 트렌딩 2위
  • 더하는 쪽: superpowers 스킬 강제 계층 · ponytail 최소코드 규범 · Beyond-Memory-PoS belief 유지(🔴 토큰 비용 증가, 초록 미공개) ⇒ ⚖️ 배타적이지 않고 곱해진다(10-02 결론 유지). 📌 그런데 오늘 처음으로 “더하는 쪽”의 비용이 명시적 쟁점이 됐다 — PoS 는 추론시 프레임워크라 매 턴 토큰을 더 쓴다. 🔴 곱셈이 성립하려면 압축이 belief 를 깎지 않아야 하고, 그 간섭은 아무도 측정하지 않았다.

② 🆕 새 유형 — “층간 동형 쌍”: 서로 다른 층에서 같은 처방이 같은 날 나왔다

논문층처방
HC-DLM디코딩(생성 과정)“잠재를 유일한 지속 생성 상태로 만든다” — 매 스텝 토큰을 읽어내고 다음 잠재의 scaffold 로 되먹인다
Beyond-Memory-PoS에이전트 루프”명시적 belief 상태를 지속적으로 구성·유지” — 현재 상태 + 미해결 요구를 결정 컨텍스트로
⇒ ⚖️ 둘 다 “흩어진 이력/독립 샘플링” 대신 “지속되는 단일 상태”를 처방한다. 📌 직교 쌍(같은 층·반대 방향)과 다르다 — 이것은 다른 층·같은 방향이다. 🔴 서로를 인용하지 않는다(같은 날 게시 · 다른 분야 · HC-DLM=UIUC+Amazon · PoS=Alibaba).
🎯 그래서 이 개념의 가치가 갱신된다: 종전에는 “대립하는 처방이 동시에 온다” 를 봤다. 오늘은 “무관한 두 분야가 같은 처방에 독립적으로 도달한다” 를 봤다. ⇒ 📌 후자가 더 강한 신호다 — 수렴은 우연이기 어렵다. 🔴 단 n=2 이고 “지속되는 상태”가 양쪽에서 같은 것을 뜻하는지 미검증이다.

③ 같은 축의 또 다른 쌍 — 커버리지를 통화로 쓰는 2건 On-Policy-or-Off-Policy-Distillation(KL 방향이 “task performance and output coverage” 를 결정) ↔ Sharpening-Tax(후처리가 pass@1 올리고 solution coverage 깎음). 증류 목적함수 쪽과 RL 후처리 쪽에서 같은 날 독립적으로 “커버리지”를 핵심 비용으로 지목했다. 🔴 단 On-Policy 쪽은 커버리지를 정의하지 않고 측정 지표도 적지 않는다 — Sharpening Tax 쪽은 pass@K 로 조작화한다. 같은 단어가 같은 것을 재는지 미확인.

🎯 핵심 — 2026-09-27 배치에 포스트트레이닝 RL 의 정반대 답 두 개가 같이 왔다

  • Rufus-Air: 8단계 직렬. SFT → Reasoning RL → Coding RL → Instruction-Following RL → General Agent → Coding Agent → Search Agent → RLHF. 🎯 주장하는 원칙은 “리워드 신뢰도가 단계 순서를 정한다” — 검증 가능한 리워드를 먼저, 애매한 것을 나중에.
  • MiMo-V2.6-Pro-RL: 단일 혼합 런(“You Only RL Once”). 코딩·일반 에이전트·비주얼·사이버보안을 한 배치에 섞어 한 번에 돌린다. 🎯 주장하는 이득은 “학습에서 본 적 없는 하니스로도 전략이 전이된다”.

🔴 분리와 혼합은 양립하지 않는다. Rufus-Air 의 전제는 단계를 나눠야 리워드 품질을 관리할 수 있다이고, MiMo 의 전제는 섞어야 전이가 생긴다이다. 한쪽이 맞으면 다른 쪽은 차선이다. 📌 그런데 둘 다 상대를 언급하지 않고, 둘 다 자기 방식으로 좋은 결과를 얻었다고 보고한다.

🔴 이것이 볼트에 주는 문제 — 비교 불가능성이 구조적이다

왜 어느 쪽이 맞는지 판정할 수 없는가:

  1. 베이스 모델이 다르다 — Rufus-Air 는 GLM-4.5-Air-Base(106B-A12B), MiMo 는 자사 1.024T 옴니모달.
  2. 평가 벤치가 겹치지 않는다 — Rufus-Air 는 벤치 이름조차 초록에 없다, MiMo 는 18개 벤치를 제시하나 3개가 자사 명칭이다.
  3. 목표가 다르다 — Rufus-Air 는 재현 가능한 레시피 공개, MiMo 는 플래그십 성능. 최적화 대상이 다르면 설계가 달라지는 것이 정상이다. 🎯 그러므로 “대립”이라는 볼트의 판정 자체를 조심해야 한다 — 두 논문은 같은 문제의 다른 답이 아니라 다른 문제의 각자 답일 수 있다. 이 구분을 볼트는 초록·카드 범위에서는 할 수 없다. 📌 이것이 비매칭-비교 의 메타 층위 사례다. 지금까지 이 개념은 하나의 표 안에서 조건이 다른 값을 나란히 놓는 것을 다뤘다. 여기서는 볼트가 서로 다른 두 소스를 나란히 놓으려는 유혹이 문제다 — 비매칭 비교를 벤더가 하는 것이 아니라 독자가 만들 수 있다.

🎯 그래도 건질 수 있는 것 — 교집합이 하나 있다

두 논문은 방법이 반대인데 한 지점에서 같은 진단을 한다: 이진 pass/fail 리워드는 부족하다.

  • Rufus-Air: “리워드 신뢰도” 가 순서 결정 기준이다 = 리워드에 품질 등급이 있다는 전제
  • MiMo: GAR(Groupwise Advantage Reranking) — “이진 pass/fail 로는 통과한 해답들끼리 서열화할 수 없다” 며 통과 trajectory 를 온라인 서열화 🎯 즉 “통과했다”와 “잘 통과했다”를 구분해야 한다는 데는 둘 다 동의한다. 방법은 반대인데 문제 인식은 같다. 📌 이것이 검사가능성-공사 의 5번째 외부 생태계 근거다. 볼트는 09-20부터 “✅확인/🔴확인 불가 2값이 부족하다” 를 알고 있었고 8일째 3값화를 구현하지 않았다. 오늘 대립하는 두 진영이 같은 칸의 필요성을 각자 독립적으로 말했다 — 합의가 아니라 수렴이므로 근거가 더 강하다.

볼트 절차 — 대립을 발견하면 무엇을 하는가

  1. 대립을 기록하되 승자를 정하지 않는다. 근거가 없으면 판정하지 않는 것이 규칙이다.
  2. 교집합을 먼저 찾는다. 반대되는 두 방법이 동의하는 지점은 한쪽 진영의 주장보다 강한 증거다.
  3. 비교 가능 조건을 명시한다 — 무엇이 같아야 비교가 성립하는지 적어 두면, 나중에 그 조건이 갖춰진 소스가 올 때 알아볼 수 있다. → 이 건의 조건: 같은 베이스 모델 + 겹치는 제3자 벤치. 둘 중 하나라도 만족하는 후속 소스가 오면 재판정한다.
  4. ⬜ 미확인: 두 논문이 실제로 상대를 인용하는지(arXiv 본문·기술보고서 미열람). 초록·카드에 없다는 것만 확인됐다.

🔄 2026-10-01 — 3쌍 동시 도착 (하루 안에)

  1. 증류 축 — RIDE(1위 · 교사를 넘어선다: 표현공간 잔차 외삽) ↔ UniEvo-VL(2위 · 교사를 없앤다: 같은 모델 + 정보 비대칭). 🎯 데일리 1·2위가 같은 문제의 반대 처방이다.
  2. 자기진화 축 — UniEvo-VL·AREX-2(자기 신호로 개선된다, 수치 제시) ↔ False-Frontiers(자기 신호 루프는 같은 오류에 합의한다, co-cheating 수치 제시). 🔴 낙관과 비관이 둘 다 정량 증거를 들고 같은 날 왔다.
  3. 지식 보강 축 — EvoDuet(파라미터 고정 · 루프와 검색 쿼리만 진화) ↔ RIDE·AREX-2(파라미터 학습 필수). 🎯 “모델을 고칠까, 하네스를 고칠까” 가 같은 배치에서 갈린다 → 하네스-설계-축.

🎯 볼트 적용 — 대립쌍은 선택지가 아니라 제약 목록으로 읽는다

세 쌍 중 볼트가 지금 실행 가능한 것은 파라미터 고정 쪽뿐이다(학습 파이프 0 · 체크포인트 쌍 0 · 통합 멀티모달 0). 따라서 오늘 배치의 실행 가능 집합은 EvoDuet 검색 게이트 + False-Frontiers CrossFit 채점경로 분리 두 개로 좁혀진다 — 둘 다 모델 없이 규칙만으로 구현된다.

🎯 AgSpec 초록 원문: “suits coding agents that repeatedly reproduce code, logs, and earlier attempts.” 📌 즉 ponytail·PyRUA-Lean 이 “비효율”로 취급하는 바로 그 성질이 AgSpec 에서는 자원이다.

🏆 그러나 이번 쌍은 배타적이지 않다 — 곱해진다

🔴 이 개념의 기존 사례들은 대개 양립 불가였다(09-30 증류 축: RIDE 교사를 넘어선다 ↔ UniEvo-VL 교사를 없앤다). ✅ 오늘 쌍은 다르다: ponytail 은 출력을 줄이고, AgSpec 은 남은 출력을 빨리 낸다. 두 이득은 서로의 전제를 깨지 않는다. 🎯 그래서 이 쌍의 교훈은 “어느 쪽이 맞나”가 아니라 “비용의 축이 두 개다” 이다 — 양(토큰 수) 과 속도(토큰/초). 📌 같은 “비용 절감”이라는 말이 서로 다른 분모를 가진다. ⚖️ 판정: 대립이 아니라 직교다. 이 개념의 하위유형으로 “직교 쌍” 을 둔다 — 동시 도착했으나 선택을 강요하지 않는 경우.

🎯 세 번째 축도 같은 배치에 있다

CorrGRPO 는 보상을 여러 개로 쪼갠 뒤의 정규화를 다룬다. 📌 09-27 배치의 “이진 pass/fail 은 부족하다” 처방(=쪼개라)의 비용이 바로 CorrGRPO 가 고치는 결함(큰 스케일 보상이 지배)이다 ⇒ 두 논의는 같은 설계 결정의 앞뒤다. 🎯 이것도 대립이 아니라 순서다.
