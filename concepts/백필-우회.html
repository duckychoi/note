백필 우회 (Backfill Bypass)

2026-09-15 — ✅ 해결됐다. 가정을 없앤 게 아니라 순서를 바꿨다

볼트는 09-14에 “쿼터가 고정인 한 백필은 항상 발생한다고 가정해 달라” 고 요청했다. 수집기는 가정을 채우는 대신 백필이 필요 없는 순서로 재설계했다:

  1. 쿼터보다 훨씬 넓은 슬레이트를 먼저 확보 (GitHub: daily/weekly/python/jupyter 4개 트렌딩 페이지 병합 67건 → 필터 후 51건)
  2. 슬레이트 전체에 중복 필터 1회 적용 → NEW풀 확정
  3. 쿼터를 NEW풀 상위에서만 채움

이 순서에는 “빈자리를 채우는 행위” 자체가 없으므로 백필이 구조적으로 0이다.

결과 (볼트 독립 검증 완료 · 2026-09-15): 배달 13건 전건을 org/name 리터럴 grep + 소스 파일명 조회로 재검사 → 중복 0 / 13건 전부 NEW. 논문 5건도 arXiv ID grep 0히트. 09-14 배치의 중복 61.5%(8/13) 에서 0%(0/13) 으로 회복.

🔴 성립 조건 — NEW풀 ≥ 쿼터일 때만 성립한다 이번엔 17/14/9 ≥ 5/5/3 으로 여유가 있었다. NEW풀이 쿼터에 미달하면 슬레이트를 넓혀야 하고, 그때는 확장분에도 2단계를 다시 적용해야 한다. 수집기가 이 조건을 스스로 명시했다 — 조건을 아는 해법은 조건을 모르는 해법보다 강하다.

📌 일반형: 백필 우회는 더 열심히 필터링해서 고치는 문제가 아니라 “채우기”라는 연산을 파이프라인에서 제거해서 고치는 문제다. 🔗 다만 같은 배치에서 중복 탐지의 다른 실패가 드러났다 → 메타데이터-부재-추론(basename grep 오탐 38히트 / huggingface-transformers).

정의

필터로 후보를 걸러내 자리가 비면, 그 자리를 다음 순위 후보로 채운다. 이때 같은 필터를 다시 적용하지 않으면 — 필터는 작동한 것이 아니라 “누가 통과했는지”만 뒤집는다. 필터는 실행됐고, 로그에도 “N건 제외” 가 남는다. 그래서 실패가 보이지 않는다. 최종 산출물의 탈락률이 아니라 통과율을 봐야 드러난다.

발견 경위 — 볼트가 2026-09-14 배치에서 정면으로 당했다

raw.md 의 2026-09-14 자동수집은 다음을 명시했다:

중복 탐지: GitHub 4건(vxcontrol/pentagi·multimodal-art-projection/YuE·SnailSploit/Claude-Red·alphaXiv/OpenResearch) + HF 모델 4건(Edge0/Edge0-35B-A3B-preview·MiniMaxAI/MiniMax-H3·google/timesfm-3.0-pytorch·tencent/AuK) 볼트 기보유 → 전량 제외. 총 후보 8건 탈락. 선정 규칙: GitHub = AI/ML + ⭐1,000+ + 볼트 미보유 → 당일 스타 증가량 상위 5 · HF 모델 = 트렌딩 30선 중 볼트 미보유 → 상위 3

중복 탐지는 실제로 작동했다. 8건을 정확히 잡아냈고 오탐도 없었다. 그런데 그렇게 해서 배달된 13건 중 8건이 볼트에 이미 있었다.

채널쿼터탈락배달배달분 중 중복
GitHub 트렌딩5455 / 5 (100%)
HF 데일리 논문5050 / 5 (0%)
HF 모델 트렌딩3433 / 3 (100%)

🎯 이 표가 메커니즘을 확정한다

탈락이 발생한 두 채널에서만 중복이 100%다. 탈락이 0인 채널에서는 중복도 0이다. 우연이 아니다. 필터가 비운 자리를 채운 후보들이 곧 중복이었다.

즉 순서가 이렇다:

  1. 상위 후보 슬레이트를 뽑는다
  2. 중복 필터를 적용 → 8건 제거, 자리 8개가 빈다
  3. 쿼터(5/5/3)를 맞추려고 다음 순위로 채운다
  4. 🔴 채운 것들에는 필터를 다시 돌리지 않는다

논문 채널은 2단계에서 아무도 안 걸렸으므로 3단계가 없었고, 그래서 오염되지 않았다. 논문이 중복에 강한 건 규칙이 좋아서가 아니라 백필이 발생하지 않아서다.

왜 안 보이는가 — 로그가 성공만 기록한다

백필 우회의 고약한 점은 관측 지표가 정상으로 보인다는 것이다.

  • “중복 8건 탈락” → 필터가 작동했다는 증거처럼 읽힌다
  • 09-13 배치는 “후보 16건 탈락, 오탐 0” 으로 칭찬까지 받았다
  • 탈락 건수는 필터의 입력에 대한 통계이고, 우리가 알고 싶은 건 출력의 오염도다

🔴 볼트도 2배치 동안 못 봤다

09-12·09-13 볼트 판정은 중복 탐지를 “유지됨 · 오탐 0” 으로 평가했다. 탈락 목록만 검증했고 배달 목록은 검증하지 않았다. 09-13 배치가 “전량 신규 13건 · 중복 0” 이었던 건 사실이지만, 그때 백필이 몇 건 발생했는지는 아무도 세지 않았다. 운이 좋았을 가능성을 배제할 수 없다.

일반형 — 이건 수집기만의 문제가 아니다

같은 구조는 “거른 뒤 정원을 채우는” 모든 파이프라인에서 발생한다.

  • 검색/추천: 부적합 결과를 제거하고 다음 페이지에서 끌어와 K개를 맞출 때
  • 데이터 정제: 불량 샘플을 버리고 배치 크기를 맞추려 재샘플링할 때
  • 에이전트 후보 선택: 도구/스킬 후보를 걸러낸 뒤 빈 슬롯을 채울 때 → COBRA-Skills 의 “dynamically evolving candidate space” 가 정확히 이 위험 구간이다
  • 선호 데이터: 의심 쌍을 버리고 데이터량을 맞추려 다른 쌍을 넣을 때 → PLC-DPO 가 “필터링 대신 교정” 을 택한 이유와 맞닿는다

🎯 PLC-DPO 가 같은 배치에 있다는 게 우연이 아니다

PLC-DPO의 재정의 — “merely filtering suspicious examples” 가 아니라 “actively correcting” — 는 필터링이 데이터를 잃고, 그 잃은 자리를 무언가로 메워야 한다는 문제를 정면으로 피한 설계다. 버리지 않으면 채울 필요가 없고, 채우지 않으면 우회가 없다.

검사 규칙 (볼트 채택)

탈락률이 아니라 통과율을 감사한다

  1. 필터를 통과해 최종 배달된 항목 전수에 같은 필터를 다시 돌린다. 탈락 목록 검증으로 대체하지 않는다
  2. 백필 발생 건수를 기록한다 — 몇 자리가 비었고 몇 개를 채웠는지. 백필 0인 채널과 그렇지 않은 채널을 분리해서 본다
  3. 쿼터가 고정(5/5/3)이면 백필은 항상 발생한다고 가정한다. 고정 쿼터 + 필터 = 백필 우회의 표준 조건
  4. 채널별로 따로 집계한다 — 이번에도 채널을 합쳐 보면 “13건 중 8건 중복(62%)“이지만, 쪼개야 100%/0%/100% 라는 신호가 보인다

인접 개념과의 경계

  • 짝-아티팩트-조회 — 무엇을 찾을지의 문제(논문↔가중치↔양자화판이 다른 이름). 백필 우회는 언제 찾을지의 문제다. 이번 8건은 basename 완전 일치여서 조회 방법은 멀쩡했다
  • 한정어-탈락 — 인용한 문장에 조건이 빠지는 것. 백필 우회는 인용이 아니라 절차의 순서 문제
  • 측정도구-먼저-반증 — 측정 지표(탈락 건수)가 실제 목표(출력 오염도)와 어긋난 사례이므로 이 개념의 하위 사례로 볼 수 있다
  • 선택비용과-중복성 — 선택기를 어디에 얼마나 쓸까의 문제. 백필 우회는 선택기를 두 번 돌려야 할 자리에 한 번만 돌린 경우
