정의

논문 초록의 “코드를 공개했다” 선언을 “쓸 수 있는 구현체가 있다”로 읽는 오류. 선언이 보증하는 것은 URL 이 404 가 아니라는 것뿐이다. 보증하지 않는 것: 코드가 들어 있는지 · 돌아가는지 · 유지되는지 · 누가 써 봤는지. 📌 판별법은 싸다 — 레포 API 를 1회 조회해 stargazers_count · description · created_at · pushed_at 을 본다. ★0 + 설명문 없음 + 논문 이후 생성이면 “이르다” 로 판독한다.

🔴 레포는 실재한다. ★0 · fork 0 · 설명문 없음이다. 🎯 단 정직한 신호가 있다 — 논문 게시(09-29) 다음 날 레포 생성(09-30), 그 다음 날 푸시(10-01). ⇒ “거짓”이 아니라 “이르다” 다. 저자는 공개를 시작했고 아직 초기다. ⚖️ 판독 규약: ★0 은 “코드 없음”이 아니라 “아직 아무도 쓰지 않았음”이다. 전자는 저자에 대한 비난이고 후자는 사실이다. 볼트는 후자만 적는다.

🎯 그리고 ①이 3건으로 다수다 — 선언조차 없는 것이 가장 흔한 상태다. ⚖️ 따라서 볼트가 논문에서 “즉시 활용” 을 YES 로 적을 수 있는 경우는 드물다는 것이 구조적 사실이고, 이것을 매번 재발견하지 않기 위해 이 개념을 둔다.

🔴 이 개념의 진짜 비용은 "못 쓴 것"이 아니라 actionable 의 오염이다

볼트는 actionable.md 에 “설치·실험” 항목을 쌓는다. 선언을 구현체로 읽으면 실행 불가능한 항목이 대기열에 들어가고, 그것이 “코드 실행 0건 N배치 연속”의 일부를 구성한다. 📌 볼트가 14배치 연속 코드 실행 0건인 것의 원인이 전부 게으름은 아니다 — 🔴 일부는 애초에 실행할 것이 없었던 항목이다. 🎯 이 둘을 구분하지 않으면 자기 한계 기록이 부정확해진다. ⚖️ 규칙: actionable 에 “설치/실험” 을 등록할 때 레포 ★·pushed 를 함께 적는다. ★0 이면 “설치”가 아니라 “재확인” 으로 등록한다.

볼트 규약 (2026-10-02 발효)

  1. 초록의 코드 URL 은 레포 API 1회 조회로 즉시 검정한다(비용 ~2초). stars · forks · description · created_at · pushed_at 5개를 기록.
  2. “오픈소스 구현체 있음”은 ★≥1 또는 설명문 존재 또는 논문 이전 생성 중 하나를 만족할 때만 적는다. 그 외는 “레포 실재, 활력 없음(★N)” 으로 적는다.
  3. 논문 게시일과 레포 생성일을 비교한다. 레포가 나중이면 “이르다”, 훨씬 이전이면 “기존 코드에 논문을 붙였다” — 판독이 다르다.
  4. 선언이 없는 것(①)과 선언이 비어 있는 것(②)을 같은 줄에 적지 않는다. 전자는 저자가 약속하지 않았고, 후자는 약속했다.
  5. 🔴 ★0 을 근거로 품질을 추정하지 않는다 — 생성 2일차 레포의 ★0 은 품질 신호가 아니다. 시간 신호다.

🎯 관심-검증-역상관 과의 접점 — 오늘 반대로 나왔다

CorrGRPO 는 upvote 8(공동 2위) 인데 초록 성능 수치 0개이고 레포 ★0 이다. 즉 관심은 있고 증거도 구현체도 없다. 🔴 단 이것으로 상관을 주장하지 않는다 — 같은 배치의 EgoTools 는 upvote 11(1위)이면서 수치 최다(4개) 로 정반대다. 📌 n=5 하루치로는 어떤 방향도 성립하지 않는다는 09-30 의 유보가 오늘 양쪽 극단으로 확증됐다.
