시계열 예측 파운데이션 모델

LLM의 “대규모 사전학습 → 제로샷 범용화” 패러다임을 시계열 예측 도메인에 적용한 모델군. 도메인별 학습 없이 다양한 시계열 데이터를 예측.

2026-09-03 — TimesFM 3.0 공개 · 이 개념이 에이전트 일색 배치에서 트렌딩 2위를 지켰다

TimesFM GitHub ⭐30,397(트렌딩 2위), 신모델 google/timesfm-3.0-pytorch(생성 2026-08-24 · DL 46,862 · 좋아요 315 · 331M 파라미터 · 라이선스 other) 확인 — 전량 HF/GitHub API 실호출.

📌 이 개념의 위치가 이번 배치에서 선명해졌다. 2026-09-03 자동수집 13건 중 12건이 에이전트·LLM·생성모델이었고, TimesFM 한 건만 다른 축이었다. 그런데 트렌딩 2위다. → 시계열 파운데이션 모델은 AI 담론의 주변부에 있으면서 사용 축에서는 살아 있다. 볼트가 이 개념을 04-11 이후 갱신하지 않은 약 5개월은 담론의 편향이지 이 분야의 정체가 아니었다.

📌 331M이라는 크기가 이 개념의 성격을 말한다. 같은 날 배치의 GLM-5.3 753B, GLM-5.3-Flash 321B, Qwen3.8-Flash-Next 180B 옆에서 TimesFM 3.0은 2,275분의 1이다. 시계열은 스케일 경쟁의 축이 다르다 — 파운데이션 모델이라는 이름을 공유하되 “크게 만들어 범용을 얻는다” 가 아니라 “작게 만들어 어디에나 꽂는다” 쪽이다. CPU·엣지 배포가 현실적이라는 뜻이며, 이는 local-llm 도메인의 관심사와 직접 겹친다.

⚠️ 세대 교체가 아직 안 일어났다: timesfm-2.5-200m-transformers DL 55,036 > timesfm-3.0-pytorch DL 46,862. 신버전이 좋아요는 2.4배(315 vs 134)인데 다운로드는 0.85배다. 공개 10일차라 판정은 다음 회차로 미룬다. ⚠️ 정확도 벤치는 여전히 미확인 — 3.0이 2.5보다 나은지 볼트는 모른다. Kronos와의 비교도 04-11 이후 갱신되지 않았다.

핵심 인사이트

“언어를 이해하는 LLM”이 등장한 것처럼, 2024~2026년에 “시간을 이해하는 파운데이션 모델”이 등장했다. TimesFM(Google)과 Kronos가 이 범주를 개척. 도메인별 모델 학습 없이 제로샷으로 비즈니스 지표·금융 데이터를 예측 가능.

기존 방법 대비 우위

  • Before: Prophet, ARIMA, Informer — 데이터별 학습 필요, 도메인 전문성 필요
  • After: 파운데이션 모델 → 즉시 추론, fine-tuning 없이 새 도메인 적용

실용 적용 범위

  • SaaS 비즈니스 지표(MAU, 매출, 이탈률) 예측
  • 재고·물류 수요 예측
  • 에너지 소비 패턴
  • 금융 자산 변동성 예측 (Kronos)

주의

금융 예측은 과적합·과신 위험 높음. TradingAgents와 마찬가지로 백테스트 → 실거래 갭 반드시 확인.

🆕 2026-09-07 — 09-03 미해결 질문 2건 중 1건 해소, 1건 이월 (timesfm-3.0-pytorch 신규)

✅ 해소: 세대 교체는 4일 만에 완료됐다

09-03에 “3.0이 좋아요는 2.4배 많고 다운로드는 0.85배 — 교체 완료 여부는 다음 회차 판정” 으로 남겼다. 09-07 계열 3세대 동시 실측으로 종결한다.

모델09-03 DL09-07 DL변화
timesfm-3.0-pytorch46,862144,455+208.3%
timesfm-2.5-200m-transformers55,03660,209+9.4%
timesfm-1.0-200m490636+29.8%

3.0 / 2.5 비율: 0.85배 → 2.40배 (4일). 교체 완료. 동시에 “좋아요는 누적되고 다운로드는 이동한다” 가 재확인됐다 — 1.0은 좋아요 835로 계열 최다인데 다운로드는 636이다.

📌 파생 규칙 강화: 볼트의 “생성 10일 이내 DL을 사용량 근거로 쓰지 않는다”(09-03, GLM-5.3-Flash·Qwen3.8-Flash-Next 근거)가 같은 모델의 시계열 추적으로 4번째 근거를 얻었다 — 10일차 46,862조차 안정값이 아니었다. → “최소 2주, 그리고 전 세대와의 상대비로 읽는다.”

🔴 이 개념에 라이선스 축을 추가한다 — TimesFM은 상업 이용 불가

09-03에 “라이선스 other” 로만 적었던 것의 정체가 확정됐다: timesfm-non-commercial-license-v1.0(HF API license_name 실측).

  • 코드(google-research/timesfm): Apache-2.0 — 상업 이용 가능
  • 가중치(timesfm-3.0-pytorch): 비상업 라이선스 — 상업 이용 불가

이 개념 페이지는 지금까지 성능과 채택만 비교하고 라이선스를 비교한 적이 없다. 그런데 실무 도입에서 먼저 걸리는 건 라이선스다. ⭐30,397짜리 Apache-2.0 레포를 보고 “쓸 수 있다”고 판단하면 틀린다. → MiniMax-H3(“오픈 가중치 ≠ 오픈 시스템”)·anthropics-skills·VoiceStudio 에서 관측된 2층 라이선스 함정의 네 번째 사례이며, 이번엔 제약이 코드가 아니라 가중치 쪽이다.

⏭️ 2회 연속 이월: 3.0이 2.5보다 실제로 나은가

다운로드 역전은 채택을 증명하지 성능을 증명하지 않는다. 모델 카드에 벤치마크 수치가 여전히 없다(09-03·09-07 두 회차 모두 미확인). 데이터 컷오프(Wikipedia Pageviews 2023-11, Google Trends 2022년말)를 보면 최근 시계열에는 도메인 드리프트 위험도 있다. 다음 회차 종결 조건: 기술 리포트/논문을 직접 찾아 3.0의 벤치 수치를 확인한다. 그때까지 이 개념 페이지는 “TimesFM이 시계열 SOTA” 라고 쓰지 않는다.
