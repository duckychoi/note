2026-09-14 — 스킬이 늘어난 다음 질문: "어느 스킬이 값을 하나" (COBRA-Skills)

이 페이지는 스킬의 생산·배포·거버넌스를 쌓아 왔다. COBRA-Skills 가 다음 층을 연다: 선택과 평가의 비용. 문제 정의: 기존 스킬 최적화는 “costly execution-based evaluation” 과 대량 과제 데이터에 의존한다. 스킬이 좋은지 알려면 돌려 봐야 하고, 그게 비싸다. 해법: 컨텍스트 밴딧으로 “promising or informative” 후보에 평가 예산을 배분(탐색-활용 균형) + 실행 피드백으로 스킬 집단 갱신. 실측: 6개 벤치 × 3개 모델에서 SkillOpt 대비 최적화 비용 55~58% 절감 · 벤치당 고유 예제 50개만 사용 · 타깃 모델 자신으로 스킬 생성·정련해도 작동. 🔴 한정어: “strongest average performance” — 평균 최고이지 개별 벤치 전승이 아니고, 절대 점수와 SkillOpt 외 비교군 이름이 초록에 없다.

🎯 왜 지금 이 질문이 나오나 — 볼트가 추적한 스킬 규모가 이미 전수 평가 불가 구간이다: OpenMontage 700+ · Claude-Red 78 · superpowers·awesome-agent-skills 계열의 누적. 스킬을 쌓는 시대에서 스킬을 고르는 시대로 넘어간다. → 선택비용과-중복성 · 백필-우회(후보 공간을 갱신하며 고를 때의 함정)

2026-09-03 — 🚨 스킬 층에 처음으로 통제된 정량 근거가 붙었다 (Repo-To-Skill)

이 개념 페이지는 08-22 개설 이래 17개 소스를 쌓았지만, 그 전부가 스타 수·다운로드·자체 주장이었다. 08-28에 ponytail을 두고 “⭐11만은 인기의 증거이지 효과의 증거가 아니다” 라고 적었고, 08-29에 scientific-agent-skills의 “190,000+ 과학자” 를 자체 주장으로 분류했다. 오늘 그 결측이 처음 메워졌다. Repo-To-Skill(HF 데일리 1위 · 업보트 334)은 GPT-5.5 백본·연구 하네스·실행 예산을 고정한 채 스킬 유무만 토글했다: MLE-bench +134.3% · PaperBench +34.4% · FrontierCS +9.2% · PassNet +14.0% ⚠️ 전부 상대 증가율이고 절대 점수가 초록에 없다 — 크기는 아직 모른다. 그러나 크기를 모르는 것과 근거가 없는 것은 다르다. 이 개념의 근거 수준이 “스타” 에서 “통제 실험” 으로 한 칸 올라갔다. → 이 페이지의 평가 기준을 올린다. 앞으로 스킬 자산을 인제스트할 때 “백본 고정 대조가 있는가” 를 묻는다. 없으면 인기 자산으로 분류하고 효과를 주장하지 않는다.

2026-09-03 — 새 축: 스킬의 「생산 방식」 (수작업 / 경험 / 증류)

기존 4층 구조(자산·하네스·레지스트리·진화)는 스킬이 어디에 놓이는가를 나눈다. 이번 배치는 스킬이 어디서 오는가라는 직교 축을 드러냈다 — 같은 날 세 방식이 상위권에 동시에 있었다:

생산 방식대표규모근거
① 수작업 — 사람이 규범을 쓴다ponytail1개 · ⭐122,495자체 벤치(자사 레포 측정)
② 경험 — 실행에서 만들고 사용 중 고친다hermes-agent미공개 · ⭐240,408없음(이슈 38,696)
③ 증류 — 코퍼스에서 뽑는다Repo-To-Skill5,000+개(레포 1,000개 → 20영역·178역량군)통제 실험 O

규모와 근거가 정확히 반비례한다. ②가 스타 최대인데 근거 최소이고, ③이 근거 최대인데 배포 규모는 미확인이다.

축의 급소 — 증류는 "하지 마라"를 뽑지 못한다 ①과 ③은 경쟁 관계가 아니다. ③은 운영지식(이렇게 하면 작동한다)을 레포에서 뽑는다. ①은 억제(하지 마라)다. 레포에는 하지 말았어야 할 것이 안 적힌다. 실패한 접근·과잉 구현·버려진 설계는 커밋되지 않거나 커밋에서 지워진다. 따라서 억제 규범은 원리적으로 증류의 사각지대에 있다. → 08-28에 연 억제 축(ponytail)이 왜 별도로 존재해야 하는지가 이번에 설명된다. 억제는 자동화가 대체할 수 없는 층이며, ⭐12만은 그 수요의 크기다.

2026-09-03 — 5,000개를 어떻게 찾게 할 것인가 (미해결·같은 날 다른 논문이 같은 문제를 푼다)

Repo-To-Skill의 초록은 스킬 선택 메커니즘을 기술하지 않는다. 태스크마다 5,000개를 전부 로드할 수 없으므로 검색이 곧 성능인데 그 부분이 비어 있다. 공교롭게 같은 배치 CoGR(데일리 4위)이 정확히 그 문제를 다룬다 — “아이템 측 표현(키워드)을 LLM이 생성해 역색인에 넣고, 질의 성공률의 반사실적 변화로 그 표현을 학습시킨다.” 스킬을 아이템으로 치환하면 그대로 적용된다. 두 논문은 서로를 인용하지 않지만 자산 생산(③)과 자산 검색이 한 쌍이라는 사실이 이번 배치에서 드러났다. → 이 개념에 5층 후보: 검색·선택 층을 잠정 등재한다. ⚠️ 승격 조건: 스킬 검색을 명시적으로 다루는 소스 2건 추가.

2026-08-29 — "자산 vs 소프트웨어" 판별 축이 언어 태그가 아님이 5건 연속 스펙트럼으로 확정됐다

이번 배치 GitHub 5건이 이슈/포크 밀도의 연속 스펙트럼을 이뤘다: scientific-agent-skills 0.0051 < awesome-gpt-image-2 0.0070 < ponytail 0.0285 < archify 0.0353 < OpenMontage 0.0388 (최고/최저 7.6배) 볼트는 그동안 “실행되는 소프트웨어는 이슈가 많고 복사되는 텍스트 자산은 적다” 를 반복 관측했는데, 이번 회차가 언어 태그가 그 프록시가 아님을 확정한다 — archify는 JavaScript인데 상단이고 scientific-agent-skills는 Python인데 최하단이다. → 판별 축은 “통째로 실행하는가, 조각을 떼어 쓰는가” 다. 카탈로그형 자산은 사용자가 꺼내 쓰다 실패해도 자기 환경 문제로 처리하지 레포에 이슈를 열지 않는다. 언어 태그를 자산/소프트웨어 판별에 쓰지 않는다를 볼트 규칙으로 확정한다.

2026-08-29 — 생태계에 반년의 시간 깊이가 확인됐다 (scientific-agent-skills 재관측)

scientific-agent-skills는 생성일 2025-10-19로, 이번 배치 5건 중 유일한 2025년생이다(나머지는 2026-03~06). 104일 만의 재관측에서 ⭐23,434 → 37,109(+58.3%·일평균 +131)로, 급등 없이 3개월 반을 꾸준히 올랐다. → 스킬 생태계는 2026년 봄의 폭발로만 보이지만 과학 도메인에는 반년 앞선 축적이 있었다. 볼트는 이 레포를 스킬 층위론의 시간 기준점으로 삼는다. 성장 곡선의 두 유형이 확보됐다: 급등-급감쇠형(awesome-gpt-image-2 — 증가율이 매일 대략 반토막: +38.5%→+11.6%→+6.8%→+3.2%)과 저속-장기축적형(scientific-agent-skills). archify는 그 중간(감쇠 0.79배/일로 완만).

2026-08-29 — "검증됨(validated)" 표기가 과학 도메인에서 갖는 특수 위험

scientific-agent-skills는 163종 스킬을 “validated”로 표기하고 “175,000+ 과학자 사용” 을 주장하나, 검증 주체·기준·절차 전량 미확인이다. 볼트는 이 레포의 reliability를 high → medium으로 강등했다. ⚠️ 일반 코딩 스킬은 틀리면 코드가 안 돌지만, 과학 워크플로 스킬은 틀린 결과가 그럴듯하게 나온다. 같은 배치 FrontierChallenge가 이를 실측했다 — 미통과 트레이스의 75.5%가 “완료했다”로 종료됐고, 분석화학은 평균 87.6점에 통과율 4% 였다. → 스킬 카탈로그는 그 실패를 표준화해서 배포할 수 있다. 이 페이지가 반복해 온 공통 약점(재현성 벤치 부재)이 과학 도메인에서는 단순한 품질 문제가 아니라 안전 문제가 된다. ⚠️ 08-28에 연 억제(빼는) 축(ponytail)의 효과 측정도 이번 회차에 여전히 0건이며, 푸시는 22일째 정체다(스타는 +1,174 유입 지속 — 텍스트 자산 패턴 재확인). 단 awesome-gpt-image-2가 정체 예상을 깨고 08-28에 푸시를 찍어, “자산형 = 반드시 정체”는 아님이 확인됐다 — 정체는 자산형의 허용 상태이지 필연이 아니다.

2026-08-26 — 생태계에 배포 레지스트리 층과 자가진화 층이 동시에 등장

이 페이지가 정리해 온 4개 층(자산 → 방법론 → 규격 → 실행)에 이번 배치로 두 층이 추가된다. (1) 배포/레지스트리 층 — claude-plugins-community (⭐1,957·포크181·이슈42·Apache-2.0·Anthropic 공식·트렌딩 2위). 지금까지 스킬 배포는 커뮤니티 개인 큐레이션(mattpocock-skills·superpowers·awesome-agent-skills·awesome-gpt-image-2)이거나 벤더 규격(cursor-plugins)이었다. 이건 벤더가 “남이 만든 것을 싣는 목록”을 직접 소유하는 첫 사례이며, 레포가 read-only 미러이고 등록은 외부 폼으로만 되는 구조다(raw 메모 기준·README 미실측). 즉 git 레포를 레지스트리의 뷰로 쓰는 패턴. 이 층의 등장이 뜻하는 것: 스킬 자산이 “clone해서 복사”에서 “레지스트리에서 install” 로 옮겨 가면 버전·업데이트·의존성이 새로운 관리 문제가 된다. ⚠️ 다만 등재 = 검증이 아니다 — 심사 기준 공개 여부 미확인이고, 이슈 42건(0.23건/포크·순수 자산 레포치고 높음)은 트래커가 등록 문의·이의 창구로 쓰이고 있을 가능성을 시사한다(미검증). (2) 자가진화 층 — Recuris의 Skill Memory. 스킬이 손으로 쓰는 텍스트 자산에서 실행 증거로 갱신되는 자산이 된다. 검증 게이트를 통과한 국소 패치만 반영되며, 이는 SkillEvo의 자가갱신 진화 노선을 메모리 아키텍처로 구조화한 것이다. (3) 인접 — AutoSaddler는 스킬이 아니라 하네스 전체를 최적화 대상으로 승격시킨다(프롬프트+툴 설정+제어 로직). 스킬 파일이 곧 하네스의 일부이므로, 이 페이지의 자산 개념은 이제 “최적화 가능한 코드” 로 읽어야 한다. 종합하면 스킬 생태계는 축적기(자산 쌓기)를 지나 유통기(레지스트리)와 진화기(자가갱신)에 동시에 진입했다. 여전히 남는 공통 약점은 변하지 않았다 — 재현성 벤치 부재.

2026-08-24 — 1층(자산)이 코딩 도메인 밖으로 확산, 동시에 코딩 1층은 커밋 정체

두 관측이 같은 날 맞물렸다. ① 도메인 확산 — awesome-gpt-image-2(⭐14,407·포크 1,545·MIT·트렌딩 2위·GitHub API 실검증)가 이미지 생성 프롬프트를 같은 형식으로 묶어 트렌딩 상위에 올랐다. 원문 설명이 “Prompt as Code … 并提炼出Skills(스킬로 추출)” 라고 직접 밝힌다. 지금까지 이 페이지가 다룬 스킬 자산은 전부 코딩 에이전트용 절차 지식이었으므로, “스킬=배포 가능한 지식 자산” 명제가 생성형 미디어 도메인으로 넘어간 첫 관측이다. 1층 경쟁이 코딩 안에서 2강 고착으로 포화되자 새 도메인으로 넓어지는 모양새. ② 코딩 1층의 정체 고착 — mattpocock-skills ⭐234,572(하루 +1,718)인데 푸시는 08-21에서 나흘째 멈춰 있다. 08-22→08-24 누적 +4,191 유입 동안 커밋 0건이다. 증분도 +2,473 → +1,718로 약 30% 둔화했다. 08-23에 “현재 유입은 콘텐츠 개선이 아니라 트렌딩 노출의 자기강화 루프” 라고 적은 판단이 추세로 확정됐다. ③ 대조군이 선명해졌다 — 같은 배치 openai-codex는 당일 푸시 + 하루 +2,046으로 스타 증분에서 자산 레포를 처음 추월했고 트렌딩 1위를 차지했다. “복사되는 텍스트 자산”과 “실행되는 소프트웨어”의 지표 패턴 차이가 이슈 수(11 vs 13,620)뿐 아니라 커밋 활성도에서도 갈린다. ⚠️생태계 공통 약점은 그대로다 — awesome-gpt-image-2의 “530+ 사례·20+ 템플릿·공업급” 은 전량 레포 자체 주장이며 미검증이다. 오히려 프롬프트 자산은 모델 버전에 종속돼(GPT-Image-2 갱신 시 자산이 조용히 낡음) 코딩 스킬보다 부패 속도가 빠를 수 있다는 새 약점이 추가된다. 이 페이지가 기록해 온 재현성 벤치 부재·스타≠품질은 새 도메인에서도 해소되지 않았다.

한 줄 정의

에이전트 스킬은 코딩 에이전트에게 “무엇을 언제 어떻게 하라”를 알려주는 프롬프트·절차·참조 파일의 묶음이며, 모델 가중치나 코드 라이브러리가 아니라 배포 가능한 지식 자산이다. 핵심 성질은 모델을 바꾸지 않고 행동을 바꾼다는 것 — 그래서 파인튜닝보다 싸고 빠르며, 그만큼 품질 보증 수단이 없다.

스킬의 내용물이 프롬프트에서 서비스 호출 규약으로 바뀌는 지점

1층 자산(mattpocock-skills·scientific-agent-skills)의 실체는 텍스트다 — 절차, 규칙, 참조 파일. 복사해 가면 그만이고 서버가 필요 없다. archify는 여기서 한 발 나가 출력 형식을 규정했지만 여전히 로컬에서 완결된다(자체완결 HTML). OpenMAIC의 스킬은 다르다. 내용물의 핵심이 “무엇을 하라”가 아니라 “어디에 어떻게 요청하고 어떻게 기다리라” 다. 호스티드 모드에서는 액세스 코드를 받아 원격 서비스를 부르고, 자체호스팅 모드에서는 클론·설정·기동을 단계별로 안내한다. 즉 스킬이 SDK 겸 설치 가이드 겸 클라이언트가 된다. 이것이 중요한 이유: 1층 자산은 품질 보증 수단이 없다는 것이 구조적 약점이었는데(아래 섹션), 서비스형 스킬은 서비스 쪽에 책임 주체가 생긴다. 대신 새 약점이 붙는다 — 로컬에서 검증 불가하고, 서비스가 죽으면 스킬도 죽으며, 데이터가 밖으로 나간다.

3층(레지스트리)이 벤더 하나로 수렴하지 않는다

볼트는 3층을 “벤더가 계약을 정의하는 층” 으로 적고 claude-plugins-official·cursor-plugins를 예로 들었다. OpenMAIC가 ClawHub라는 제3의 허브를 통해 배포된다는 사실은, 레지스트리가 에디터/모델 벤더 소유가 아닌 곳에서도 생긴다는 뜻이다. 같은 날 관측된 수치가 이를 보강한다 — claude-plugins-official은 배치 최저 성장률(+1.03%/일) 이었다. 공식 인덱스라는 지위가 유입을 만들어 주지 않는다. 사람들은 인덱스가 아니라 자산과 서비스로 간다.

그래서 이건 5층인가, 1층의 변종인가

볼트는 판단을 보류하고 1층의 두 번째 변종으로 잠정 분류한다(archify가 첫 번째 변종 — 출력 형식을 규정). 근거: 표본이 OpenMAIC 하나뿐이고, ClawHub 생태계 자체를 볼트가 아직 관측하지 않았다. 판별 기준을 미리 적어 둔다 — 원격 서비스를 감싸는 스킬 사례가 서로 다른 도메인에서 2건 더 나오면 “서비스 래퍼”를 독립 층으로 승격한다. 그전까지는 변종으로 둔다.

이 개념의 구조적 약점

스킬에는 품질 보증 수단이 사실상 없다

코드 라이브러리는 타입·테스트·시맨틱 버저닝이 있지만, 스킬은 자연어 절차라 다음이 전부 결여돼 있다:

  • 재현성 벤치 없음 — mattpocock-skills·superpowers 어느 쪽도 “이 스킬을 쓰면 성공률이 N% 오른다”는 정량 근거를 리포에 제시하지 않는다. superpowers의 설명문에 붙은 “that works” 는 주장이지 측정이 아니다.
  • 스타 수 ≠ 품질 — 저자 브랜드 파워가 스타를 견인하는 구조(mattpocock-skills는 Matt Pocock의 TypeScript 교육자 기반).
  • 결함이 멀티턴에서만 드러남 — SkillEvo가 실증한 비대칭. 한 번 써보고 괜찮으면 좋은 스킬로 보이지만, 여러 턴 이어 쓸 때만 나타나는 결함은 발견 경로 자체가 없다.
  • 이식성 미해결 — 하니스별 규격이 갈라지면(claude-plugins-official vs cursor-plugins) 같은 스킬을 여러 곳에 유지해야 한다. superpowers가 멀티 하니스 지원을 내세우는 것이 이 압력의 방증.

자동 발동의 양면성

superpowers류의 자동 트리거는 사용자가 조작할 필요가 없다는 장점이 있지만, 동시에 에이전트를 특정 프로세스에 강하게 구속한다. 빠른 단발 태스크에는 오버헤드이고, 의도치 않은 개입 여지가 있다.

실무 함의

스킬을 도입·작성할 때의 판단 기준

  1. 1층 자산은 복사 전 읽어라 — 스타 수가 아니라 실제 절차 내용을 본다. 브랜드가 스타를 만든다.
  2. 개선은 멀티턴 로그에서 뽑아라 — SkillEvo의 핵심 교훈. 1회 실행 결과로 스킬을 고치면 1라운드 뒤 개선이 멈춘다.
  3. 규격 종속을 경계하라 — 3층은 아직 갈라지는 중이다. 스킬 본문은 하니스 중립으로 쓰고, 규격 어댑터만 분리한다.
  4. “works” 주장은 근거를 요구하라 — 방법론 층 리포일수록 정량 근거가 없다.
