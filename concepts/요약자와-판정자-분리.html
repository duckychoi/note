요약자와 판정자 분리

한 줄

자료를 수집한 주체가 그 자료의 신뢰도를 판정하면 안 된다. 에이전트는 수집을 잘하고 해석을 못한다. 이 둘은 같은 능력이 아니므로 같은 주체에게 맡기면 안 된다.

외부 증거 — 이건 볼트만의 관찰이 아니다

SAEScientist-Bench 가 같은 분해를 실험으로 보였다. 초록 원문:

“에이전트는 허위 후보를 배제하는 대조는 설계할 수 있으나, 실험 측정치를 빈번히 오해석한다(frequently misinterpret experimental measurements).” 축별 결과도 같은 방향이다 — 대조 텍스트에서 목표 개념 분리는 전문가 수준에 근접, 인과적 생성 스티어링은 크게 뒤처짐. → 관찰은 되는데 개입/판정이 안 된다. 09-09 Encoded-Early-Used-Late 의 “프로브가 읽히는 레이어는 개입할 곳이 아니다” 와 동형이다. 읽기와 쓰기가 분리되듯, 수집과 판정이 분리된다.

볼트 자체 관찰 — raw의 오류는 매번 "판정"에서 났다

raw는 소스를 찾고 읽는 데는 거의 실패하지 않는다. 틀리는 곳은 언제나 판정 단계다:

  • 2026-09-07 / 09-08 — 과장(범위 확대·2배로 세기)
  • 2026-09-09 — 누락(프레임에 맞는 문장만 남기고 정량 성과 폐기 — Cadence · Language-Transfer-Robot-Policies · Spark-X2.5-4B)
  • 2026-09-10 — 역전(teamai-cli 라이선스: API 파생 분류를 원문보다 신뢰 → 파생표기-함정) → 오류의 방향은 매번 바뀌었는데 위치는 한 번도 안 바뀌었다. 원인은 하나 — 요약자가 자기 요약을 검증 없이 신뢰도 판정한다.

🎯 해법의 형식화 — Discovery-Certification-Protocol

DCP가 이 원칙을 실행 가능한 프로토콜로 만들었다. 볼트가 경험으로 도달한 규칙과 1:1로 대응한다:

  • 볼트 “보장된 null 도입” ↔ DCP 60쌍 널 스터디
  • 볼트 “틀린 입력 arm 추가” ↔ DCP Gate 2 대조 에이전트(목표 연구 이력 차단)
  • 볼트 “요약자가 판정하지 않는다” ↔ DCP LLM 없는 결정적 검증기 특히 마지막이 핵심이다 — 검증기 자체에 LLM이 없다. 판정자가 요약자와 같은 종류의 실패를 하지 않도록 아예 다른 메커니즘으로 만든 것. DCP의 핵심 발상도 여기 붙는다: 발견의 증거는 결과가 아니라 “대안 경로의 부재”다. 다른 경로로 같은 결론에 도달할 수 있다면 그 결론은 원문에서 온 게 아니다.

볼트 운영 규칙 (2026-09-10 승격)

  1. raw는 요약만, 볼트가 판정한다. raw의 신뢰도 표기(⭐·“medium” 등)는 입력이지 결론이 아니다.
  2. 복구 테스트(DCP Gate 2 축소판) — raw 요약만 보고 결론을 세운 뒤, 원문을 열어 그 결론에 도달할 다른 경로가 있었는지 확인한다. → 이번 teamai-cli 건이 정확히 이 테스트에 걸렸다: raw는 NOASSERTION 이라는 다른 경로로 결론에 도달했고, 원문 경로와 어긋났다.
  3. 볼트도 자기 예외가 아니다. 볼트가 요약한 것을 볼트가 판정하지 않도록 원문 grep 대조를 강제한다. 이번 배치에서 이 강제가 실제로 1건을 잡았다.

이 규칙의 비용

원문 대조는 느리다. 13건 배치에서 API 실호출 + README/카드 원문 다운로드가 필요했다. 그 비용을 치른 결과가 반증 1건 + 누락 발견 2건이다. → 비용 대비 수익이 명확하지 않을 때도 있다. 다만 틀린 판정이 볼트에 영구 저장된다는 점이 비대칭을 만든다 — 검증은 1회, 오염은 영구.

  • 09-11 — 🔴 탐지 실패(중복 1건) + 판정 정확도는 사실상 100% → 지금까지 결론은 “방향은 매번 바뀌고 위치(판정 단계)는 안 바뀐다” 였다. 이번에 위치가 바뀌었다.

🔴 신규 유형 — 구조적 탐지 실패 (vercel-skills)

raw는 이번 배치에 “raw.md 기존 URL과의 중복 0건” 이라고 보고했다. 실제로는 1건 중복이었다 — vercel-skills 는 2026-04-23에 이미 인제스트돼 있었다(⭐15,695 기록). 원인은 부주의가 아니라 설계다:

  • raw의 중복 검사 대조 대상 = raw.md 의 기존 URL
  • 그런데 raw.md 는 처리 후 항목을 즉시 삭제하는 대기열이다(볼트 스키마 핵심 원칙 1번) → 🎯 처리된 소스는 raw.md에 남아 있지 않다. 그러므로 raw는 원리상 기존 인제스트를 절대 탐지할 수 없다. → 대조 대상이 틀렸다. 봐야 할 것은 wiki/sources/ 와 index.md 다. → ⚠️ 볼트가 안 잡았으면 1,002번째 소스로 중복 페이지가 생성될 뻔했다. 그리고 볼트가 잡은 방법은 정교한 검사가 아니라 ls | grep 한 줄이었다.

raw의 중복 탐지는 일관되지 않다

같은 배치에서 i-have-adhd 는 raw가 “볼트에 기존 노트 있음 → 신규 아님, 갱신 항목” 이라고 정확히 자기 신고했다. → 즉 raw는 어떤 중복은 잡고 어떤 중복은 못 잡는다. i-have-adhd는 트렌딩 급상승으로 raw가 기억하던 것이고, vercel-skills는 4.5개월 전 항목이었다. → 🎯 raw의 중복 탐지는 조회가 아니라 회상에 의존한다. 오래된 것일수록 못 잡는다 — 볼트가 클수록 이 실패는 늘어난다.

처방 — 볼트 쪽에서 막는다

raw를 고치는 것보다 볼트 ingest 1단계에 중복 검사를 고정하는 것이 확실하다:

→ 같은 배치 AgentGrad 의 처방과 일치한다: 수집기 프롬프트를 고쳐 해결되기를 기대하지 말고, 실제로 확인하는 절차를 넣어라.

🪞 그리고 판정자도 안전하지 않다

같은 배치 SenseNova-U1.5 에서 볼트 자신의 예측이 빗나갔다(“SenseTime 특성상 오픈소스 가능성 낮음” → U1.5가 학습 코드 공개 예고). → “raw는 요약만, 볼트가 판정한다”는 raw의 오류를 줄이지만 볼트의 오류를 줄이지 않는다. 볼트에는 상위 판정자가 없다 — 이것이 queries/ 0건(검사가능성-공사)이 계속 문제인 이유다.
