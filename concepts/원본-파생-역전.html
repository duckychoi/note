원본-파생 역전

🏆 2026-10-03 — 1:N 역전에서 두 분기가 반대로 움직인다 + 🔴 수집기 "최대 배수" 주장 기각

Comfy-Org-Qwen-Image-2.1 을 파생 언급에서 독립 페이지로 승격(볼트 규칙 “파생 DL 이 베이스를 넘으면 독립 페이지” 의 2번째 집행)하면서 같은 원본의 두 분기 시계열을 나란히 놓았다:

분기배수 추이방향
abenzerps/…-Uncensored-GGUF12.3 → 16.9 → 16.9증가 후 고정
Comfy-Org/…82.07 → 78.17 → 76.91 → 69.42🔴 4점 단조 감소
⚖️ 10-02 결론 “역전이 수렴하지 않는다. 구조적 격차다” 는 abenzerps 분기에서만 참이다. ⇒ 📌 조항 추가: 1:N 역전에서 N개 분기는 같은 운명을 갖지 않는다. 역전의 “구조성”은 쌍 단위로 판정하고 원본 단위로 일반화하지 않는다.

🏆 그리고 감소의 원인이 중요하다 — 파생의 쇠퇴가 아니라 원본의 성장이다. 볼트 독립 계산(09-22 → 10-03 · 11일):

  • 원본 Qwen/Qwen-Image-2.1: 6,523 → 81,738 = 12.53배
  • 파생 Comfy-Org/…: 535,365 → 5,674,460 = 10.60배 ⇒ 둘 다 10배 이상 폭발했고 원본이 약간 더 빨랐다. 분모가 자라서 비가 줄었다. ⚖️ 배수 단독 인용은 두 양의 방향을 숨긴다 → 복합지표-분해. 📌 69배는 “해소 중”이 아니다 — 여전히 압도적 역전이다.

🔴 수집기 오판 적발 2겹: 수집기는 69.4배를 “최대 배수 사례” 로 보고했다. ① 볼트 기존 최대는 114.3배이고(기록된 사례: 114.3 · 95.6 · 93.8 · 82.1 · 76.9 · 75.5 · 75.3 …) 69.4 는 8번째 이하다. ② 같은 쌍의 자기 최고치(82.1배 · 09-22 볼트 실측)보다도 낮다. ⚖️ 규칙: “최대/최초” 류의 서열 주장은 수집기가 하지 않고 볼트가 한다. 수집기는 당일 수치만 보고 볼트만 이력을 갖는다. 📌 볼트가 09-24 에 “원본이 상대적으로 회복” 이라 적어 둔 것이 오늘 오판을 막았다 — 기록이 방어가 됐다.

🆕 새 축 관측 — 다운로드는 품질이 아니라 배포 편의를 잰다. 이 분기는 ComfyUI 단일 파일 재포장본이고 성능이 원본과 동일하다(성능 주장이 있을 수 없다). 그런데 DL 이 69배다. ⇒ 📌 HF 다운로드 상위권에 재포장본이 올라온다. DL 순위를 모델 품질 순위로 읽으면 안 된다. 관심-검증-역상관 과는 다른 축이다(그쪽은 관심↔검증, 이쪽은 설치 단계 수).

정의

HF에서 파생 저장소의 다운로드가 원본을 압도적으로 앞선다. 다운로드로 선발하는 채널은 따라서 구조적으로 파생을 고르고 원본을 버린다 — 필터가 틀려서가 아니라 정렬 키가 그렇게 생겼기 때문이다.

🎯 파생저장소-식별 이 “왜 파생이 중복 필터를 통과하는가”를 설명했다면, 이 개념은 “왜 애초에 파생만 도착하는가”를 설명한다. 전자는 탐지의 문제, 후자는 선발의 문제다.

🔴 두 쌍 모두 파생이 배달됐고 원본은 오지 않았다. 수집기 선발 기준이 다운로드이기 때문이다.

🎯 좋아요는 반대로 간다

Swift 쌍에서 좋아요는 원본이 497 대 321로 앞선다. 다운로드는 12.5배 뒤지는데 좋아요는 1.55배 앞선다. 📌 두 지표가 서로 다른 것을 센다:

  • 다운로드 = 파일을 받은 횟수 → 실행 형식(GGUF·ComfyUI 패키지)이 이긴다. 한 사용자가 여러 tier를 받으면 여러 번 센다.
  • 좋아요 = 계정당 1회, 대상 지목 → 정체(identity) 가 이긴다. “이 모델이 좋다” 는 원본에 누른다. 🎯 즉 다운로드는 “어떤 파일을 쓰는가”, 좋아요는 “어떤 모델을 아는가”를 센다. 수집 채널이 전자로 정렬하면 정체가 아니라 포장을 수집한다.

대가 — 이미 두 번 치렀다

  1. 🔴 Swift-Qwen3.8-27B-GGUF: 볼트는 GGUF 카드로 성능을 읽어야 했는데, BF16 9행 표의 실제 주인은 원본 + Swift 어댑터다. 피측정물의 페이지 없이 측정값을 받았다 — mem0 에서 8개월간 벌어진 일과 같은 형태다.
  2. 🔴 FastVideo: 볼트 09-18 actionable 이 “FastH3 8-Step V2 를 돌려 E2E 를 재라” 였는데, 실제 사용자의 95.6%는 Comfy 재포장본을 쓴다. 실측 대상이 틀렸다.

볼트 규약

  1. 파생이 배달되면 원본의 지표를 같이 조회한다 — cardData.base_model + base_model_relation 으로 부모를 얻어 1회 조회. 비용 1콜.
  2. 원본이 미보유면 backlog 슬롯으로 별도 요청한다 — 다운로드로는 영원히 선발되지 않는다.
  3. 수치의 귀속을 먼저 쓴다 — “이 수치는 원본/파생 중 어느 것의 것인가”. 파생 카드의 수치가 원본의 것일 수 있다.
  4. 🔴 다운로드 순위를 “인기”로 읽지 않는다 — 상대속도-가림 · 파생저장소-식별(trendingScore는 볼트 커버리지의 함수)에 이어 HF 지표를 액면가로 읽으면 안 되는 세 번째 사례다.

🔴 한계

표본 2. 둘 다 같은 배치·같은 유형(무거운 실행 아티팩트: GGUF·ComfyUI). 텍스트 파인튜닝 파생에서도 같은 방향인지 확인하지 않았다. Ternary-Bonsai-2-27B(1,908,396) ↔ Bonsai-27B(662,554)는 원본/파생이 아니라 세대 관계라 이 표에 넣지 않았다. 🔴 다운로드 카운트의 정의(유니크 사용자인지 파일별 합산인지)를 HF 문서로 확인하지 않았다. 위 “여러 tier를 받으면 여러 번” 은 추정이다.

🔄 2026-09-23 갱신 — 반례로 들어올 뻔한 사례가 지지 사례였다

🔴 수집기 판정: "Qwen3.8-27B ↔ Qwen3.8-27B-GGUF 격차 0.85% → 역전 성립하지 않음. 반례 1건 추가."

이 판정은 철회한다. 잘못된 지표 창에서 읽혔다.

✅ 볼트 실측 — 창을 바꾸면 결론이 뒤집힌다

  • 최근 창(downloads): 원본 7,079,646 vs 파생 7,019,401 → 격차 0.85%, 역전 없음
  • 누적(downloadsAllTime): 원본 9,681,199 vs 파생 13,993,047 → 파생 / 원본 = 1.445배 🎯 역전은 성립한다. 최근 창에서 격차가 사라진 이유는 별개의 관찰거리다 — 원본이 최근 다시 받아지고 있거나, 파생의 초기 폭발이 창 밖으로 밀려났거나. 어느 쪽인지는 ⬜ 미확정.

🎯 이 개념에 붙는 새 조항 — 역전은 "언제 세느냐"에 의존한다

기존 정의는 “다운로드는 어떤 파일을 쓰는가, 좋아요는 어떤 모델을 아는가를 센다” 였다. 여기에 세 번째 축이 붙는다: 언제 썼는가.

  • 누적에서의 역전 = 파생이 역사적으로 더 퍼졌다
  • 최근 창에서의 역전 = 파생이 지금 더 쓰인다 둘은 다른 주장이고, 서로 반대일 수 있다. 앞으로 이 개념의 사례는 어느 창에서 측정했는지 반드시 명시한다 → 지표-창길이.

소급 점검 대상

이 페이지 기존 사례(Swift-Qwen3.8-27B-GGUF · FastVideo · Ternary-Bonsai-2-27B · Qwen-Image-2.1 · Qwen3.8-Flash-Next-GSQ-RCO-GGUF · ZDTaichu5.0-9B)는 전부 최근 창 값으로 판정됐을 가능성이 있다. 🔴 누적값 재조회 미수행 — 다음 배치 백로그. 역전 방향이 바뀌는 사례가 더 나올 수 있다.

🎯 결론 1 — 방향이 바뀐 사례는 0건이다. 09-23의 우려는 기각된다

09-23 기록: “역전 방향이 바뀌는 사례가 더 나올 수 있다.” → 하나도 없었다. 4건 역전 유지, 2건 반례 유지.

🎯 그리고 그 이유가 우연이 아니다: 파생 저장소는 거의 전부 신생이다(created 09-04 ~ 09-16). 30일 창이 생애 전체를 덮으므로 창값 = 누적값이다. 7쌍 중 창≠누적인 것은 2건뿐이고 둘 다 오래된 쪽이다(Ternary-Bonsai v1 = 07-04 생성 82일 · Qwen3.5-9B = 02-27 생성 209일). 📌 즉 이 개념이 다루는 대상 자체가 창 효과에 거의 노출되지 않는다. 재포장·양자화 파생은 원본보다 항상 어리다.

🔴 결론 2 — 그러나 배수는 창에 매우 민감하다. 창 기준은 역전을 “과대 추정”한다

원본이 오래되면 30일 창이 원본을 과소평가한다 → 파생/원본 배수가 부풀려진다.

  • ZDTaichu5.0-9B 반례: 창 기준 원본 1,833배 → 누적 기준 9,397배. 반례가 5.1배 강해졌다.
  • Ternary-Bonsai-2-27B v1: 볼트 09-22 기록 “Bonsai-27B 662,554” 는 창값이었다. 누적은 1,879,078(2.84배).

🎯 이 개념에 붙는 네 번째 조항

기존 3축: 어떤 파일을(다운로드) · 어떤 모델을 아는가(좋아요) · 언제 썼는가(창/누적). 🆕 네 번째: 양쪽의 나이가 같은가. 원본과 파생의 생성일 차이가 창 길이를 넘으면 창 비교는 구조적으로 파생에 유리하다. 배수를 인용할 땐 양쪽 createdAt 을 병기한다.

🎯 trendingScore 가 좋아요와 같은 방향, 거의 같은 비율(3.24 vs 3.17)로 원본을 편든다. 기존 2축(“파일 vs 정체”)에 정체 쪽 독립 지표가 하나 더 생겼다 — 좋아요는 누적 행위, trendingScore는 현재 관심인데 둘이 일치한다. 📌 주목(trend·♥)과 채택(DL)이 78배 갈린다. 원본이 trendingScore 3배 앞서면서 다운로드는 78분의 1이다. 🔴 단 주의: 파생저장소-식별 이 “trendingScore 절대값은 볼트 커버리지의 함수” 라 기록했다. 여기서 쓴 것은 절대값이 아니라 동일 시점 쌍 내 비(比) 이므로 그 경고에 걸리지 않는다. 배치 간 비교는 여전히 금지.
