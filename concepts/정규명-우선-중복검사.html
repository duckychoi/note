정규명 우선 중복검사

정의

리다이렉트를 따라가 정규명(canonical name)을 확정한 뒤에 중복 검사를 해야 한다. 순서가 뒤바뀌면 이미 가진 것이 신규로 들어온다. 레포 이름은 식별자가 아니다 — ID가 식별자이고, 이름은 그 ID의 별칭 중 하나다.

🎯 파생저장소-식별 이 “다른 것이 같아 보인다”(파생이 원본처럼 통과)를 다룬다면, 이 개념은 “같은 것이 달라 보인다”(같은 레포가 두 이름으로 두 번 들어온다)를 다룬다. 전자는 과다 포함, 후자는 중복 포함.

발단 — 2026-09-24, 수집기의 “본체 누락 4번째”가 이미 있던 페이지였다

수집기 판정: ”🎯 볼트가 재포장본을 세 번 추적해 온 Comfy-Org 의 본체 레포인데 페이지가 없다 — browser-use·HuggingFace·mem0 에 이은 본체 누락 4번째”

🔴 틀렸다. wiki/sources/ComfyUI.md 는 2026-08-11부터 존재한다(★126,600 기록, 48행).

왜 통과했는가 — 수집기의 정직한 작업이 정확히 중복을 만들었다

수집기는 09-21 요청 1을 이행했다: “grep -rl 로 vault/wiki/ 를 먼저 검색해 이미 소스 페이지가 있는 레포를 제외했다” — 그 결과 12건을 제외했다. 그런데 ComfyUI는 통과했다.

순서가 원인이다:

  1. 수집기가 트렌딩에서 레포를 집었다
  2. comfyanonymous/ComfyUI → HTTP 301 → Comfy-Org/ComfyUI 를 스스로 발견하고 기록했다(raw.md 87행 ⚠️ 주석)
  3. API를 정규명으로 조회했다 — 올바른 판단
  4. 🔴 그런데 중복 검사는 조회에 쓴 정규명 기준으로 다시 돌리지 않았다. 볼트 페이지는 구 이름(comfyanonymous/ComfyUI)으로 적혀 있다.

📌 리다이렉트를 찾아낸 행위 자체가 중복 검사를 무력화했다. 수집기가 게을러서가 아니라 한 단계 더 정확해졌기 때문에 어긋났다.

🎯 더 깊은 원인 — 레포가 자기 문서에서 구 이름으로 자칭한다

볼트가 ComfyUI README 437행을 확인한 결과:

  • 배지·릴리스 링크(27~32행): 전부 comfyanonymous/ComfyUI
  • 예제 링크(62행): comfyanonymous.github.io
  • 🔴 ## Release Process(90행): 3개 연결 레포를 나열하는데
    • 1. ComfyUI Core → github.com/comfyanonymous/ComfyUI ← 구 이름
      1. Comfy Desktop → github.com/Comfy-Org/Comfy-Desktop ← 신 조직
      1. ComfyUI Frontend → github.com/Comfy-Org/ComfyUI_frontend ← 신 조직

🎯 조직 이관이 문서에서 절반만 끝났다. 본체만 구 이름으로 남았고 위성 레포는 신 조직이다. → 볼트 페이지가 “낡은” 게 아니라, 레포의 자기 표기를 따라간 것이다. 그 시점엔 그게 정답이었다.

선행 사례 — 볼트는 이 패턴을 세 번 봤고 매번 다른 얼굴이었다

🎯 리다이렉트는 양방향으로 오류를 만든다

  • 추적하지 않으면 → 옮겨 간 레포를 죽은 것으로 보고 버린다(abenzerps)
  • 추적하고 중복 검사를 다시 안 돌리면 → 가진 것을 또 받는다(ComfyUI) 한 번만 추적하면 안 된다. 추적 결과를 모든 하위 판정에 되먹여야 한다.

볼트 규약

  1. 🔴 리다이렉트 추적 → 정규명 확정 → 그다음 중복 검사. 순서를 바꾸지 않는다.
  2. 🔴 중복 검사는 두 이름 모두로 돌린다 — 구 이름과 정규명. grep -rl "comfyanonymous\|Comfy-Org" vault/wiki 처럼.
  3. 레포 ID로 대조한다 — GitHub 301 응답은 api.github.com/repositories/589831718 처럼 숫자 ID를 준다. 이름보다 강한 식별자다. (ComfyUI 실측 ID 589831718 — 볼트 확인)
  4. 페이지 제목·URL에 정규명을 쓰고, 구 이름은 별칭으로 본문에 남긴다 — 미래의 grep이 양쪽에 걸리게.
  5. 📌 레포가 자기 문서에서 쓰는 이름과 API 정규명이 다를 수 있다. 다르면 둘 다 적는다.

🔴 한계

  • 표본 3(KrillinAI · abenzerps · ComfyUI). GitHub 2건 + HF 1건이고 셋 다 이름 변경 계열이다. 포크·미러로 인한 중복은 이 규약이 못 잡는다(ID가 다르므로).
  • ⬜ 볼트 기존 페이지 중 몇 건이 이미 구 이름으로 고정돼 있는지 전수 확인하지 않았다. ComfyUI 가 하나 걸렸으니 더 있을 수 있다 → actionable 등록.
  • ⬜ GitHub 301 응답이 항상 숫자 ID를 주는지 문서로 확인하지 않았다(1건 관측).
