지표 창길이

🔴 먼저 — 이 페이지는 "새 발견"이 아니다. 볼트는 이미 알고 있었다

수집기는 이번 배치에서 ”🔴 이번 배치 최대 발견 — DL 수치의 의미가 바뀐다” 며 30일 창 가설을 제시했다. ✅ 볼트 실측 반박: 볼트는 이 사실을 최소 2026-09-06부터 관측했고 09-15에 규칙으로 명문화했다.

  • HuggingFace 엔티티 27행: ”🔴 downloads 는 30일 누적이다 — 전체 누적이 아니다” · 32행: “다운로드는 ‘30일’을 항상 병기한다”
  • MiniMax-H3-Physical-Reasoning 71행: 09-06 4,986,349 → 09-19 4,449,605, “줄었다(누적 아님)” 로 이미 정확히 해석
  • Qwen3.6-35B-Uncensored 17행: “30일 롤링 윈도 기반이라 신규 유입 둔화 시 수치가 감소하는 정상 등락” 🎯 그러므로 “볼트의 증분 해석 전체를 재검토해야 한다”는 수집기 주장은 과장이다. 볼트는 감소를 이미 창 이동으로 읽고 있었다.

🎯 진짜로 새로운 것은 딱 하나 — 부재 판정이 틀렸다

볼트가 Qwen3.8-27B-GGUF 85행에 적어 둔 문장:

“downloadsAllTime 은 null로 미제공돼 교차 검증 경로도 없다.” 🔴 이 문장이 틀렸다. 필드는 존재하고, ?expand[]=downloadsAllTime 을 붙이면 값이 온다. ✅ 볼트 실측 (2026-09-23, 3/3 성공):

모델downloads(30일)downloadsAllTime(누적)
Qwen/Qwen3.8-27B7,079,6469,681,199
unsloth/Qwen3.8-27B-GGUF7,019,40113,993,047
prism-ml/Ternary-Bonsai-2-27B-gguf2,569,6042,569,604

🎯 없던 것은 데이터가 아니라 요청 파라미터였다. 볼트는 몇 주 동안 “교차검증 불가”를 전제로 동결·감소를 해석해 왔는데, 경로는 처음부터 있었다.

✅ 내부 정합 검증 — 가장 어린 레포가 증명한다

Ternary-Bonsai-2-27B 는 2026-09-16 생성 = 7일 차, 창 길이보다 어리다. 이 레포만 두 값이 정확히 일치한다(2,569,604). 성숙한 레포 2건은 벌어진다(7.08M<9.68M · 7.02M<13.99M). 🎯 레포 나이 < 창 길이면 두 값은 같아야 한다 — 3표본이 이 예측을 정확히 만족. 창 해석과 누적 필드 양쪽이 동시에 확인됐다.

파급 — 원본-파생-역전 판정이 뒤집힌다 (이번 배치 실질 성과)

🎯 같은 쌍이 창을 바꾸면 반대 결론을 준다

수집기 판정: “Qwen3.8-27B ↔ Qwen3.8-27B-GGUF 격차 0.85% → 역전 성립 안 함. 반례 1건 추가.”

  • 30일 창: 7,079,646 vs 7,019,401 → 격차 0.85%, 역전 없음
  • 누적: 9,681,199 vs 13,993,047 → 파생이 원본의 1.445배, 역전 성립 🔴 반례가 아니라 지지 사례였다. 새로 열린 누적 축이 없었다면 오염된 반례가 개념 페이지에 들어갔다 → 측정도구-먼저-반증.

🔴 볼트 자기 한계 (숨기지 않는다)

규칙은 있었는데 적용되지 않았다

HuggingFace 32행의 “다운로드는 ‘30일’을 항상 병기한다” 는 09-15에 만든 볼트 자체 규칙이다. 그런데 09-22 log.md 는 여전히 4,511,348→4,960,483(+449,135) 형태의 맨 증분으로 적었다(233행). 창 표기 없음. 🎯 지식이 페이지에 있는 것과 규칙이 작업에 적용되는 것은 다르다 → 암묵을-명시로 의 역방향 사례: 명시했는데도 적용되지 않았다. 📌 그래서 수집기가 “발견”으로 되가져왔을 때 볼트가 바로 반박하지 못할 뻔했다. 자기 규칙의 미적용이 남의 과장을 키운다.

⬜ 확인 범위 (부재 주장에 범위를 붙인다)

  • 창 길이가 정확히 30일이라는 건 ⬜ 공식 문서로 확인되지 않았다. huggingface/hub-docs docs/hub/models-download-stats.md 전문 3,934바이트 확인 — 카운팅 방식(쿼리 파일·GGUF·diffusers)만 서술하고 기간은 한 글자도 없다. “30일”은 볼트·커뮤니티의 관측 기반 통용값이다.
  • 기존 원본-파생-역전 사례 6건의 누적값 재조회 미수행 → 역전 방향이 바뀌는 사례가 더 있을 수 있다.

볼트 규칙 (개정)

  1. HF 모델 조회는 ?expand[]=downloadsAllTime 필수. 두 값을 항상 병기: DL 7,079,646(30일) / 9,681,199(누적).
  2. A→B 증분 서술은 누적값에서만. 30일 값의 차이는 “창 이동” 으로 적는다.
  3. 동결·감소는 이제 “관측 실패”로 남기지 않는다 — 누적 축으로 교차 확인한다. (기존 Qwen3.8-27B 109행의 “격일 갱신 가설” 도 누적 축으로 재검토 가능해졌다)
  4. 창 길이는 ⬜ 문서 미확인 상태로 표기한다. “30일”을 단정하지 않는다.

🆕 2026-09-24 — 창 길이에 처음으로 수치 근거가 붙었다 (문서는 여전히 없다)

볼트가 09-23에 남긴 ⬜: “창 길이 30일은 여전히 문서 미확인 — 공식 models-download-stats.md 전문 3,934B 에 기간 서술이 한 글자도 없다. 볼트·커뮤니티 관측 기반 통용값일 뿐이다.”

문서는 여전히 없다. 그러나 원본-파생-역전 소급 점검(7쌍 전수 재조회)에서 창 길이를 역산할 수 있는 쌍이 2건 나왔다 — 생성 30일 이상 지난 저장소만 창 ≠ 누적 이 되기 때문이다.

역산 — 다운로드율이 균일하다고 가정할 때

저장소createdAt경과일30일 창누적창/누적함의 창 길이
Qwen/Qwen3.5-9B2026-02-27209일9,787,24265,161,68715.02%≈31.4일
prism-ml/Ternary-Bonsai-27B-gguf(v1)2026-07-0482일653,2981,879,07834.77%≈28.5일

🎯 규모가 35배 다르고(1.9M vs 65M) 나이가 2.5배 다른(82일 vs 209일) 두 저장소가 28.5일과 31.4일을 낸다. 둘 다 30일을 감싼다. 📌 볼트 통용값 “30일”은 이제 근거 없는 관습이 아니라 실측 2건과 정합하는 추정값이다.

🔴 이 추정이 기대는 가정 — 숨기지 않는다

균일 다운로드율 가정이 계산의 전부를 떠받친다. 실제 모델 다운로드는 보통 출시 직후 몰리고 감쇠한다.

  • 감쇠한다면 → 최근 30일 몫이 비례보다 작아야 한다 → 관측값(15.02% > 비례 14.35%)은 최근 유입이 평균보다 많다는 뜻 → 함의 창은 30일보다 짧아질 여지
  • 즉 28.5~31.4일은 신뢰구간이 아니다. 두 개의 점추정이고, 각각 해당 저장소의 다운로드 곡선 모양에 오염돼 있다. 🔴 여전히 ⬜ 미확정이다. 다만 등급이 달라졌다: “근거 없음” → “실측 2건이 30일 근방과 정합, 문서 미확인”. ⬜ 추가로 필요한 것: 같은 저장소를 며칠 간격으로 연속 관측해 창이 어떻게 미끄러지는지 직접 보는 것. 1회 스냅샷 역산보다 강하다 → actionable.

🎯 부수 발견 — 창 경계를 막 넘은 저장소가 경계를 보여준다

Qwen/Qwen3.8-Flash-Next (created 2026-08-24 = 31일 경과):

  • 30일 창 807,550 / 누적 807,789 → 차이 239

📌 31일 된 저장소에서 창 밖으로 밀려난 양이 239다. 창 길이가 30일이라면 이 239는 “생애 첫 1일분” 에 해당한다. 🎯 출시 첫날이 807,550의 0.03%밖에 안 된다는 것은 이 모델이 조용히 올라갔다가 나중에 퍼졌다는 뜻이고, 이는 위 “최근 유입이 평균보다 많다”는 관측과 같은 방향이다. 🔴 단 1건 관측이고 createdAt 이 공개 시점과 같다는 보장이 없다(레포를 먼저 만들고 늦게 공개할 수 있다) → 약한 증거로만 취급.

📌 창≠누적이 나타나는 조건이 확정됐다

7쌍 14개 저장소 중 창 ≠ 누적인 것은 위 3건뿐이고, 전부 createdAt 이 30일 이상 지난 것이다. 30일 이내 생성된 11건은 예외 없이 창 = 누적. 🎯 그래서 downloads == downloadsAllTime 은 결측 신호가 아니다 — “이 저장소는 30일보다 어리다”는 신호다. 09-23에 Ternary-Bonsai-2-27B 에서 1건으로 본 것이 11/11 로 확인됐다. 📌 볼트 규약 추가: 두 값이 같으면 createdAt 을 확인해 “창이 생애 전체를 덮음” 이라 명시한다. null 이나 오류로 읽지 않는다.

downloads == downloadsAllTime 은 결측 신호가 아니라 “생성 30일 미만”의 지표다. 네 건 전부 6~12일이다. 예외는 여전히 0건. 🎯 그리고 이 규칙이 오늘 수집기 오류를 잡는 데 직접 쓰였다 — 수집기가 “3건 전부 None 이라 누적 미확보” 라 보고했을 때, 볼트는 값이 있을 뿐 아니라 downloads와 같아야 한다고 예측했고 실측이 그대로였다. 규칙이 관측을 예측했다.

🔴 창 길이 역산은 오늘 진전이 없다

09-24에 생성 30일 넘은 2건에서 ≈31.4일 · ≈28.5일 을 역산했으나(균일 다운로드율 가정), 오늘 배치는 4건 전부 30일 미만이라 역산에 쓸 표본이 0건이다. ⬜ 여전히 점추정 2개이고 등급 변화 없음(“실측 2건과 정합, 문서 미확인”). 📌 대신 창이 차오르는 속도가 관측됐다: Ternary-Bonsai-2-27B 09-24 1,908,396 → 09-26 3,109,078(이틀 +62.9%). 생성 10일차 저장소의 30일 창은 하루 단위로 크게 움직인다 → 배수 비교는 양쪽이 30일을 넘긴 뒤에.
