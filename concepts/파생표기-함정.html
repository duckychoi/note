파생표기 함정

한 줄

원문에서 파생된 표기(API 분류·표 서식·벤치마크 구성)를 원문 대신 읽으면 틀린다. 파생표기는 누군가가 원문을 해석한 결과지 원문이 아니다. 그 해석에는 실패 모드가 있고, 실패해도 에러를 내지 않는다.

볼트 규칙 계보 — 세 번째 항목

볼트는 같은 형태의 오류를 세 번 만났고 매번 한 칸씩 넓혔다:

  1. 2026-09-08 — “description은 소스가 아니다”
  2. 2026-09-09 — “이름도 소스가 아니다”(레포 이름에서 기능 추론 금지 — qm 건)
  3. 2026-09-10 — “API가 계산해준 필드도, 표의 서식도, 벤치마크 구성도 소스가 아니다” → 공통 구조: 원문 옆에 있는 더 읽기 쉬운 것을 원문 대신 읽었다. 매번 그게 더 편했기 때문이다.

2026-09-10 배치의 3개 사례 — 세 가지 다른 파생물, 같은 실패

① API의 파생 분류 — teamai-cli raw: “실제 LICENSE 파일은 Tencent 자체 라이선스” → 틀렸다. LICENSE 원문(1,418바이트)은 이렇게 쓴다: “teamai-cli is licensed under MIT… does not impose any additional restrictions” + MIT 전문 수록. GitHub이 NOASSERTION 을 준 이유는 자체 라이선스여서가 아니라 파일 머리의 Tencent 인사말 2줄이 licensee 자동탐지 정규식을 깨뜨려서다. → NOASSERTION 은 “라이선스가 아니다”가 아니라 “내 정규식이 못 읽었다”는 뜻이다.

② 표의 서식 — Qwen3.8-Flash-Next-NVFP4 카드 표가 FP8 행 전체를 볼드 처리해 시각적으로 FP8 우위를 암시한다. 실제 숫자는 9개 중 5개에서 NVFP4가 앞선다. → 볼드는 저자의 강조지 측정 결과가 아니다.

③ 벤치마크 구성 — Qwopus3.8-27B-Flash-GGUF raw는 이 모델을 텍스트 전용으로 기술했다. 실제로는 vision·multimodal·image-text-to-text 태그를 가진 멀티모달 모델이다. raw가 그렇게 읽은 이유: 벤치마크가 전부 텍스트(수학·물리·화학·MMLU-Pro)였다. → 평가가 텍스트만 다뤘다고 모델이 텍스트 전용인 건 아니다.

검증 규칙 (볼트 ingest 절차에 적용)

  1. 라이선스 — license.spdx_id 를 믿지 말고 LICENSE 파일 본문을 읽는다. NOASSERTION·Other 는 판정 유보 신호지 판정 결과가 아니다.
  2. 수치 — 볼드·색·하이라이트를 무시하고 숫자만 따로 뽑아 비교한다.
  3. 능력 범위 — 모달리티·지원 범위는 태그·pipeline_tag·아키텍처 기술에서 확인한다. 벤치마크 목록에서 역추론하지 않는다.
  4. 일반 규칙 — 어떤 필드가 다른 필드에서 계산된 것이면, 계산 이전의 것을 찾아본다.

왜 이 함정이 특히 위험한가

파생표기는 원문보다 짧고 구조화돼 있다. license: "MIT" 한 줄이 1,418바이트 법률 텍스트보다 읽기 쉽다. 볼드 처리된 행이 9개 숫자 비교보다 빠르다. → 효율이 정확도를 대체하는 지점이 정확히 여기다. 그리고 파생표기가 틀렸을 때 아무 신호도 없다 — text-to-cad 의 “조용한 실패 3종”과 같은 구조. → 측정도구-먼저-반증 의 형제 개념: 저기서는 계측기를, 여기서는 계측기의 출력 포맷을 의심한다.

🔄 2026-09-11 갱신 — 규칙이 이틀 연속 적중했고, 자기 처방이 하루 만에 함정이 됐다

① 라이선스 규칙 적중 — llm_wiki 도 NOASSERTION 인데 GPL-3.0

어제 teamai-cli(실제 MIT)와 완전히 동일한 원인이다. LICENSE 원문(35,195B) 볼트 직접 확인:

1행: LLM Wiki — Copyright (C) 2024-2026 Yong Su
3행:                     GNU GENERAL PUBLIC LICENSE
4행:                        Version 3, 29 June 2007

→ 전문 앞에 저작권 1줄이 붙어 자동탐지가 깨진다. 이틀에 두 건이면 우연이 아니라 흔한 패턴이다. → 그리고 이번엔 결과가 다르다: teamai-cli는 MIT(관대), llm_wiki는 GPL-3.0(전염성). 규칙을 안 지켰으면 참고 시 라이선스 위험을 놓쳤을 것이다. → 규칙의 값이 실증됐다.

🔴 ② 어제의 처방이 오늘의 함정이 됐다 — Nex-N2.5-mini

어제 볼트가 정립한 처방(규칙 3번):

“모달리티·지원 범위는 태그·pipeline_tag·아키텍처 기술에서 확인한다.”

오늘 Nex-N2.5-mini 실측: cardData.pipeline_tag = text-generation 인데 HF 태그에는 image-text-to-text 가 있고 본문은 멀티모달로 기술한다. 실질 멀티모달이다. → pipeline_tag 만 믿었으면 오늘 틀렸다. 어제 함정(벤치 구성에서 역추론)과 반대 방향의 같은 실패. → 🎯 규칙 3번 보강: “pipeline_tag 단독도 소스가 아니다. 태그 목록·본문 아키텍처 기술과 교차확인하고, 셋이 어긋나면 본문을 상위로 둔다.” → 📌 메타 교훈: “X를 보라”는 처방은 X가 틀릴 수 있다는 가능성을 함께 적지 않으면 다음 함정의 씨앗이 된다. 볼트의 처방은 단일 필드를 지목하는 형태를 피해야 한다.

③ 원문이 둘인데 서로 다른 경우 — vercel-skills (새 변종)

같은 README의 두 자동생성 블록이 어긋난다: 산문 “…and 75 more”(= 4+75 = 79) vs 표의 --agent 식별자 실카운트 78. → 지금까지 함정은 “원문 옆의 읽기 쉬운 것” 을 읽는 것이었다. 여기서는 둘 다 자동생성이라 무엇이 원문인지 불명이다. → 볼트는 판정하지 못하고 병기했다. 이건 규칙의 한계 지점이다 → 단위-불일치 미해결 질문으로 이월.

④ 벤더 정체성에서 정책 추론 — SenseNova-U1.5 (볼트 자신의 오류)

볼트가 2026-05-13 sensenova-u1 에 적었던 것: “SenseTime 특성상 완전 오픈소스 가능성 낮음” U1.5 초록: “We will open-source training code…” → 빗나갔다. → 09-09 규칙 “이름에서 기능을 추론하지 말 것” 의 확장: “벤더 이름에서 정책을 추론하지 말 것.” → 🎯 이건 raw의 오류가 아니라 볼트 자신의 오류다. 볼트도 같은 함정에 빠진다 — 요약자와-판정자-분리 가 “판정자는 안전하다”는 뜻이 아님을 보여준다.

규칙 계보 (4세대)

  • 2026-09-08 — description은 소스가 아니다
  • 2026-09-09 — 이름도 소스가 아니다
  • 2026-09-10 — API 필드·표 서식·벤치 구성도 소스가 아니다
  • 2026-09-11 — pipeline_tag 단독도, 자동생성 산문 요약도, 벤더 정체성도 소스가 아니다. 그리고 정확한 수도 내 질문의 답이 아닐 수 있다 → 마지막 절은 단위-불일치 로 분리 신설

🔄 2026-09-12 갱신 — NOASSERTION 이 사흘 연속, 그리고 Tencent 에서 두 번

3일 연속 재현 — 이제 우연이 아니라 관행이다

  • 09-10 teamai-cli (Tencent) — NOASSERTION → 실제 MIT
  • 09-11 llm_wiki — NOASSERTION → 실제 GPL-3.0
  • 09-12 WeKnora (Tencent) — NOASSERTION → 실제 MIT

볼트 실측(WeKnora): LICENSE 158,420B(서드파티 고지가 대부분). 8행: “This project is licensed under the MIT License except for the third-party components listed below.” 이후 MIT 전문 수록. → 🎯 벤더 규칙으로 승격 가능: Tencent 레포의 NOASSERTION 은 제약 신호가 아니라 「서드파티 고지를 LICENSE 파일에 합치는 관행」의 부작용으로 우선 가정하고, 본문 앞부분(8행 근처) 을 확인한다. → raw가 이번엔 행번호까지 정확히 짚었다(“LICENSE 본문 8행이 MIT”) — 09-11 볼트가 유지하라고 한 영역이 실제로 유지됐다.

🔴 반대 방향 사례 — null 은 NOASSERTION 과 다르다 (MathModelAgent)

지금까지 이 개념은 “NOASSERTION 을 보고 제약이 있다고 과대 판정” 하는 실패를 다뤘다. 오늘 반대 사례가 나왔다. 볼트 실측: MathModelAgent 는 GitHub API license: null 이고, 루트 파일 14개를 직접 조회한 결과 LICENSE·COPYING 계열이 0건이다. → 🎯 이 경우엔 원문을 열 수 없다. 원문이 없기 때문이다. 그리고 라이선스 부재의 기본값은 저작권 유보다. → 즉 null 은 판정 유보 신호가 아니라 실제 판정이다. NOASSERTION(= 파서가 못 읽음 → 원문 확인 필요)과 정반대로 취급해야 한다. → 볼트 규칙 정정: 09-10 actionable 3번 “NOASSERTION·Other 는 판정 유보 신호로 취급” 에 null 을 포함시키면 안 된다. null + LICENSE 파일 부재 = 사용 제한 확정.

인접 개념이 분리됐다

오늘 한정어-탈락 을 별도 개념으로 신설했다. 경계:

  • 파생표기 함정 = 파생물을 읽었다 → 처방: 원문을 봐라
  • 한정어 탈락 = 원문을 정확히 읽었는데 조건절을 안 옮겼다 → 처방: 원문을 봐도 안 잡힌다. 인용 주변 ±10행과 표를 봐라 09-11 vercel-skills 의 “산문 79 vs 표 실측 78” 은 두 개념의 경계 사례였고, 오늘 사례들로 한정어 탈락 쪽으로 정리된다.
