표 부분인용

2026-09-18 — 🆕 네 번째 축: 기준선. 그리고 평균은 행을 접는 연산이다

④ 기준선 축 — SoL-Pi: 이득이 두 기준선으로 보고됐다. 네이티브 Codex·Claude Code 대비 시간당 8.75 13.50∗∗,∗∗Pi대비로는4.36~5.71. 🎯 절감폭의 절반가량은 Pi가 이미 확보한 몫이다 — “$13.50 절감” 만 인용하면 기여를 2배 이상 부풀린다. 🔴 숫자는 둘 다 정확하므로 원문 대조로 걸리지 않는다(이 개념의 원래 논지). → 지금까지 축은 행(ms-marco-MiniLM-L6-v2) · 열(DeepSeek-R1 cons@64) · 표 개수(Qwen3.8-27B-TWIN-TURBO-709-GGUF) 였다. 기준선이 네 번째다.

📌 평균도 부분인용이다 — NeoHorse-1-9B: “10벤치 평균 69.04(+3.44) · 비교군 6종 중 1위” 인데 10개 축이 세 모델에 3:3:4 로 갈렸다(Gemma-4-12B-it 3축 1위 · Muse-Glimmer-30B 3축 1위 · NeoHorse 4축 1위). 🎯 평균은 행 전체를 한 칸으로 접는 연산이고, 접힌 것은 복원되지 않는다. 그리고 이 경우 평균이 덮은 것 중에 자기 베이스 대비 −0.37 하락이 있었다.

📌 출처 간 부분인용 — DeepSeek-V4.1-Flash-Paper: 🎯 논문 초록이 모델 카드보다 적게 말한다. 카드는 HLE 36.8 vs 56.3·TB4.0 31.2 vs 51.8 같은 불리한 축을 게시했는데, 초록은 “delivers substantially better performance” 한 줄이다. 🔴 요약은 약점을 먼저 버린다 → 같은 대상의 논문과 카드가 둘 다 있으면 불리한 수치는 카드 쪽에 있다.

한 줄

표에서 몇 점을 읽는가가 결론의 정확도가 아니라 종류를 바꾼다. 1점은 주장을, 2점은 우열을, 3점 이상은 기울기를 답한다 — 그리고 어느 열을 고르냐가 우열을 뒤집는다.

계보 — 볼트가 세 배치에 걸쳐 같은 실패를 만났다

배치소스읽은 범위놓친 것결론이 어떻게 바뀌었나
09-16ms-marco-MiniLM-L6-v2행 2개(L6·L12)행 L4”L12는 손해” → “L6이 수확체감 변곡점”
09-17DeepSeek-R1열 4/6열 cons@64·LiveCodeBench”70B에서 하락” → “크기·순위 관계가 열마다 다르다”
09-17Qwen3.8-27B-TWIN-TURBO-709-GGUF표 1/4표 2·3·4단계”거부 0/100 = 제거” → 🔴 “이 레포는 68/100”

🎯 09-16 이후 볼트는 “모델 패밀리 비교 시 최소 3점을 잡을 것” 을 규칙으로 요청했다. 수집기는 이행했다 — 5점 비교를 냈다. 그런데 같은 배치에서 두 번 더 실패했다. 📌 이유: 09-16 규칙은 행만 제약했다. 열과 표 개수는 제약하지 않았다.

축 1 — 열 선택 (DeepSeek-R1, 09-17)

수집기는 증류 패밀리 5개 행(1.5B·7B·14B·32B·70B)을 4개 열로 비교해 “변곡점은 14B, 32B→70B에서 하락” 을 얻었다. 행 규칙은 지켰다.

볼트가 6열 전부 읽자 다른 것이 보였다:

AIME 2024 pass@1 :  7B 55.5  →  32B 72.6   = +17.1점
AIME 2024 cons@64:  7B 83.3  →  32B 83.3   =   0.0점   🔴 동일

🎯 같은 벤치·같은 모델 쌍인데 집계 방식만 바꾸면 격차가 사라진다. 해석: 32B의 우위는 능력 상한이 아니라 1회 시도의 신뢰성이다. 64회 샘플링 예산이 있으면 7B가 32B를 따라잡는다(AIME 한정). 파라미터 4.6배가 집계 예산으로 교환된다. 🔴 그리고 cons@64 는 단조도 아니다: 14B(80.0) < 7B(83.3).

열 선택이 결론을 만든 증거: 6열 집계 시 70B가 4열 최고(카드가 직접 볼드 표기), 32B가 2열 최고. 수집기가 고른 4열에는 70B 최고 열이 2개만 들어갔다. 🎯 올바른 진술은 “70B는 하락한다”가 아니라 “순위가 열마다 다르다” 다.

축 2 — 표 개수 (Qwen3.8-27B-TWIN-TURBO-709-GGUF, 09-17)

카드의 성능 섹션에 표/수치 블록이 4개 있는데 수집기는 첫 번째만 읽고 모델에 귀속시켰다.

STAGE 1              KL 0.0535  거부 0/100    ← 🔴 타인(trohrbaugh) 작업
STAGE 2 (랩)         KL 0.0025  거부 11/100
STAGE 2 Twin Turbo   KL 0.0025  거부 68/100   ← ✅ 카드가 "[ THIS REPO/ MODEL ]"이라 명시
STAGE 2 ULTRA-HERETIC KL 0.0397 거부 6/100    ← "[ SEPARATE REPO ]"

🔴 68점 오류다. 그리고 오류의 방향이 나쁘다 — 모델 이름이 약속하는 것(Uncensored)을 카드가 부정하는데, 첫 표만 읽으면 카드가 긍정하는 것처럼 보인다.

🎯 4점을 함께 읽으면 축이 드러난다: KL이 낮을수록 거부가 남는다. 기계적으로 당연하다 — 거부 행동은 원본 분포의 일부이므로 제거하면 정의상 분포가 멀어진다. 두 지표는 독립이 아니라 같은 축의 양끝이다. ✅ 저자가 이 상충을 직접 적었다: “Stage 2 was balanced based on ultra low KLD first (performance, quality) matched with low refusal rate second.” 📌 68/100은 실수가 아니라 선언된 트레이드오프의 결과다. 카드는 정직했고, 읽는 쪽이 첫 표만 봤다.

🎯 왜 이 실패가 반복되는가 — 부분인용은 틀린 값을 만들지 않는다

세 사례 모두 인용한 숫자 자체는 정확했다. ms-marco-MiniLM-L6-v2 의 −0.01, DeepSeek-R1 의 72.6/70.0, DavidAU의 0.0535/0-100 — 볼트가 원문 대조해 전부 문자 일치였다.

🎯 그래서 위험하다. 오타·환각·과장은 대조하면 걸린다. 부분인용은 대조를 통과한다 — 인용한 범위 안에서는 사실이기 때문이다. 📌 잡히는 유일한 방법은 “인용하지 않은 부분”을 세는 것이다. 그것은 원문을 다시 읽어야만 가능하다.

🔗 인접 개념과의 구분:

  • 한정어-탈락: 저자가 붙인 한정어를 떼어내는 실패. → 텍스트 층
  • 측정도구-먼저-반증: 지표 자체가 현상을 못 재는 문제. → 지표 설계 층
  • 이 개념: 지표도 맞고 값도 맞는데 읽은 범위가 좁은 실패. → 독해 범위 층
  • 수확체감-변곡점: 이 개념의 결과물 중 하나(행 축을 3점 이상 읽었을 때 보이는 것)

⚖️ 판정 절차 (볼트 적용용)

표에서 수치를 옮길 때:

  1. 표가 몇 개인가? 성능 섹션 전체를 스캔한다. 🔴 같은 카드에 단계별·변형별 표가 여럿일 수 있다
  2. 각 표가 무엇에 귀속되는가? 🔴 ”[ THIS REPO ]” 류 표기를 찾는다. 표가 이 모델의 것인지, 이전 단계·타인·형제 레포의 것인지 확인
  3. 열이 몇 개인가? 🔴 열을 선택하지 않는다. 전 열을 옮기거나, 못 옮기면 “N열 중 M열을 옮겼다”를 적는다
  4. 행이 몇 개인가? 최소 3점(09-16 규칙 유지). 비교군 행(경쟁 모델)도 같은 표에 있으면 함께 본다
  5. 두 지표가 같은 축의 양끝일 가능성을 검사한다 — 한쪽 개선이 다른 쪽 악화를 정의상 수반하는가

볼트 규칙 (신설 · 09-16 규칙 확장)

표를 옮길 때: ① 표 개수와 귀속 대상을 먼저 확인 ② 열을 선택하지 말 것 ③ 선택했다면 “N열 중 M열”을 명시. 비용 비대칭: 열 2개 더 옮기기 = 후보당 몇 초 / 놓치는 것 = “7B가 32B와 같다” 또는 68점 오류.

✅ 대조군 — 부분인용이 아닌 경우

ProgramDistill(09-17)은 지는 축을 저자가 먼저 적었고 수집기가 그대로 옮겼다(GPT-6 Astra 49.2% / Claude Opus 5 28.8%, 깊이 1→8에서 100%→64.0%·96%→32%). 🎯 초록은 표가 아니라 문장이므로 “열을 고를” 여지가 없다. 부분인용 위험은 표 형식 출처에 집중된다 — 모델카드·벤치 표·README 기능표. 🔴 단 ProgramDistill 에도 미해결이 있다: 두 계열(100→64.0 / 96→32)이 무엇인지 초록이 밝히지 않는다 — 이쪽은 부분인용이 아니라 원문 자체의 부족이다.

🆕 2026-09-19 — 다섯 번째 축: 행마다 참조 모델 교체 → K2-Horizon-7B

셀 값은 IFM 블로그 표와 전부 일치하는데, 카드는 SciCode 행에서 유일한 승자(Gemma 4-12B 38.2 > 31.6)를 빼고 블로그에 없는 Mistral Small 4 를 넣었다. 🔴 값 대조로는 안 잡힌다. 📌 규칙 개정: “불리한 수치는 카드에 있다” → “불리한 수치는 전체 표가 있는 쪽에 있다”(이번엔 블로그). 📌 README 층위판: marin 은 README 에 베이스 승리(Llama 3.1 대비)만, 회고 문서에 SFT 패배(43.8 < Tulu 50.0) — 은폐는 아니나 README 만 읽으면 구조적으로 부분인용이 된다.
