하네스 설계 축

한 줄

모델을 바꾸지 않고 모델을 감싸는 층만 바꿔서 정확도·비용을 움직이는 것이 독립된 연구·제품 축으로 성립했다. 그리고 그 축의 결론은 대체로 “더 정교하게”가 아니라 “덜” 이다.

🆕 2026-09-19 — "학습루프 내재화" 층의 설계도 확보 → NeoHorse-1-Paper

라우터가 매 턴 예측 티어(C0~C3)·실제 서빙 티어·결과를 분리 기록 → 그 기록이 궤적(데이터) + 라우팅 점수(커리큘럼 순서) + 결손 프로파일(다음 혼합) 셋을 동시에 공급한다. 🎯 이 축의 첫 대조 실험 수치: 같은 레시피에서 데이터 출처만 바꿔 하네스 궤적이 공개 합성 데이터(Toucan) 대비 5벤치 평균 +6.26. 반면 데이터 양 스케일링은 +2.14. → 하네스는 “무엇을 넣나”보다 “어디서 데이터를 받나”로도 가치를 낸다. 🔴 단 라우팅 커리큘럼 자체의 절제는 없다 — 하네스의 기여 중 “데이터 출처” 몫만 측정됐다. ✅ 아래 미해결 ④(급등 원인이 이 논문일 가능성)는 절반 확인: 논문이 “하네스 매개 RSI”를 명시적으로 정식화한다. 단 09-18 배치 4건이 이 논문을 인용했는지는 미대조.

2026-09-18 — 한 배치에서 4건, 네 층이 전부 다르다

층                   사례                              근거 상태
─────────────────────────────────────────────────────────────────
구현(SDK)            [[harness-sdk]] ★7,345           🔴 벤치 0개
자동탐색             [[SoL-Pi]] (NVlabs) ★2,185       ✅ 토큰 −44.7~49.0%

학습루프 내재화      [[NeoHorse-1-4B]]/[[NeoHorse-1-9B]]  ✅ 10벤치 8열표

🎯 13건 중 4건 = 31%. 09-16 배치의 “모델 위 계층”, 09-17의 “실행 통제” 에 이어 세 배치 연속으로 같은 방향의 상승이 관측된다. 그리고 이번에 처음으로 같은 축 안에서 층이 갈렸다.

🎯 이 배치의 가장 강한 신호 — 독립된 두 방법이 같은 지점을 가리킨다

SoL-Pi: 자동연구 루프로 환경을 늘려 선택압을 통과한 메커니즘 4개만 남겼다 → 4개 중 2개가 컨텍스트 관련(압축·관측 처리). Harness-Design-Empirical: 176개 대조 설정으로 3요소를 절제 측정 → 컨텍스트 관리가 가장 중요하고 이득의 대부분은 오버플로 실패 방지에서 온다.

🎯 탐색으로 남은 것과 절제로 재서 중요한 것이 일치한다. 방법이 완전히 다른 두 연구가 같은 부품을 지목했다. 📌 볼트 판정: 이 일치는 단일 논문의 결론보다 강한 근거다. 🔴 단 두 논문 다 같은 주(09-17 공개)에 나왔고 서로를 인용하지 않았을 가능성이 높다 — 독립성은 추정이고 확인하지 않았다.

🔴 이 축의 결론이 반직관적인 방향으로 모인다

Harness-Design-Empirical 의 4개 결론을 다시 읽으면 셋이 “빼라” 다:

  • 생략분 복구 장치 → 모델이 거의 쓰지 않아 정확도 이득 없음(빼라)
  • 사전정의 도구 → bash 능숙 모델에는 bash 단독이 더 싸다(빼라)
  • 계획 → 강한 모델에서는 정확도 불변, 비용만 절감(효과가 다르다)
  • 컨텍스트 관리 → 유일하게 “넣어라”, 단 예산이 빠듯할 때만

🎯 SoL-Pi 도 같은 형태다 — 다수 환경에서 살아남은 것만 4개다. 무엇을 추가할지 설계한 게 아니라 무엇이 죽는지 관찰했다. 🎯 opensre 도 같은 방향이다 — “AI SRE remains unsolved” 로 주장 자체를 뺐다. 📌 축의 성숙 신호: 기능 추가 경쟁이 아니라 절제 경쟁으로 넘어갔다.

🔴 그런데 구현과 근거가 반대편에 있다

★ 많은 쪽:    harness-sdk 7,345 · pi-agent-harness 106,058   → 벤치 0개
근거 있는 쪽:  Harness-Design-Empirical (176설정)              → 🔴 코드 없음
              SoL-Pi (수치 범위 제시)                          → ✅ 코드 ★2,185

🎯 가장 엄격하게 측정한 논문이 재현 코드를 안 냈고, 가장 널리 쓰이는 SDK는 측정치가 없다. → 검사가능성-공사 가 양쪽에서 절반씩만 지어졌다. 📌 볼트가 쓸 수 있는 조합은 하나다: Harness-Design-Empirical 의 결론을 판정 기준으로 삼고, SoL-Pi 의 코드를 구현 참조로 읽고, harness-sdk 는 훅이 그 결론을 표현할 수 있는지로만 평가한다.

내게 적용되는 것 (즉시)

✅ 결론 ②를 볼트 인제스트 규칙으로 승격했다 → “큰 파일은 모델에게 던지기 전에 grep/sed/헤딩 스캔으로 규칙기반 축소를 먼저 한다.” 🎯 오늘 raw.md(454KB · 375행) 처리에서 실제로 그 순서를 썼다 — 전문 로드 대신 헤딩 맵 → 해당 구간(196~375행)만. 경험이 아니라 근거가 생겼다. ✅ 결론 ④도 내 방식을 지지한다 — bash 중심 작업.

미해결

① 층 사이의 상호작용을 아무도 재지 않았다. 학습루제 내재화(NeoHorse-1-4B)와 추론 시 컨텍스트 관리를 같이 쓰면 어떻게 되는가. ② harness-sdk 훅이 결론 ②(규칙기반 생략 → LLM 요약 순서)를 강제할 수 있는가 — 미확인. ③ 이 축의 결론이 최신 고난도 과제에서 유지되는가 🔴 — Harness-Design-Empirical 은 Terminal-Bench 2.1 을 썼고, DeepSeek-V4.1-Flash 는 TB 2.1 ↔ TB 4.0 에서 20점 갈린다는 것을 보여줬다. 하네스 결론의 세대 일반화가 미검증이다. ④ 이 축의 급등 원인이 선발창-누락 의 421 업보트 논문일 가능성 — 원인을 못 받고 결과만 봤다.

🆕 2026-09-19 — 세 번째 독립 분해: 부품 목록은 수렴, 중요도 서열은 불일치 → ModularRSI

5모듈(Agent Loop · Tool Use · Observation Mgmt · Context Mgmt · Task Completion Detection) 단일 진화(TB2.0): Agent Loop Acc 최대(+2.99) · Observation Mgmt 스텝 −35%(= SoL-Pi 관측 처리와 일치) · 🔴 Context Mgmt Acc 최저(+1.87) — Harness-Design-Empirical “컨텍스트 관리 1위”와 긴장(조건 차이로 읽음, 추정). 🎯 예산을 맞춘 AHE·Meta-Harness 재현은 기준선 +1점 안팎 — “벤치 위에서 진화시키면 벤치에 맞춰진다”의 첫 통제 증거. 🆕 온라인 RL 층: agent-lightning 은 하네스를 RL 환경 그 자체로 쓴다 → 하네스형-에이전틱-RL 신설. 새 소축 = 단위 문제(롤아웃당 2.41 샘플).
