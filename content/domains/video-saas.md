## 결과 QA — "최종 컷"이 아니라 "전개"를 본다 (2026-08-27 추가)

### VGI-BENCH가 바꾸는 재시도 전략
[[VGI-BENCH]](HF 데일리 4위·27과제 810인스턴스·초록 원문 대조)의 디노이징 내부 분석에서 **후반 스텝은 초기 가설을 다듬을 뿐 추론 오류를 교정하지 못한다**(limited self-correction)는 것이 관측됐다.

> [!action] 파이프라인 재시도 규칙 분리
> **스텝/해상도를 올리는 재시도는 화질을 올리지 추론을 고치지 않는다.** 구도·물리·인과가 틀린 샷은 더 오래 돌려도 안 고쳐진다.
> → 재시도 분기를 둘로 나눈다: **품질 불만 → 스텝·해상도 증가** / **구도·인과 오류 → 프롬프트·입력 조건 변경**(재생성).

### 생성 품질과 시각 추론은 별개다
최강 모델 **[[Seedance]] 2.0도 자체 기준 51.0%**. VFX 품질로 위키에 등록된 모델이 시각 추론에서는 절반 수준이다 — **"영상이 예쁘다"와 "말이 된다"는 다른 능력**임을 보여주는 수치. ⚠️ 다른 모델 개별 점수·채점 규칙 미공개, 코드/데이터 "공개 예정" 상태라 제3자 재현 불가.

### 경쟁 우위 빈틈 — 과정 기준 자동 검수
[[SemComp-Bench]](의미적 완료도 채점)와 [[VGI-BENCH]](전개 타당성)를 합치면 **생성 영상 자동 검수 렌즈**의 밑그림이 된다. 현행 툴들이 최종 프레임 품질만 보는 상황에서 **중간 프레임의 인과 일관성을 검사하는 QA**는 비어 있는 차별화 지점이다. [[HarnessEval-W]](생성물 평가의 에이전트화)가 같은 축.

## [2026-09-03] 자동수집 배치 — 데이터 계약(SolarWM)과 음성 하네스(VoiceStudio)

### [[SolarWM]] — 월드모델의 **데이터 계약**이 공개된다
10개 데이터셋 **143만 클립**을 **프레임 정렬 단일 계약**으로 통합: 시각 관측 · **미터법 카메라 기하** · 캡션 · **품질 메타데이터** · **선별 결정** · **출처**.
[[LTX-2.5]] · [[MiniMax-H3]] · Wan2.2 백본 위 **5B~33B 4종**을 각자 표현 보존한 채 학습. **5초 시퀀스만 학습해 분~시간 롤아웃**을 실시간 상호작용으로 주장.
- **디자인/파이프라인 레퍼런스**: ⭐ **계약 6개 필드 구조는 내 영상 파이프라인에 즉시 이식 가능**하다. 특히 *선별 결정*과 *출처*를 씬 메타데이터의 **1급 필드로 승격**시키는 발상 — 지금 내 [[reat-chunk]]/[[reat-scene]] 산출물은 *무엇을 골랐는지*는 남기지만 ***왜 뺐는지***를 안 남긴다.
- **경쟁 우위 빈틈**: 월드모델 논문 대부분이 **비교 불가능한 자체 세팅**에 갇혀 있었다. 공용 계약이 실제로 공개되면 그 파편화가 풀린다.
- ⚠️ **초록에 벤치 수치 0.** *"실시간"* 의 fps·해상도·GPU 미상, 장기 롤아웃에서 **무엇이 먼저 무너지는지** 미기술.

### [[VoiceStudio]] — ⭐ **[[reat-voice]] 로컬 대체 후보 (배치 유일 즉시 활용)**
⭐15,454 · **AGPL-3.0** · 당일 푸시. **모델이 아니라 16 TTS + 11 ASR 엔진 위의 하네스**다.
- **인터페이스 4종**: 데스크톱 앱 · 로컬 REST/SSE/WebSocket · **OpenAI 호환 오디오 API** · **MCP 서버**
- → 기존 TTS 호출을 **엔드포인트만 바꿔 로컬 전환** 가능하고, ASR 11종으로 **자막(SRT)까지 같은 스택**에서 처리된다. 계정·API 키·구독·사용량 미터 **없음**(로컬 워크플로).
- **워크플로 함의**: 음성 스택이 *"어느 모델을 쓸까"* 에서 ***"어느 껍데기에 꽂을까"*** 로 이동. [[SolarWM]]이 비디오 백본에 한 것과 **같은 패턴의 음성판**이다.
- ⚠️ **"646개 언어"는 레포가 스스로 한정**한다(*"actual coverage and quality depend on the selected engine"*). **엔진별 한국어 품질은 미측정** — 실측이 유일한 경로.
- ⚠️ **라이선스 2층**: 앱 AGPL-3.0(네트워크 서비스 제공 시 소스 공개 의무) / 다운로드 모델은 **각자 상위 조건 유지**. **개인 워크플로 = 문제없음 / 제품 임베드 = 엔진별 심사 필요.**

## [2026-09-04] 배치 — 타이밍·마스킹·가속, 조립형 파이프라인의 세 부품

### 🎯 [[TCR]] — 볼트 `reat-*` 파이프라인의 존재 이유를 외부에서 증명했다
결합 오디오-비디오 생성 모델은 **화질과 A/V 동기화는 이미 잘한다.** 못 하는 건 *언제 컷이 바뀌고 언제 대사가 나오는가* 다. 논문이 짚은 원인이 급소다 — 대본에 적힌 타이밍은 **프롬프트의 텍스트 표현에만** 인코딩되어 어느 모달리티의 시간 좌표와도 정렬되지 않는다. 결과: ***영상과 오디오는 서로 완벽히 동기화된 채로 둘 다 대본 타임라인을 벗어난다.***
- **Shot Boundary MAE 1.11초 → 0.042초 (96%↓)** · **Dialogue Acc@0.5s 28.3% → 84.1%** · 화질·동기화는 동등 유지 · 사용자 연구 5개 차원 전부 선호 (200개 대본)
- **함의**: 볼트의 `/reat-chunk → /reat-scene → /reat-render` 는 **생성 모델에 타이밍을 안 맡기고 SRT/beats로 밖에서 시간축을 강제**하는 설계다. TCR은 **그 선택이 옳았음을 정량화**했다 — 맡기면 1.11초가 나오고, **1초 넘게 어긋나면 편집물로 못 쓴다.**
- ⚠️ **볼트는 이 값을 한 번도 잰 적이 없다.** → actionable: `/reat-scene` 계획 컷 시각 vs 렌더 컷 시각의 **MAE 측정**. TCR의 0.042초가 비교 기준선.
- ⚠️ 베이스라인 모델명 미상·코드 미공개 → **수치는 목표치 참조용**으로만.

### 🎭 [[sam3]] — 로토스코핑 자동화의 실물 부품 (DL 2,081,577)
SAM 2까지는 점·박스로 **그 객체 하나**를 분할했다. SAM 3는 **짧은 텍스트로 지정한 개방 어휘 개념의 모든 인스턴스를 남김없이** 분할한다(PCS). *"모든 사람 흐리게"* 가 **1회 프롬프트**가 된다.
- **SA-CO 벤치마크에서 인간 성능의 75~80%**, 270K 고유 개념(기존의 50배) · **비디오 마스크·추적 지원** · 🤗 Transformers 정식 통합(`Sam3Model`)
- **편집자가 가장 시간을 쓰는 작업이 마스킹**이다. 조립형 파이프라인에 **후처리 단계로 끼우기 쉽다**(생성 모델 교체 불필요)
- **경쟁 우위 빈틈**: 상용 툴의 자동 마스킹은 대개 **폐쇄 어휘**(사람·하늘·배경). 270K 개방 어휘는 *"빨간 우산만"* 을 가능하게 한다
- ⚠️ 라이선스 `other` + 게이트 `manual` — **카드 열람이 자유롭다고 사용이 자유로운 게 아니다**

### ⚡ [[Minimax-h3-Turbo-lightx2v]] — 3주 전 볼트 가설의 검증 (DL 1,117,509)
08-12에 [[MiniMax-H3-Turbo-Lora]](DL **669**)를 보며 *"파생 가속 계층 형성의 신호, 단 초기 단계"* 라 적었다. **3주 만에 같은 계열이 DL 111만**이다.
- **Turbo LoRA / 베이스 = 1,117,509 / 5,118,457 = 21.8%** — **베이스를 받는 다섯 중 하나가 가속 LoRA도 받는다.** 파생 가속층은 **표준 배포 구성품**이 됐다 → "초기 단계" 판정 폐기
- **FL2V 8-step 768p**, Apache-2.0, 게이트 없음, **이 모델을 쓰는 Space 85개**, 무료 웹앱(`x2v.light-ai.top`)
- **오픈 i2v의 병목은 화질이 아니라 대기 시간이었다** — DL 21.8%가 그 증거. 사람들은 품질을 조금 내주고 속도를 산다
- ⚠️ 단 **승자는 다른 제작자**였다(larryvrh → lightx2v). 당시 트렌딩 3위가 승자를 예고하지 않았다 — *"순위와 사용은 다른 것을 잰다"* 추가 사례
- ⚠️ **가속 폭·품질 손실은 3주 뒤에도 여전히 미공개.** 채택이 1,670배 커져도 **근거는 커지지 않는다.** 베이스 라이선스는 `other` 이므로 LoRA가 Apache라도 **상용 시 베이스 조항이 지배**

### 이 배치가 video-saas에 남긴 것
세 부품이 **조립형 파이프라인의 서로 다른 칸**에 정확히 들어간다 — **타이밍**(TCR·측정 기준) · **마스킹**(SAM 3·후처리) · **속도**(Turbo LoRA·렌더). 공통점은 셋 다 **생성 모델 자체를 바꾸지 않고 주변에서 제어를 늘린다**는 것이며, 이는 [[암묵을-명시로]] 가 말하는 방향과 같다.

# 📦 2026-09-07 배치 — [[Motion-Omni]] (재분류: ai-news → video-saas)

## 아바타 파이프라인에서 **단계 하나가 사라졌다**

말하는 아바타는 *무엇을 말할지* 와 *말하며 어떻게 움직일지* 를 동시에 정해야 하는데, 두 능력은 **다른 모델 계열**에 살았다. 표준 해법인 **캐스케이드**(음성 완성 → 그 오디오로 모션 생성)는 **두 번째 완전 추론 패스**를 요구하고 **공동 최적화를 원천 차단**한다.

[[Motion-Omni]] 은 **음성을 만들어내는 바로 그 hidden state에서** 표정·손·상반신·하반신 모션을 직접 출력한다.

| 항목 | 값 |
|---|---|
| 모션 품질 | teacher 캐스케이드 대비 **2% 이내**(reference-free) |
| 속도 | **5.4배** · **RTF 0.78**(실시간 초과) |
| WER | **2.62%** — 비교 omni-modal 중 최저 |
| 학습 | 의사 라벨 **422,856쌍 / 1,402시간** |

> [!warning] 인용 주의 — **teacher를 이긴 게 아니다**
> *"2% 이내로 **맞췄다**"* 이지 *"더 좋다"* 가 아니다. 주장은 **품질을 거의 유지하면서 실시간을 넘겼다** 이다.

## 이 도메인에 주는 함의 — **생성(offline) 축과 대화(online) 축이 갈린다**

볼트가 추적하는 [[Higgsfield]]·[[Seedance]] 계열은 **영상을 만드는** 축이다. **RTF 0.78** 은 *"실시간으로 반응하는 캐릭터"* 가 성립하는 선이고, 이건 **다른 제품 범주**다.
→ [[AI-영상-생성-2026]] 에서 아바타·립싱크는 **다단 파이프라인**(텍스트→음성→립싱크→모션)이 기본이었는데, 이 논문이 **음성↔모션 경계를 제거**한다. **단계가 줄면 지연이 준다.**

> [!insight] 값싼 경로가 막혔다 — 파이프라인 설계에 직접 걸리는 제약
> 초록: *"**with the speech pathway frozen, motion remains misaligned**"* — **기존 음성 모델에 모션 헤드만 붙이는 방식은 실패한다.** LLM·Speech Generator·Motion Generator를 **함께 적응**시켜야 한다.
> → **자체 구현보다 모델 공개를 기다려 채택하는 게 합리적.** 모듈 조립으로는 안 된다.

## 저평가된 기여 — **비교 가능성을 만든 것**
**SwDA-500** + *"확률적 개방형 전신 음성대화 **최초의 공개 평가 프로토콜**"*. 모션 시스템 간 **오디오를 맞춘 뒤** 렌더링·자동지표·인간평가·지연을 통일한다.
→ **모델을 못 써도 프로토콜은 즉시 전용 가능.** 볼트가 아바타/립싱크 도구를 비교할 때 *"오디오를 맞춘 뒤 비교한다"* 는 통제 하나만 가져와도 기존 비교가 정직해진다. → [[검사가능성-공사]]

### 이 배치가 video-saas에 남긴 것
지난 배치들이 **생성 모델을 바꾸지 않고 주변에서 제어를 늘리는** 방향이었다면([[암묵을-명시로]]), 이번엔 반대다 — **모델 내부를 합쳐서 단계를 없앤다.** 주변 제어로는 얻을 수 없는 것(**지연**)이 목표일 때 쓰는 수단이며, **경쟁 우위 빈틈은 RTF < 1** 이다.
