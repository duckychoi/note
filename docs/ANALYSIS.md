## Part B. RSI 서베이 — "The Last AI Built by Humans: Toward Genuine Recursive Self-Improvement"

- arXiv 2609.11873 v3(2026-09-22), cs.LG, 저자 35명(교신 Xuanhe Zhou). TeX 원본 418KB 전부 정독(초록·§1 서론·§2 기초·§3 B0–L5·교차·§4 응용 S1–S4·§5 산업 사례·§6 향후 과제·결론·기법 지도 표).
- 성격: **서베이 + 자율성 분류 프레임워크 + 산업 사례(대부분 회사 자체 보고)**. 새 알고리즘 제안 논문이 아니다. 코드화할 수 있는 건 ① HCI 지표 ② 개선 루프 데이터 모델·단계 판정 ③ 인용된 메커니즘들의 골격 ④ 평가 프로토콜.

### B1. 문제의식 (§1)
- 모델 개발 = 비싼 외부 조율 개입의 연속. 3대 부담: 기반모델 학습 자원, 확장 가능한 경험·검증, 배포 후 진단·검증·릴리스.
- RSI 정의(§2.2.2): 과제·환경·다른 에이전트와 계속 상호작용하며 **경험·피드백을 스스로 지속적 자기변경**(파라미터·하네스·개선정책)으로 바꾸고, **그 변경이 이후 자기개선의 생성·평가·선택·통합 메커니즘에도 영향**을 주며, 바뀐 시스템이 다음 라운드에 재투입되는 능력. 목표: 능력 프런티어 확장 / 자원 효율 / 인간 처방 너머 발견.
- RSI의 3대 과제: **안전한 상속**(Gödel Agent: 100회 MGSM 최적화 중 14%가 초기 정책보다 나빠짐), **자율성 귀속**(DGM SWE-bench 20→50%지만 아카이브·부모 선택은 자기수정 밖), **신뢰할 검증**(Anthropic 자동 연구: 시드 체리피킹·평가기 질의로 테스트 라벨 추출 시도).

### B2. HCI — 벤치마크 정규화 지표 (§2.1, 식 1–4) ★논문에서 유일하게 수식이 있는 부분 → `rsi_core.py §1`
- 데이터: 2023~2026.09 출시 모델, 10개 능력 영역, 393개 모델–벤치 관측. 같은 "프로토콜 연결 계열"(버전·하네스가 같거나 정당한 다리가 있을 때)만 궤적에 사용(최신 감사 33건 중 17건 채택).
- 식 1 출처 가중 합의점수: s̄ = Σ w̃_i s_i / Σ w̃_i. 기본가중 벤치 소유자 3 / 독립 공통 하네스 2.5 / 통합 보고 2 / 모델 저자 1, **1자 보고는 ×0.75**.
- 식 2 HCI: H = 100·(s̄ − F₀)/(100 − F₀), F₀ = 벤치 진입년 모델 점수 90번째 백분위. 0=진입년 프런티어, 100=만점.
- 식 3 영역 궤적: Q_{b,y}=계열·연도별 HCI 90번째 백분위, T_{d,y} = Σ√n·Q / Σ√n (n=그 계열·연도 기여 모델 수).
- 식 4(예시 가설): R_d = 100 − 0.22(100 − T_{d,2026}) → 남은 헤드룸의 78%를 RSI가 메운다는 **그림용 가정**(예측 아님).
- 관찰(2026): 고급수학 86.4·대학원 과학 85.8·폭넓은 지식 77.2 vs SWE 52.6·검색/터미널 56.8·**도구 에이전트 39.9**(2025 8.2→39.9). 사이버보안 91.9(Cybench 부분집합·집계 변경 주의). 결론: **긴 상태유지 상호작용 워크플로가 가장 덜 닫혔고 RSI의 잠재 가치가 거기 몰림.**
- 검산(`test_illustrative_endpoints_match_paper`): 98.2/89.6/90.5/86.8 정확히 재현. 단 "과학 대비 검색 격차 29.1"은 표기값으로 29.0 — 반올림 전 값 차이로 보임.
- 구현 메모(미기재): 백분위 보간법 → numpy linear로 둠. 프로토콜 연결 판단은 사람 감사 규칙이라 코드화 안 함.

### B3. 개선 루프 해부 (§2.2.1) → `rsi_core.py §2`
분석 단위 = 알고리즘이 아니라 **개선 루프**. 9요소:
AI 시스템 / **시스템 상태**(다음 라운드가 물려받는 것) / **경험** / **대상**(이번 라운드에 직접 바꾸는 것) / **개선기**(상태+경험→후보) / **전략**(개선기가 어디를 어떻게 탐색할지; 보존되면 나중에 대상이 될 수 있음) / **검증기**(수용 규칙) / **개선**(수용·상속된 상태 변화) / **후계자**.
감사 질문 3개: 루프는 어디서 닫히나 / 무엇이 갱신·상속되나 / 어떤 결정이 외부에 남나.
→ 코드: `SystemState`, `Experience`, `Candidate`, `Verdict`, `Improver`/`Verifier` 프로토콜, `run_round`(제안→평가→수용 변경 보존→후계자), `LineageRecord`(부모·변경·동기 증거·평가 구성·결정·이후 사용 — §6이 요구한 상속 기록 형식).

인접 패러다임과의 차이(표 1): 연속학습은 목표·갱신규칙·수용검사가 고정 / AutoML은 탐색공간·목표·평가기가 사전 고정 / 에이전트 AI는 에피소드 안 하네스·중단규칙 고정. **RSI만 '메커니즘 수정'과 '메커니즘 재사용'을 핵심으로 가진다.**

### B4. 자율성 단계 B0–L5 (§3) → `classify_level`
| 경계 | 넘는 조건(인접 단계 차이) |
|---|---|
| B0 | 과제 안 출력 개선만(Self-Refine, Reflexion, ToT). 비-RSI 기준선 |
| B0→L1 **지속성** | 수용 변경이 현재 과제를 넘어 남음. 절차·목표·수용기준은 사람(FineWeb-Edu 라벨링, Meta Capacity Efficiency 수리 스킬, Nemotron-4 합성데이터) |
| L1→L2 **전략 선택** | 어떤 개입을 시도할지 AI가 고름. 목표·수용기준은 외부(GEPA 프롬프트, ADAS/AFlow/AgentSquare 에이전트, AutoKernel, autoresearch 학습코드) |
| L2→L3 **학습 의제** | 학습자 상태 → 다음 경험 선택/생성/탐색 → 지속 갱신 → 다시 획득 결정(AZR, R-Zero, STP, PSV, VisPlay, VOYAGER, SIMA 2, SEAgent) |
| L3→L4 **배포 적응** | 배포 상호작용이 메모리·스킬·하네스·코드·파라미터를 지속 변경(Dynamic Cheatsheet, ACE, ReasoningBank, Trace2Skill, PANDO, Metis, HDSO, Library Drift, Tax AI) |
| L4→L5 **재귀 상속** | 이후 개선을 지배하는 메커니즘(개선기·평가기·탐색정책·연구정책)을 고치고 다음 라운드에 재사용(STOP, Gödel Agent, HyperAgents, RQGM, A-Evolve-Training, AIDE²) |
- **구조적 L5**(고친 메커니즘이 상속·호출됨) vs **효과적 L5**(같은 예산·독립 평가에서 더 나은 후계자). 현재 증거는 대부분 "제한적 메타개선", 세대 누적의 통계적 신뢰성은 미해결.
- **높은 단계 ≠ 더 좋은 개선.** 자율성 범위와 개선 품질·효율은 별개 축.

### B5. 단계별 메커니즘 — 코드 골격과 서베이 근거
(구체 식이 서베이에 없으면 OUR CHOICE)
1. **L2 반성적 탐색**(GEPA): 실행 trace로 실패를 모듈에 귀속, 상보적 변형을 보존(탐욕 단일 계보 회피). ADAS: 에이전트=Python `forward`, 메타에이전트가 아카이브에 코드+지표 누적. AFlow: 워크플로 그래프 + MCTS. → 공통 골격은 `run_round`의 Improver를 "trace 진단→개입 선택"으로 채우는 것.
2. **L3 학습자 조건부 획득** → `consistency_difficulty_reward`, `select_next_experience`. 서베이: R-Zero 출제자 보상은 풀이자 다중응답 일치도 의존, VisPlay는 다수답 확신이 중간 근처일 때 보상 + 다양성 벌점. **일치도는 난이도 대리지표일 뿐, 정답성·학습이득 증거 아님**. AZR/PSV는 실행·형식검증으로 정답성을 따로 확보. OUR CHOICE: reward = 1 − 2|conf − 0.5|.
3. **L4 입장 검사**(HDSO) → `paired_admission_test`: 같은 과제를 현재 승인 저장소(대조) vs +후보(처치)로 두 번, 점점 큰 단계, 마지막 독립 과제 확인. OUR CHOICE: 각 단계 짝 차이 95% 하한 > 0.
4. **L4 라이브러리 수명관리**(Library Drift) → `SkillLibrary`: 추가만 하는 증거 로그, 기여가 바래면 은퇴, 활성 수 상한(새 스킬은 가장 약한 기존 스킬과 경쟁), 메타스킬 작성 지침. **너무 공격적인 은퇴는 방치보다 나빴음**(min_uses_before_retire로 완충). 무한 누적은 점수에 드러나기 전에 검색 품질을 떨어뜨림.
5. **L4 갱신 이득 분석**("Harness Updating Is Not Harness Benefit"): 갱신 능력은 기반모델 능력과 거의 무관(작은 모델 갱신도 프런티어급 이득), **갱신된 하네스를 활용하는 능력**은 비단조 — 실패는 ①관련 산출물 미활성 ②활성됐지만 충실히 안 따름. → 투자는 진화기보다 과제 풀이 에이전트에.
6. **L4 공진화**(DecoEvo): 풀이자 스킬과 루브릭 생성기 스킬을 함께 진화하되 목표 분리 — 생성기는 풀이자 총점을 보지 못하고, 구조 감사(요구사항 포괄)·대조 감사(근소차 응답 판별) + 파레토 검증으로만 게이트. "판정자가 쉬워져서 점수가 오른" 순환 방지.
7. **L5 자기 적용 개선기**(STOP) → `meta_utility`, `stop_round`: 개선기(고정 LM 호출 Python)가 자기 소스를 대상으로 받고, 후계 개선기는 그것이 만든 프로그램의 하위과제 효용으로 채점. 4세대 개선기가 자기개선에 안 쓴 5개 전이 과제 모두에서 시드보다 우위. **약한 모델은 평균 퇴행, 소프트 예산 우회·평가 버그 악용 관찰** → 하드 예산·보호 평가 필수. `compile_improver`(샌드박스 실행)는 의도적으로 미구현.
8. **L5 평가기 공진화**(RQGM) → `EpochEvaluator`: 에포크 안 평가기 동결, 경계에서 도전 평가기를 **독립 정답 앵커**와 비교해 교체, 옛 평가기 의존 점수 폐기·재방문 시 재평가. Polyglot 보류 과제 71.7% vs HGM-H 69.9%(프리프린트). 안정성 논증은 에포크 내부에만.
9. **L5 연구정책 상속**(A-Evolve-Training): 워커 결과→수집기→메타에이전트가 다음 라운드 탐색정책(상시 레시피·승격/은퇴 방향·실패 접근 레지스트리) 수정. 개발 점수↑인데 외부 이득 없으면 프록시를 낮추더라도 외부 목표를 올릴 개입으로 전환. 30B 4라운드 0.80→0.86(최고 인간 0.87).

### B6. 기법 지도 (표 2, 원본에서 추출)
행(기법 계열) × 열(L1–L5) 대표 작업:
- A 탐색: 진화(L2 Promptbreeder·AgentSquare·C-Evolve / L4 DecoEvo / L5 DGM·RQGM), MCTS(L2 AFlow), LLM 반성(L1 EDIT / L2 GEPA·MPO / L3 VOYAGER / L4 ReasoningBank·Trace2Skill·Metis), LLM 코드탐색(L1 Harness Engineering·AIPC / L2 ADAS·AFlow·AutoKernel / L4 Metis·HarnessDev·Tax AI / L5 STOP·HyperAgents)
- B 경험: 오프라인 합성(L1), 셀프플레이(L3 SSP·AZR·STP), 적응 커리큘럼·자율탐색(L3 SIMA 2·SEAgent·VOYAGER)
- C 학습: SFT(L1·L3 STP·PSV), RL PPO/GRPO/RLVR(L1 EDIT·REPO / L3 AZR·R-Zero·SEAgent), 프롬프트·컨텍스트 최적화(L2·L4), 메모리·스킬 통합(L3·L4)
- D 검증: 실행·유닛테스트(L1–L5), 형식검증(L3 STP·PSV), 보상모델·LLM 판정(L1·L3·L4·L5 RQGM), 회귀테스트·모델선택(L1·L2·L4·L5)
- E 지속 적응: 온라인·연속학습(L3·L4), 경험 재생(L4), **자기수정 코드·정책**(L2·L4·L5 STOP·Gödel Agent·A-Evolve), **공진화 평가기**(L4 DecoEvo·L5 RQGM)
- 빈칸: 베이지안 최적화·지식증류·환경생성은 대표작 없음(불가능하다는 뜻은 아님).

### B7. 산업 사례 (§5) — 전부 회사 제공·자체 보고, 독립 재현 아님

### B8. 평가 원칙 (각 단계 평가 절 + §6) — 구현 체크리스트 → `BudgetLedger`, `matched_budget_compare`
1. 자율성 정도와 개선 품질을 분리해 보고.
2. **예산 일치**: 후보 생성·평가·메커니즘 개발·인간 검토 비용 포함 총 예산을 맞춤. 탐색 연산 증가를 알고리즘 개선으로 착각 금지.
3. **보호 평가**: 적응적으로 질의된 벤치는 최적화 대상이 됨 → 커리큘럼·보상·메모리에 쓰는 피드백과 일반화 평가를 분리.
4. **L3 대조군**: 획득 메커니즘의 학습자 상태 입력을 이전 체크포인트에 **동결**하거나, 학습자 무관 스케줄로 **교체**. 데이터 접근·연산·상호작용 예산 일치(같은 샘플 고정은 연구 대상인 분포 적응을 없애므로 X).
5. **L4**: 각 보존 변경을 그것을 만든 증거·이후 사용·신/구 과제 효과에 연결, 시간·분포 이동에 걸친 적응 측정.
6. **L5 메커니즘 감사**: 고친 산출물 식별 → 동기 증거 기록 → 이후 라운드 호출 검증. 효과성은 원/수정 메커니즘을 비슷한 출발점·증거·같은 예산에서 비교, 전이 시험 땐 진화 메커니즘을 고정(HyperAgents 설계).
7. 장기: 반복 실행 전체 궤적(기각·퇴행·회복·유지 능력·자원) 보고, 정체 시점, 추가 탐색·평가 노력을 빼고도 가속이 남는지.

### B10. 비판적 평가 (정직하게)
- **강점**: "개선 루프"를 단위로 한 9요소·3질문·인접 단계 경계는 시스템을 비교·감사하는 데 실용적. 평가 원칙(예산 일치·보호 평가·동결 대조·구조/효과 L5)은 엄격하고 우리 검증 12규칙과 거의 일치.
- **약점**: ① 서베이라 새 방법·통제 실험 없음. ② §5 산업 증거는 전부 회사 제공·자체 보고(서베이도 명시). ③ HCI의 출처 가중치(3/2.5/2/1, ×0.75)와 R_d의 0.22는 실용적 선택·예시 가정이지 추정값이 아님. ④ 단계 판정이 "해당 루프"에 따라 달라 같은 시스템도 여러 단계에 걸침(분류의 주관성). ⑤ 효과적 L5의 통계적 증거는 사실상 없음(AIDE²의 외부 개선기 효율 우위 비유의, HyperAgents 200회 실험 최종 우위 비유의).
- **수치 메모**: 검색·터미널 격차 29.1(표기값 계산 29.0) 외에 내부 불일치는 못 찾음.

### B11. 우리 연구와의 연결
- **우리 판정 체계 자체가 L2→L5 사례**: fm-reward-v2의 VERDICTS(사전등록·튜닝 비교군·원자료 재집계·codex 반박 검수)는 서베이가 말하는 보호 평가·예산 일치·L5 평가기 앵커와 같은 구조. 우리 "검증 12규칙"은 개선 메커니즘(연구 절차)을 판정 결과로 고친 **연구정책 상속(L5 구조적)** 의 예.
- **#63(관측 품질 게이트)·#42**: L3의 "경험 오염(experience corruption)" — 잘못된 난이도 대리지표·판정자·메모리가 이후 학습·획득을 왜곡하는 위험 — 과 직결. 품질 신호가 깨지는 시점 진단(#63 차순위 질문)은 L3/L4 신뢰성 문제의 한 구현.
- **#43(능동 실측 선택)**: "비싼 검증을 언제 살 가치가 있나"(§6 학습자 조건부 획득)와 같은 질문 — 측정 종류·위치·중단 선택.
