## 0. 한 줄 요약
**GRPO(토큰 레벨) + 두 가지 수정(엔트로피 적분제어로 움직이는 비대칭 상한 클립, 외부 비율 클립) + 강한 데이터 필터(early-exit·통과율) + 학습–추론 수치 일치(마스크·라우팅 재생, 비트 일치) + 붕괴 시 자기증류로 재시작.** 알고리즘 자체는 DAPO·dual-clip PPO·DeepSeek 계열 기법의 조합이고, 진짜 무게는 "몇 주~몇 달 비동기 RL을 수천 GPU에서 안 터지게 돌리는" 인프라와 안정화에 있다.

## 1. 목적함수 (§3.1.1, 식 4–9)
- 프롬프트 q 마다 G개 응답 y_1..G, 보상 R_i.
- 어드밴티지: A_i = (R_i − mean(R)) / std(R), 응답의 모든 토큰에 공유. (std 종류 미기재 → 모집단 std 사용)
- 비율: r_{i,t} = πθ(y_{i,t}|·) / π_old(y_{i,t}|·), π_old = **롤아웃을 만든 정책**.
- 토큰 레벨 정규화: J = (1/Σ_i|y_i|) Σ_i Σ_t min(r·A, clip(r)·A). **전역 배치의 모든 토큰(모든 DP 랭크)** 으로 나눔 → 긴 응답의 토큰도 같은 가중.
- **적응 신뢰영역**: r^tr = clip(r, 1−ε, (1−ε)^{-1} + k). k=0 에서 로그비 대칭.
- **외부 비율 클립**(식 9): r^out = clip(r, r_min, r_max) 를 모든 가지에 적용. PPO가 열어두는 두 가지(A<0·r>1, A>0·r<1)가 극단 비율에서 그래디언트 폭주를 일으켜서 추가. r_max=50, r_min=0.
  - 구현 해석: s = min(r^out·A, r^tr·A). r>r_max 면 상수가 되어 그래디언트 0 (dual-clip PPO와 같은 정신). ← 해석 선택, 원문은 수식만 제시.
- KL 항·엔트로피 보너스: **없음**(엔트로피 보너스는 적응 제어보다 못했다고 보고).

## 2. 엔트로피 적분제어 (식 7–8)
- Ĥ = (1/|T|) Σ −log πθ(y_t)·r_t  (π_old 표본으로 πθ 엔트로피를 중요도 가중 추정).
- 매 스텝: k ← clip(k + δ·sign(H* − Ĥ), 0, k_max). 초기 k=0.
- 값: ε=0.6, k_max=2.5, δ=0.25, H*=0.3. (Fig.13 예시는 k_max=1.0)
- 의도: 엔트로피가 낮으면 상한을 넓혀 "대안 토큰 확률을 더 공격적으로 올리게" 함.

## 3. 보상 (§3.1.2, 식 10–12; §3.4.1)
- R = R_task + w_lang·R_lang − w_len·R_len.
- R_lang = max(1 − α·(CoT 내 비영어 단어 수), 0). w_lang=0.5, α=0.005. (혼합 언어 CoT가 학습–추론 로그확률 괴리 급증과 상관 → 불안정. top-p 도 비슷한 효과)
- R_len = ρ_q·|y|/ℓ_max, ρ_q = 그 문제의 통과율. 쉬운 문제는 길이에 강하게, 어려운 문제는 약하게 벌점. w_len=0.25(64k 단계까지), 128k 단계에서 0.
- 다목적 결합(도움·안전 climb): 합산 대신 **사전식**(상위 보상이 그룹 내 동률일 때만 하위 보상 사용, 스케일 불변) 또는 **게이트**(안전 불통과면 최소 보상, 품질 채점 안 함).

## 4. 샘플링 (§3.1.3, §3.6.2)
- **early-exit**: G_early=16 개로 통과율(보상>0 비율) 계산 → [0.05, 0.8] 밖이면 폐기.
- 통과하면 G=128 까지 생성 → **통과율 필터** [0.1, 0.8] 밖이면 폐기(분산 작은 그룹 제거). ※ §3.6.2는 "추가 128개"라 적어 총 수가 모호.
- **top-p 마스크 재생**: p=0.97 로 샘플링, 그 nucleus 마스크를 저장했다가 학습 때 제외 토큰 logit=−∞. 안 하면 "수 스텝 내 발산하는 파국적 오프폴리시 불일치".
- **길이 커리큘럼**: 최대 길이 8k→16k→32k→64k→128k.

## 5. 비동기·오프폴리시 (§3.1.5, §3.6, Rocket 글)
- 추론 가중치 갱신 사이 **5 그래디언트 스텝**, 생성 정책이 **8 갱신(=40 스텝)보다 오래된 롤아웃 폐기**.
- 한 롤아웃이 여러 가중치 버전에 걸칠 수 있음(Rocket 글: 최장 롤아웃이 6개 버전, 그룹 내 최단 롤아웃이 최장을 7.6시간 기다림).
- staleness ≈ (샘플러 지연 + 학습 시각 − 생성 시각) / 스텝 간격. 추론 서버를 늘리면(배치 고정) 스텝이 빨라져 staleness가 **오히려 늘 수 있음**.
- 긴 길이에선 어려운 문제의 긴 롤아웃이 더 stale → lr 1e-6 → 9e-7 로 낮춤.
- 대형 런은 off-policy 컨트롤러, 소형 실험·디버깅은 on-policy.

## 6. 학습–추론 수치 불일치 (가장 실전적인 부분)
- 측정: 같은 토큰에 대한 샘플러 vs 학습기 로그확률의 평균 절대차(Rocket Fig.3). staleness와 함께 커지고, **RL이 진행될수록 커짐**(최적화가 수치 차이를 증폭·착취한다고 추정).
- MAI-Thinking-1: 양쪽 **bf16**, **MoE 라우팅 재생**, **top-p 마스크 재생**.
- MAI Base 2(Rocket 2): **비트 단위 일치** 달성, 성능 저하 없음, 일치 런이 더 높은 점수(Fig.6, 수치 미공개).
  - 어텐션 출력 투영: 샘플러는 TP 유지하되 o_proj 가중치 복제 + 헤드 출력 all-gather → 교차 GPU 합산 제거, 학습기는 TP 없이 같은 합산 순서.
  - MoE: TP 없는 EP, all-to-all 로 받은 전문가 출력을 **FP32로 같은 순서로** 가중합.
  - 어텐션 커널: 학습 forward·prefill·decode 모두 같은 FA4, 슬라이딩 윈도 K-블록 경계를 학습기 타일에 정렬, split당 KV 토큰 수 고정.
  - 정밀도: MoE 가중치는 MXFP8 저장·BF16 계산 → 학습기는 **같은 양자화 후 즉시 역양자화(fake quant)**. KV는 국소층·마지막 전역 3층 BF16, 나머지 전역층 MXFP8(학습기도 KV fake quant). 전문가 matmul을 MXFP8로 하면 불일치↑.

## 7. 실패 복구·자기증류 (§3.1.4, Rocket 글)
- 붕괴 직전 체크포인트로 돌아가도 소용없는 경우가 많음(불안정이 붕괴 한참 전에 파라미터에 이미 박힘).
- **자기증류**: RL 중 나온 성공 trace로 mid-trained 체크포인트를 SFT → 그 모델에서 RL 재개. O(1M) trace면 교사 성능 회복. 여러 **후반** 체크포인트의 trace를 섞을 것(초반 trace는 해롭고, 마지막 하나만 쓰면 다양성 부족). 같은 토큰 예산이면 프롬프트 다양성 > 프롬프트당 trace 수. 단순 무작위 선택이 편향 선택보다 나음. 긴 문맥 능력 망각 방지로 mid-training 데이터 혼합. 하이퍼: 배치 2048, 길이 128k, AdamW wd 0.001, cosine lr 1.7e-5→5.2e-6, warmup 2%.
- 인프라 복구: **학습기만 재시작**(~5분, 추론·커리큘럼 유지, 한 런에서 GPU 시간 7% 이상 절약), 추론 복제본 교체, 탄력성(학습 연산 9.88% 개선), 3단 방어(복제본 워치독·라우터 서킷브레이커·잡 수준 생존 감시 + 스텝 진행 워치독).

## 8. 하이퍼파라미터 (§3.1.5)
AdamW β1=β2=0.95, eps=1e-15, wd 0 · lr 1e-6 상수(긴 길이 9e-7), warmup·decay 없음 · 전역 배치 7040(packing 후), 비packing 시퀀스 ≤12000 · dropless MoE, 부하균형 계수 1e-5 · 최대 길이 128k · 규모 예: GB300 4864칩 중 추론 4096 : 학습 768(최대 5:1).

## 9. 구조 (§3.6)
컨트롤러(문제 선택·필터·배치 구성·가중치 전송 시작·커리큘럼 상태) → 문제 워커(early-exit/전체 롤아웃 요청, 그룹 채점, 어드밴티지) → 롤아웃 워커(에이전트 루프: 추론 호출 ↔ 도구 실행, 개별 채점) → SGLang 라우터·서버(부하분산, 단일턴은 prefix cache 끔·다중턴은 hit 97–98%) → 학습기(YOLO). 가중치 전송은 학습기·추론 샤딩 교집합으로 계산한 **전송 계획**을 시작 시 한 번 컴파일해 재사용(Rocket 2: 2단계 전송 15초).

## 10. 주장과 근거의 강도
- MAI-Thinking-1 공개 벤치(표 11): **선두는 아니고 경쟁권**(예: SWE-bench Verified 73.5 vs Opus 4.6 80.8, AIME 2025 97.0). 저자 스스로 "does not lead the field".
- Rocket 글의 "Claude Opus 4.8을 넘었고 몇 주 내 GPT-5.6 Sol 추월": **사내 집계 벤치**(수십 개 평가를 한 숫자로) 기준 **자기보고**, 점수·오차막대·프로토콜 미공개 → 검증 불가.

## 11. 우리 소규모 점검에서 본 것 (판정 아님)
`src/demo_entropy_control.py`, `src/ablation_k_only.py` (표 정책, V=4, T=5, 시드 5):
- 단위테스트 12개 통과(유한차분 그래디언트 300+ 토큰 일치, 클립 각 경우, 제어기·필터·마스크·staleness).
- 전체 레시피 toy: 정답률이 오르면 **통과율 필터가 문제를 전부 걸러** 54–61% 반복에서 학습 중단 → 엔트로피 하한을 정한 건 제어기가 아니라 필터.
- ε=0.6 에서 상한(2.5)이 거의 안 걸려 k 는 무효(k=0 과 비트 단위 동일 궤적).
- 상한이 걸리는 조건(lr 10배, 상한클립률 0.05–0.1%)에서 k 를 키우면 엔트로피가 오히려 0.469→0.446 (5시드 모두 같은 방향): 상한 완화는 **양의 어드밴티지 토큰**을 키우는데, 다중정답 무대에선 그게 '더 자주 뽑힌 답'이라 쏠림을 가속. → 논문의 "대안 토큰 탐색" 직관은 **저확률 토큰이 양의 어드밴티지를 받을 때만** 성립. LLM 규모 재현은 `docs/PREREG.md`.
