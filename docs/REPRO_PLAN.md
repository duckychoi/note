## 0. 하드웨어 티어와 공통 규칙

| | 티어 A: RTX A6000 ×2 | 티어 B: RTX 5090 ×1 |
|---|---|---|
| GPU 메모리 | 48GB × 2 (합 96GB) | 32GB |
| 세대 | Ampere — BF16 가능, **FP8 텐서코어 없음** | Blackwell — BF16·FP8(·FP4) |
| 병렬 | DDP 2장(가능하면 NVLink) | 단일 GPU, 메모리 부족 시 grad checkpointing·accumulation |
| 권장 | 큰 모델(ViT-L 교사, 1.5B LLM) | 작은 모델 + FP8 실험(DeepSeek-V3식 FP8은 티어 B만) |

공통:
1. **처리량 탐침 먼저**: 각 트랙 본실험 전 200스텝을 돌려 초당 샘플·토큰과 최대 메모리를 기록하고, 아래 시간 추정을 그 값으로 다시 계산해 `runs/<track>/budget.json`에 저장한다. 아래 시간은 **추정치**다.
2. **같은 예산 비교**: 비교 팔은 같은 스텝·같은 샘플 수·같은 벽시계 상한. 비교군 하이퍼파라미터도 같은 검증 예산(팔당 3후보 × 짧은 런)으로 튜닝.
3. **시드 3개 이상**, 데이터셋·시드 짝 차이와 95% 구간으로 보고. 원자료는 JSON으로 저장하고 보고는 그 JSON에서 재집계.
4. **양성 대조**: 각 트랙은 공개 체크포인트로 평가 하네스가 논문 수치를 재현하는지부터 확인. 실패하면 실험보다 평가 코드부터 고친다.
5. 결과는 불리한 것 포함, 결론 먼저.

## D. 깊이 모델 전 과정 (Depth Anything V2 + Depth Pro 절차 축소판) — `depth/`

**재현할 절차**: 합성 전용 교사 → 실사진 가짜 라벨 → 학생 → 미터 단위 미세조정 → 합성 전용 경계 다듬기 → 제로샷 평가.

**데이터(공개)**
- 교사용 합성: Hypersim(~7.4만 프레임, 장면 단위로 받기 가능) + Virtual KITTI 2(~2.1만). 티어 B는 Hypersim 절반 + VKITTI2.
- 무라벨 실사진(DA2의 6200만 대신): COCO 2017 unlabeled(12.3만) + train(11.8만) ≈ 24만장. 티어 B는 12만장.
- 미터 미세조정: Hypersim·VKITTI2 미터 깊이(DA2 공개 미터 모델과 같은 선택).
- 제로샷 평가: NYUv2 test(654), KITTI Eigen test(652), DIODE val, ETH3D. 경계: Hypersim·VKITTI2 보류 장면의 깊이 경계 F1(Depth Pro식 깊이비 경계).
- 데이터는 `depth/README.md`의 폴더 형식(`rgb/*.png` + `depth/*.npy` + `valid/*.png`)으로 변환.

**모델·설정**

| 단계 | 티어 A (A6000×2) | 티어 B (5090) |
|---|---|---|
| 교사 | DINOv2 ViT-L/14 + DPT, 518², GPU당 배치 4 × 누적 4 (유효 32), 4만 스텝 | DINOv2 ViT-B/14 + DPT, 518², 배치 8 × 누적 4, 4만 스텝 (ViT-L은 392² + checkpointing으로 선택) |
| 가짜 라벨 | 24만장, 518², 수평 뒤집기 TTA 평균 | 12만장 |
| 학생 | ViT-S/14와 ViT-B/14, GPU당 배치 16, 6만 스텝 | ViT-S/14, 배치 16, 6만 스텝 |
| 미터 | 학생에서 2만 스텝, CSTM 정준 초점 f_c=300 | 같음, 1만 스텝 |
| 경계 다듬기 | 합성만, MAE+MSE+다중스케일 미분, 1만 스텝 | 5천 스텝 |
| 옵티마이저 | AdamW, 인코더 5e-6 / 디코더 5e-5, 1% 워밍업·80% 상수·19% ×0.1 (Depth Pro 스케줄) | 같음 |
| 추정 시간 | 교사 ~1.5일, 라벨 ~6시간, 학생 S+B ~1.5일, 미터+다듬기 ~0.5일 | 교사 ~1.5일, 학생 ~1일, 나머지 ~0.5일 |

**양성 대조(필수, 먼저)**: 공개 Depth-Anything-V2-Small 가중치로 우리 평가 코드(`depth/eval.py`)를 돌려 2406.09414 표의 NYU·KITTI AbsRel/δ1과 상대오차 5% 이내로 맞는지 확인. 안 맞으면 정렬(스케일·시프트 최소제곱, 시차 공간 여부)·크롭·유효 마스크부터 고친다.

**가설(사전등록)**
- **HD1(가짜 라벨의 가치)**: 같은 크기·같은 스텝에서 "가짜 라벨 실사진 학생"이 "합성만 학생"보다 제로샷 AbsRel이 낮다. 관문: 4개 평가셋 평균 상대 개선 ≥ 5%, 4개 중 3개 이상에서 같은 방향, 시드 짝 95% 구간 하한 > 0.
- **HD2(기울기 정합 손실)**: 교사 학습에서 gm 가중 2 vs 0 → 경계 F1 개선(하한 > 0), AbsRel 악화 ≤ 2%.
- **HD3(합성 전용 경계 다듬기)**: 다듬기 후 경계 F1 개선, AbsRel 악화 ≤ 2% (Depth Pro 주장 재현).
- **HD4(미터)**: 상대 학생에서 미세조정이 같은 스텝의 처음부터 미터 학습보다 NYU·KITTI 미터 AbsRel이 낮다(FoundationGeo 주장).
- 절제: 가짜 라벨 손실 상위 10% 무시 on/off, DINOv2 특징 정렬 on/off.
- **중단**: 양성 대조 실패, 또는 교사가 Hypersim 보류 장면에서 학습 1만 스텝 내 AbsRel 개선이 없으면 구현 결함으로 보고 중단.

## G. 이미지·영상 생성 — `gen/`

### G1. 처음부터 축소 학습: rectified-flow DiT (Wan 절차 축소판)
- **데이터**: 이미지 = ImageNet-100 클래스 부분집합(~13만장, 클래스 조건), 영상 = UCF-101(1.33만 클립, 101 동작 클래스) 17프레임.
- **잠재**: 이미지·영상 모두 Wan2.1 VAE(4×8×8, C16)로 사전 계산 — 이미지는 1프레임 영상(T=1)으로 인코딩해야 같은 DiT로 공동 학습 가능(`gen/precompute_latents.py`, 기본값). 클래스 표는 ImageNet-100(0–99) + UCF-101(100–200, `--label_offset 100`). VAE는 학습하지 않는다(축소판 범위 밖).
- **모델**: Wan식 공유 adaLN DiT(`gen/dit.py`), 3D patchify(1,2,2). 티어 A: DiT-B(~130M, d768, 12층) / 티어 B: DiT-S(~33M, d384, 12층).
- **목표**: 속도 예측 rectified flow, t ~ logit-normal(0,1), 해상도 시프트 α=√(m/n), 클래스 드롭아웃 10%(CFG).
- **커리큘럼**: (1) 128px 이미지 → (2) 256px 이미지 → (3) 이미지 + 128px 영상 공동(이미지 비율 30% 유지) → (4) 고품질 부분집합 어닐링. 각 단계 LR 1e-4 → 마지막 단계 3e-5, AdamW wd 1e-3(Wan), EMA 0.9999.
- **예산(추정)**: 티어 A 총 ~4일(이미지 40만 스텝 + 영상 15만 스텝, 배치 256/128), 티어 B ~4일(DiT-S, 배치 128/64).
- **평가**: 이미지 FID-10k(clean-fid), 영상 UCF-101 클래스 조건 FVD(StyleGAN-V 구현), 샘플 50스텝 Euler.
- **양성 대조**: 평가 하네스로 공개 DiT 계열 체크포인트나 실데이터 분할끼리의 FID가 상식 범위인지 확인.
- **가설**: HG1 logit-normal vs 균등 t → 같은 스텝 FID 개선(SD3). HG2 해상도 시프트 on/off(256px). HG3 영상 단계에서 이미지 혼합 유지 vs 영상만 → FVD(Wan·Hunyuan 관행). HG4 공유 adaLN(+깊이 증가) vs 블록별 adaLN, 같은 파라미터 수(Wan 절제 재현). 관문: 시드 3개 짝 차이 95% 하한 > 0.

### G2. 실제 Wan2.1-T2V-1.3B 후학습 (선택)
- LoRA SFT(소량 큐레이션 클립 500~2000개, 480p) → 선호 단계(보상 가중 또는 Diffusion-DPO; 보상 = 미학 점수 + 텍스트 정합). Wan 공식 저장소·DiffSynth-Studio류 학습기 사용 권장 — **이 저장소에 코드 없음**(GPU·가중치 없이 검증 불가해서 넣지 않음).
- 티어 A: 1.3B LoRA 480p 81프레임. 14B는 오프로딩이 필요해 비권장. 티어 B: 1.3B LoRA 480p.
- 평가: VBench 부분 차원 + 블라인드 쌍비교 50쌍.

## L. LLM — `llm/`

### L1. 처음부터 소형 사전학습 (DeepSeek-V3 / Kimi K2 절차 축소판)
- **데이터**: FineWeb-Edu `sample-10BT`, GPT-2 BPE(tiktoken)로 uint16 샤드(`llm/prepare_data.py`). 어닐링 혼합: FineMath + 코드 부분집합 20%.
- **모델**(`llm/model.py`): 사전정규화·SwiGLU·RoPE·GQA·QK-RMSNorm. 
  - 티어 A: dense 313M(24층, d1024, 16/4헤드), MoE 변형(8전문가 top-2 + 공유 1, 총 693M · 활성 313M).
  - 티어 B: dense 114M(12층, d768, 12/4헤드), MoE 변형(총 208M · 활성 111M).
- **단계**: (1) 일반 1K 문맥, WSD 스케줄(워밍업 1% → 상수 → 마지막 20% 감쇠, 최고 LR 1.5e-3 small / 6e-4 medium), AdamW(0.9/0.95, wd 0.1) → (2) 어닐링(마지막 10%를 수학·코드 혼합으로) → (3) 문맥 확장 1K→4K(RoPE 기저 10K→500K, 2% 토큰).
- **토큰 예산(추정)**: 티어 A 313M × 7B 토큰 ~2.5일 / 티어 B 114M × 5B 토큰 ~1.5일 (bf16. 티어 B의 FP8 팔(HL4)은 이 저장소 코드에 미포함 — torchao 등 FP8 학습 도구를 붙여야 함).
- **평가**: 보류 검증 손실, HellaSwag(nanoGPT식 다지선다 로그우도), 수학 검증 손실, 문맥 확장 후 4K needle 검색 정확도.
- **양성 대조**: 공개 GPT-2 124M 가중치로 HellaSwag 하네스가 알려진 값(~0.29)을 내는지.
- **가설**: HL1 WSD vs 코사인, 같은 토큰 → 최종 검증 손실(동률이어도 WSD는 분기 어닐링이 싸다는 점을 별도 보고). HL2 MoE 보조손실 없는 편향 균형 vs 보조손실 균형(DeepSeek-V3 절제) → 같은 활성 파라미터 검증 손실 + 전문가 부하 최대/평균. HL3 dense vs MoE(같은 활성·같은 토큰). (티어 B) HL4 FP8 vs BF16 손실 상대오차 < 0.5%(DeepSeek-V3는 0.25%).

### L2. 후학습: SFT → GRPO(검증가능 보상) → 증류 (R1 / Qwen3 절차 축소판)
- **베이스**: Qwen2.5-1.5B(티어 A) / Qwen2.5-0.5B(티어 B).
- **단계**: (1) 콜드스타트 SFT 수천 건(GSM8K·MATH 학습셋 정답 풀이 형식화) → (2) GRPO(`llm/grpo.py`): 그룹 8~16, 규칙 보상(정답 일치 + 형식), 통과율 0 또는 >0.9 문제 제외, 클립 0.2/0.28, KL 0.001, 토큰 레벨 정규화, 최대 생성 1024 → (3) 거부샘플링 SFT → (4) 0.5B에 1.5B 온폴리시 로짓 증류(`llm/grpo.py`의 증류 모드).
- 티어 A: GPU 1장 생성(vLLM 권장) + 1장 학습. 티어 B: 생성·학습 시분할(HF generate, 느림).
- **평가**: GSM8K test(1319) pass@1 온도 0, MATH-500 pass@1, 오염 검사(학습셋과 13-gram 중복 제거).
- **양성 대조**: 하네스로 Qwen2.5-1.5B-Instruct 공개 GSM8K 값을 상대 5% 이내 재현.
- **가설**: HL5 GRPO가 같은 GPU시간의 SFT만보다 GSM8K 개선. HL6 비대칭 클립(0.2/0.28) vs 대칭(0.2)(DAPO). HL7 통과율 필터 on/off. HL8 0.5B: 증류 vs 같은 GPU시간 GRPO(Qwen3 주장: 증류 우세).

## V. VLM (LLaVA식 축소판, Qwen-VL 단계 구조) — `vlm/`
- **구성**: 비전 인코더 동결(티어 A: SigLIP-so400m / 티어 B: SigLIP-base) + 2×2 토큰 병합 + 2층 MLP + LLM(Qwen2.5-1.5B / 0.5B).
- **데이터**: 0단계 LLaVA-Pretrain 55.8만 캡션(티어 B는 20만), 1단계 LLaVA-Instruct-665K 부분집합(티어 A 30만 / B 15만) + 순수 텍스트 SFT 20%.
- **단계**: 0단계 프로젝터만(LR 1e-3, 1에폭) → 1단계 프로젝터+LLM(LR 2e-5, 1에폭; 비전은 동결 유지).
- **평가**: lmms-eval로 MMBench-dev, TextVQA val, POPE + 텍스트 능력 보존(MMLU 부분집합) 확인.
- **양성 대조**: 공개 LLaVA-1.5-7B 등의 하네스 점수가 보고값과 맞는지.
- **가설**: HV1 0단계 정렬 생략 시 1단계 동일 예산에서 성능 하락. HV2 1단계에 순수 텍스트 20% 혼합이 텍스트 능력 하락을 줄이면서 멀티모달 점수 손해 ≤ 1%p.
