영상 AI SaaS 누적 인사이트

최근 흐름 (2026-09-15 배치 · 1건) — 편집이 렌더 뒤가 아니라 스트림 위로 올라왔다

🔀 신규 1건 — Vidu-S2 (raw ai-news → video-saas 재판정)

재판정 근거: 전작 Vidu-S1 이 이미 이 도메인에 있다. 같은 계보의 후속작을 다른 도메인에 두면 누적 인사이트가 끊긴다.

🎯 S1이 “실시간 생성”을 열었다면 S2는 “실시간 편집”을 연다. S2-Avatar: 540p → 720p 실시간 · 언제든 갱신 가능한 동적 레퍼런스 · 춤 같은 지시 따르기 강화 S2-Editing(신설): 스트림 상태에서 스타일 렌더링 · 의상 교체 · 인물 교체 · 배경 교체 여기에 실시간 공간(spatial) 비디오 탐색까지.

📌 내 reat-* 스택의 전제와 정면으로 다르다. 현재 파이프라인은 프롬프트 → 렌더 → 클립 → 후처리다. S2는 편집이 렌더 뒤가 아니라 스트림 위에서 일어난다 — 프리뷰와 최종본의 구분이 사라진다.

🔴 성립 조건 부재 — 초록에 수치가 하나도 없다 초록 전부: "Experiments show that Vidu S2 outperforms all baselines." baseline 이름·벤치마크명·수치 전무. 확인 가능한 비교 대상은 자사 전작 S1뿐. 🔴 S1은 "소비자 GPU 540p·42FPS"를 명시했는데 S2는 하드웨어 조건을 안 적었다 — 720p 향상이 같은 조건인지 알 수 없다 → 단위-불일치. 후속작이 전작보다 신뢰도가 낮다(S1 medium → S2 low). 능력은 올라갔는데 검증가능성은 내려갔다.

당장 할 것

vidu.com/vidu-stream 데모 직접 실측. 논문이 안 준 수치는 데모에서만 얻는다 — 720p 실시간 실측 · 편집 지연 · 인물 교체 품질.

최근 흐름 (2026-09-10 배치 · 1건)

Programmable-World-Model — 비디오 모델을 렌더러로 강등시켰다

월드 상태 진화를 시각 관측 생성과 완전히 분리한다. 에이전트가 자연어를 실행 가능 프로그램(엔티티 상태 + 전이 규칙)으로 번역 → 경량 엔진이 명시적·영속적 전역 상태 유지(화면 밖 엔티티·비시각 속성 포함) → 상태 증강 3D OBB를 중간표현으로 → 카메라 궤적과 함께 픽셀 정합 조건신호로 결정적 컴파일 → 사전학습 비디오 모델이 렌더링.

🎯 내 reat- 파이프라인과 구조가 같다*: beats.json/scene-plan.json = 프로그램, Remotion = 결정적 컴파일러, 비디오 모델 = 렌더러. 차이는 하나 — 내 쪽엔 영속 전역 상태가 없다. 씬 간에 유지돼야 할 것(캐릭터 위치·화면 밖 요소·누적 값)이 암묵적이다 → 암묵을-명시로

크리에이터 관점: 사용자가 영상 AI에 진짜 원하는 건 예쁜 한 컷이 아니라 “아까 그 캐릭터가 계속 그 캐릭터인 것”. 상용 툴(Higgsfield·Seedance)은 영속 상태를 안 준다 → 경쟁 빈틈.

📊 CombatStateBench Count 94% / State 98%. ⚠️ 그러나 저자가 같은 논문에서 신설한 벤치마크이고 비교 모델명·수치가 초록에 없다. “substantially outperforming” 이라는 서술뿐 → 자기 시험지의 자기 점수. 사전학습 비디오 모델이 무엇인지도 미명시라 재현 불가. reliability medium → 측정도구-먼저-반증

함께 볼 것: 같은 배치 Show-Harness 가 로봇 쪽에서 동일한 구조(의미 층 분리 + 결정적 접지)를 제안했다. 서로 다른 도메인에서 같은 설계가 나온 것은 신호일 수 있다.

목표: Higgsfield 같은 영상 자동화 SaaS 개발

결과 QA — “최종 컷”이 아니라 “전개”를 본다 (2026-08-27 추가)

VGI-BENCH가 바꾸는 재시도 전략

VGI-BENCH(HF 데일리 4위·27과제 810인스턴스·초록 원문 대조)의 디노이징 내부 분석에서 후반 스텝은 초기 가설을 다듬을 뿐 추론 오류를 교정하지 못한다(limited self-correction)는 것이 관측됐다.

파이프라인 재시도 규칙 분리

스텝/해상도를 올리는 재시도는 화질을 올리지 추론을 고치지 않는다. 구도·물리·인과가 틀린 샷은 더 오래 돌려도 안 고쳐진다. → 재시도 분기를 둘로 나눈다: 품질 불만 → 스텝·해상도 증가 / 구도·인과 오류 → 프롬프트·입력 조건 변경(재생성).

생성 품질과 시각 추론은 별개다

최강 모델 Seedance 2.0도 자체 기준 51.0%. VFX 품질로 위키에 등록된 모델이 시각 추론에서는 절반 수준이다 — “영상이 예쁘다”와 “말이 된다”는 다른 능력임을 보여주는 수치. ⚠️ 다른 모델 개별 점수·채점 규칙 미공개, 코드/데이터 “공개 예정” 상태라 제3자 재현 불가.

경쟁 우위 빈틈 — 과정 기준 자동 검수

SemComp-Bench(의미적 완료도 채점)와 VGI-BENCH(전개 타당성)를 합치면 생성 영상 자동 검수 렌즈의 밑그림이 된다. 현행 툴들이 최종 프레임 품질만 보는 상황에서 중간 프레임의 인과 일관성을 검사하는 QA는 비어 있는 차별화 지점이다. HarnessEval-W(생성물 평가의 에이전트화)가 같은 축.

[2026-09-03] 자동수집 배치 — 데이터 계약(SolarWM)과 음성 하네스(VoiceStudio)

SolarWM — 월드모델의 데이터 계약이 공개된다

10개 데이터셋 143만 클립을 프레임 정렬 단일 계약으로 통합: 시각 관측 · 미터법 카메라 기하 · 캡션 · 품질 메타데이터 · 선별 결정 · 출처. LTX-2.5 · MiniMax-H3 · Wan2.2 백본 위 5B~33B 4종을 각자 표현 보존한 채 학습. 5초 시퀀스만 학습해 분~시간 롤아웃을 실시간 상호작용으로 주장.

  • 디자인/파이프라인 레퍼런스: ⭐ 계약 6개 필드 구조는 내 영상 파이프라인에 즉시 이식 가능하다. 특히 선별 결정과 출처를 씬 메타데이터의 1급 필드로 승격시키는 발상 — 지금 내 reat-chunk/reat-scene 산출물은 무엇을 골랐는지는 남기지만 왜 뺐는지를 안 남긴다.
  • 경쟁 우위 빈틈: 월드모델 논문 대부분이 비교 불가능한 자체 세팅에 갇혀 있었다. 공용 계약이 실제로 공개되면 그 파편화가 풀린다.
  • ⚠️ 초록에 벤치 수치 0. “실시간” 의 fps·해상도·GPU 미상, 장기 롤아웃에서 무엇이 먼저 무너지는지 미기술.

VoiceStudio — ⭐ reat-voice 로컬 대체 후보 (배치 유일 즉시 활용)

⭐15,454 · AGPL-3.0 · 당일 푸시. 모델이 아니라 16 TTS + 11 ASR 엔진 위의 하네스다.

  • 인터페이스 4종: 데스크톱 앱 · 로컬 REST/SSE/WebSocket · OpenAI 호환 오디오 API · MCP 서버
  • → 기존 TTS 호출을 엔드포인트만 바꿔 로컬 전환 가능하고, ASR 11종으로 자막(SRT)까지 같은 스택에서 처리된다. 계정·API 키·구독·사용량 미터 없음(로컬 워크플로).
  • 워크플로 함의: 음성 스택이 “어느 모델을 쓸까” 에서 “어느 껍데기에 꽂을까” 로 이동. SolarWM이 비디오 백본에 한 것과 같은 패턴의 음성판이다.
  • ⚠️ “646개 언어”는 레포가 스스로 한정한다(“actual coverage and quality depend on the selected engine”). 엔진별 한국어 품질은 미측정 — 실측이 유일한 경로.
  • ⚠️ 라이선스 2층: 앱 AGPL-3.0(네트워크 서비스 제공 시 소스 공개 의무) / 다운로드 모델은 각자 상위 조건 유지. 개인 워크플로 = 문제없음 / 제품 임베드 = 엔진별 심사 필요.

[2026-09-04] 배치 — 타이밍·마스킹·가속, 조립형 파이프라인의 세 부품

🎯 TCR — 볼트 reat-* 파이프라인의 존재 이유를 외부에서 증명했다

결합 오디오-비디오 생성 모델은 화질과 A/V 동기화는 이미 잘한다. 못 하는 건 언제 컷이 바뀌고 언제 대사가 나오는가 다. 논문이 짚은 원인이 급소다 — 대본에 적힌 타이밍은 프롬프트의 텍스트 표현에만 인코딩되어 어느 모달리티의 시간 좌표와도 정렬되지 않는다. 결과: 영상과 오디오는 서로 완벽히 동기화된 채로 둘 다 대본 타임라인을 벗어난다.

  • Shot Boundary MAE 1.11초 → 0.042초 (96%↓) · Dialogue Acc@0.5s 28.3% → 84.1% · 화질·동기화는 동등 유지 · 사용자 연구 5개 차원 전부 선호 (200개 대본)
  • 함의: 볼트의 /reat-chunk → /reat-scene → /reat-render 는 생성 모델에 타이밍을 안 맡기고 SRT/beats로 밖에서 시간축을 강제하는 설계다. TCR은 그 선택이 옳았음을 정량화했다 — 맡기면 1.11초가 나오고, 1초 넘게 어긋나면 편집물로 못 쓴다.
  • ⚠️ 볼트는 이 값을 한 번도 잰 적이 없다. → actionable: /reat-scene 계획 컷 시각 vs 렌더 컷 시각의 MAE 측정. TCR의 0.042초가 비교 기준선.
  • ⚠️ 베이스라인 모델명 미상·코드 미공개 → 수치는 목표치 참조용으로만.

🎭 sam3 — 로토스코핑 자동화의 실물 부품 (DL 2,081,577)

SAM 2까지는 점·박스로 그 객체 하나를 분할했다. SAM 3는 짧은 텍스트로 지정한 개방 어휘 개념의 모든 인스턴스를 남김없이 분할한다(PCS). “모든 사람 흐리게” 가 1회 프롬프트가 된다.

  • SA-CO 벤치마크에서 인간 성능의 75~80%, 270K 고유 개념(기존의 50배) · 비디오 마스크·추적 지원 · 🤗 Transformers 정식 통합(Sam3Model)
  • 편집자가 가장 시간을 쓰는 작업이 마스킹이다. 조립형 파이프라인에 후처리 단계로 끼우기 쉽다(생성 모델 교체 불필요)
  • 경쟁 우위 빈틈: 상용 툴의 자동 마스킹은 대개 폐쇄 어휘(사람·하늘·배경). 270K 개방 어휘는 “빨간 우산만” 을 가능하게 한다
  • ⚠️ 라이선스 other + 게이트 manual — 카드 열람이 자유롭다고 사용이 자유로운 게 아니다

⚡ Minimax-h3-Turbo-lightx2v — 3주 전 볼트 가설의 검증 (DL 1,117,509)

08-12에 MiniMax-H3-Turbo-Lora(DL 669)를 보며 “파생 가속 계층 형성의 신호, 단 초기 단계” 라 적었다. 3주 만에 같은 계열이 DL 111만이다.

  • Turbo LoRA / 베이스 = 1,117,509 / 5,118,457 = 21.8% — 베이스를 받는 다섯 중 하나가 가속 LoRA도 받는다. 파생 가속층은 표준 배포 구성품이 됐다 → “초기 단계” 판정 폐기
  • FL2V 8-step 768p, Apache-2.0, 게이트 없음, 이 모델을 쓰는 Space 85개, 무료 웹앱(x2v.light-ai.top)
  • 오픈 i2v의 병목은 화질이 아니라 대기 시간이었다 — DL 21.8%가 그 증거. 사람들은 품질을 조금 내주고 속도를 산다
  • ⚠️ 단 승자는 다른 제작자였다(larryvrh → lightx2v). 당시 트렌딩 3위가 승자를 예고하지 않았다 — “순위와 사용은 다른 것을 잰다” 추가 사례
  • ⚠️ 가속 폭·품질 손실은 3주 뒤에도 여전히 미공개. 채택이 1,670배 커져도 근거는 커지지 않는다. 베이스 라이선스는 other 이므로 LoRA가 Apache라도 상용 시 베이스 조항이 지배

값싼 경로가 막혔다 — 파이프라인 설계에 직접 걸리는 제약

초록: “with the speech pathway frozen, motion remains misaligned” — 기존 음성 모델에 모션 헤드만 붙이는 방식은 실패한다. LLM·Speech Generator·Motion Generator를 함께 적응시켜야 한다. → 자체 구현보다 모델 공개를 기다려 채택하는 게 합리적. 모듈 조립으로는 안 된다.

🔴 hyperframes — 영상을 모델이 아니라 렌더러로 만든다

이 도메인의 소스는 지금까지 거의 전부 생성 모델이었다(Seedance·MiniMax-H3·Higgsfield). hyperframes 는 모델을 아예 쓰지 않는다 — HTML/CSS를 puppeteer로 프레임 렌더 → ffmpeg 인코딩. 결정론적이다.

생성 모델의 3대 고질병이 발생하지 않는다: ① 프레임 간 일관성 ② 텍스트 렌더링 붕괴 ③ 재현 불가능성. 대가: 실사·인물은 못 만든다. → 경쟁이 아니라 분업이다. 내 SaaS에서 “모델로 만들 것” 과 “렌더로 만들 것” 을 가르는 선이 여기서 명확해진다. 수치가 정확해야 하는 영상(리포트·대시보드·실적)이 생성 모델이 못 하는 빈틈이고, 이 층이 그걸 가져간다.

⚠️ 중복 검토 필요: 볼트 운영자는 이미 Remotion 기반 파이프라인을 운영 중이다(reat 스킬군). Remotion도 React를 프레임으로 렌더하므로 개념이 거의 같다. hyperframes는 보완재가 아니라 대체재이며, 갈아탈 이유는 (a) mcp 토픽 (b) React 비의존 정도다. 둘 다 미검증.

HeyGen 엔티티 신설 — 영상 AI SaaS 기업이 모델은 닫고 렌더 층을 Apache-2.0으로 전면 개방했다. Firecrawl(코어 AGPL·SDK MIT)·MiniMax(“오픈 가중치 ≠ 오픈 시스템”)에서 본 오픈코어 패턴의 변형이며, 여기선 층을 나눠 연다. 그리고 설명이 “Built for agents” 다 — 응용 SaaS 기업이 에이전트를 자사 사용자로 상정하기 시작했다.

🔴 Minimax-h3_Singularity — 지표 없이 데모만으로 5.8만 다운로드

MiniMax-H3 체크포인트 융합·프루닝 + ComfyUI 배포(T2V/I2V/Ref2V/V2V 4모드 주장). HDR 모션블러 개선을 주장하나 정량 지표 전무, 근거는 데모 링크(RunningHub/YouTube/Bilibili)뿐.

두 가지가 이 도메인에 남는다:

  1. 관측 대상은 모델이 아니라 시장 구조다. 벤치 없이 DL 5.8만이 나온다 — Huihui-Qwen3.8-27B-abliterated-GGUF(벤치 전무·DL 219만)와 같은 구조가 영상 도메인에서 재현됐다. 영상 품질은 정량화가 어렵고 데모는 체리피킹을 배제할 수 없어서, 이 도메인은 특히 이 구조에 취약하다.
  2. 배포 형식이 ComfyUI라는 것 — 크리에이터는 HF 카드가 아니라 노드를 소비한다. 논문/모델 카드만 보면 실제 유통 경로를 놓친다.

⚠️ 이 모델은 raw가 드리프트 가설의 근거로 쓴 건인데, 볼트 재측정에서 DL이 58,060에 고정되어 가설이 반증됐다. 상세는 Minimax-h3_Singularity 및 ai-news 09-08 절.

③ 납품 후에도 편집 가능한 워크벤치 CapCut 스타일 브라우저 편집기. 영상이 샷/트랜지션/자막/SFX 트랙으로 분해되어 스키마 기반 인스펙터로 카피·폰트·색 편집, 클립 이동·트림·속도램프, 라이브러리에서 모션 드래그 후 Remotion 렌더. → “생성으로 끝나지 않고 편집으로 넘긴다” 는 계약(references/workbench.md)이 별도 문서로 존재.
