핵심 인사이트 — 부정 결과를 먼저 말해서 설계 공간을 좁힌다

“for lossless coding a foundation model is worth nothing” — 절감 비트가 예측 정확도의 로그이기 때문이다: Δb = log₂(MAE_old / MAE_new). 그래서 TimesFM-3 이 32-tap 선형예측기 대비 가진 1.51배 우위가 20.28비트 중 0.60비트밖에 못 산다 → 중앙값 +0.03%. 탈출구는 한 지점뿐: 오차 허용(error-bounded) 구간. 예측이 허용대역 안에 들어오면 잔차 인덱스가 0이 되고 샘플이 사실상 공짜가 된다.

raw가 헤드라인 수치를 통째로 놓쳤다 — 이번 배치 raw 왜곡 패턴 ②

raw는 “xz/zstd 대비 9.7% 우위(15/15 전승)” 만 적었다. 그건 레인지 코더 vs 범용 압축기 비교일 뿐이고, 논문의 본 결과는 따로 있다:

  • EIA-930 수요 49계열(2026): 고전 예측기 6종 최고 대비 +13.3%
  • MTA 승객 50계열(2026): +28.3%
  • 297개 (계열×허용오차) 쌍에서 중앙값 +21.4%, 297/297 전승
  • 다운샘플링 대비(시계열 DB가 실제로 쓰는 보존 전략): 같은 크기에서 최악 오차가 28–56배 더 타이트 → raw는 또 부정·유보 문장만 남기고 정량 성과를 버렸다.

도메인별 추출 (ai-news)

  • 신뢰도: ⭐⭐⭐ — 업보트 8 · 2026-09-05 · 저자 1인(단독). 그러나 부정 결과 3건과 철회한 주장 8건을 전부 보고하고, 자기 주장을 반증하려는 시도까지 싣는다(SDRBench: 이론이 실패를 예측했고 실제로 중앙값 −0.8%, 27쌍 중 0쌍 개선). 저자 수는 적지만 방법론 정직성은 이 배치 최상위.
  • 즉시 활용: 직접은 NO(수요 시계열 압축 도구). 간접 YES — 아래 결정성 결과는 내 파이프라인에 바로 걸린다.
  • 6개월 영향력: “파운데이션 모델을 X에 붙이면 좋아진다” 류 주장에 로그 스케일 반론이라는 정량 기준을 제공. 압축뿐 아니라 예측 정확도를 비트/비용으로 환산해야 하는 모든 곳에 적용.
  • 대체 관계: 무손실 영역에서는 xz/zstd를 대체하지 못한다(저자 명시). 오차허용 영역에서만 대체.
  • 허와 실: 허가 없다. 오히려 이 논문의 형식(주장 → 반증 시도 → 실패 보고)이 본체다.

가장 실무적인 발견 — 파운데이션 모델은 비트 단위로 결정적이지 않다

“predictions are not bit-identical across batch sizes, and no PyTorch configuration repairs this” → 그래서 그룹 크기와 실행 디바이스를 컨테이너 포맷에 박아 넣어야 했다. 압축기는 복원 시 정확히 같은 예측이 필요하기 때문. 이건 압축만의 문제가 아니다. 모델 출력을 캐시·재현·검증하는 모든 파이프라인(내 볼트의 재측정 규칙 포함)이 같은 함정을 갖는다 — 배치 크기가 바뀌면 같은 입력이 같은 출력을 주지 않는다.

당장 할 것

결정성 결과만 따로 읽는다. 내 워크플로에서 모델 출력을 “같은 입력 → 같은 출력”으로 가정하는 지점이 있는지 점검 — 특히 배치 크기가 가변인 곳. 9월 배치에서 Minimax-h3_Singularity 재측정으로 배운 “수치는 관측 시각과 함께 기록” 규칙에 “실행 조건(배치·디바이스)도 함께” 를 추가할 근거.
