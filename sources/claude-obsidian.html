GitHub: https://github.com/AgriciDaniel/claude-obsidian 지표(2026-08-28): ⭐14,215 · 포크 1,432 · 이슈 140 · Python · MIT · 생성 2026-04-07 · 최종 푸시 2026-08-26 — GitHub API 실호출 검증(raw 표기 14,213 대비 +2 드리프트) · 트렌딩 데일리 14위(당일 +634) 자기 규정: “Self-organizing AI second brain for Obsidian + Claude Code … Based on Karpathy’s LLM Wiki pattern” (README description 원문)

핵심 인사이트 — 이 볼트의 직접 비교군이 처음으로 트렌딩에 등장했다

이 레포는 볼트에 흔한 “참고할 만한 도구”가 아니다. 이 볼트가 채택한 바로 그 패턴(LLM-Wiki · llm-wiki-karpathy-2026)을 레포로 패키징한 것이고, 스택까지 동일하다 — Obsidian + Claude Code + 순수 마크다운. 설계 주장도 이 볼트의 볼트 스키마(CLAUDE.md) 원칙과 겹친다: “임의의 소스를 투입하면(drop any source) 읽고 · 링크하고 · 정리한다”, “당신이 소유하는 하나의 연결된 순수 마크다운 지식그래프”. 그래서 이건 벤치마킹 대상이 아니라 대조군이다. 같은 패턴을 남이 구현했을 때 무엇이 자동화됐고 무엇이 여전히 사람/LLM 판단으로 남았는지가, 이 볼트의 인제스트 루프에서 자동화 가능한 부분의 상한을 알려준다.

이슈/포크 0.098 — 배치 내 상위 마찰 신호

이슈 140 / 포크 1,432 = 0.098건/포크. 이번 배치 5개 GitHub 레포 중 가장 높다:

  • claude-obsidian 0.098 · OpenMontage 0.038 · ponytail 0.028 · archify 0.031 · awesome-gpt-image-2 0.0072

볼트가 08-24~08-27에 정립한 규칙 — “이슈 밀도는 품질이 아니라 소프트웨어의 종류를 말한다” — 을 그대로 적용하면, 이 레포는 배치에서 가장 ‘실행되는 소프트웨어’에 가깝다. 프롬프트 템플릿 모음(awesome-gpt-image-2 0.0072)과 13.6배 차이다. 다만 방향은 미확정이다. 이슈가 많은 건 실제로 돌려보는 사람이 많다는 뜻일 수도, 정리 결과가 기대와 어긋난다는 뜻일 수도 있다. 이슈 내용은 미확인이다.

"정리 정확도"를 재는 수치가 없다 — 이 도구 부류의 공통 공백

레포는 얼마나 정확히 링크하고 분류하는지에 대한 수치를 제시하지 않는다. 지식그래프 도구의 핵심 실패 모드는 동작하지 않는 것이 아니라 그럴듯하게 잘못 연결하는 것인데, 그건 스타 수로는 절대 드러나지 않는다. 이 경고는 이번 배치의 PAWBench·FrontierChallenge 계보와 같은 지점을 겨눈다: 산출물이 존재한다 ≠ 산출물이 옳다.

도메인별 추출 (ai-news · 교차 local-llm)

  • 신뢰도: ⭐⭐⭐⭐ high — GitHub API 실검증 · MIT · 4개월 운영 · 당일에 가까운 푸시(08-26) · 스타 1.4만. 단 정리 품질 주장은 전량 미검증.
  • 즉시 활용: YES(조건부) — 이 볼트를 갈아엎는 용도가 아니라, 인제스트 루프의 자동화 격차를 진단하는 용도로 즉시 유용하다. 특히 확인할 것: (1) 소스 투입에서 페이지 생성까지 사람 개입 지점이 어디인가 (2) wikilink를 어떤 근거로 만드는가(문자열 매칭인가, 의미 판단인가) (3) 중복 페이지 판정을 어떻게 하는가 — 이 볼트가 매 인제스트마다 수동으로 하는 “신규냐 갱신이냐” 판정이 그 부분이다.
  • 6개월 영향력: 개인 지식베이스가 “내가 쓰는 관습” → “설치 가능한 레포” 로 옮겨가는 신호다. 에이전트-스킬 층위로 보면 이건 1층(자산)도 2층(방법론)도 아니고, 볼트 구조 자체를 규정하는 층이다.
  • 대체 관계: 이 볼트의 /wiki 스킬과 정면으로 겹친다. 대체가 아니라 차이 목록을 만들 대상이다 — 이 볼트에는 있고 저기 없는 것(도메인별 인사이트 템플릿·API 실검증 관행·> [!warning] 신뢰도 분리·raw 대기열), 저기 있고 여기 없는 것(무엇인지 확인 필요).
  • 허와 실: “self-organizing(자기조직화)“이 마케팅 어휘인지 실제 자동 루프인지가 갈림길이다. Claude Code가 매번 호출되는 구조라면 자기조직화가 아니라 그냥 위임이다 — 이 볼트와 동일한 구조가 된다.
  • 액션: 레포를 열어 링크 생성 로직과 중복 판정 로직만 읽는다(높음). 전체 도입은 하지 않는다.
