핵심 인사이트

VRAM·RAM·NVMe를 단일 메모리 계층으로 취급하고, MoE 전문가(expert)를 디스크에서 스트리밍해 744B2.8T 모델을 소비자 하드웨어에서 돌린다. 순수 C·의존성 0. 그런데 이 저장소의 진짜 판정 포인트는 성능이 아니다 — 저자가 “속도에는 SLA가 없다”고 먼저 선언하고, 대신 의미론(semantics)에만 하드 개런티를 건다. README 3538행 원문: “there is no SLA on speed, and a hard guarantee on semantics: … [no experiment] silently changes model precision or router semantics” → “빠르다”를 팔지 않고 “조용히 바꾸지 않는다”를 판다. 자기제한-명시 계보의 가장 선명한 사례.

"돌아간다" ≠ "쓸 만하다" — 저자 실측 4구간

README 322~327행 원문 수치. 같은 엔진인데 하드웨어에 따라 100배 이상 벌어진다:

  • 6× RTX 5090 풀 레지던시: 5.8~6.8 tok/s 디코드, TTFT ~13초
  • 128GB CPU 전용 데스크톱: ~1.8 tok/s (warm)
  • RTX 5070 Ti 랩탑급 1대: 1.07 tok/s
  • 25GB 개발 박스: 0.05~0.1 tok/s (콜드) — 저자가 “the proven floor” 라 부르는 하한 → 최상단(6×5090 ≈ 2천만원+)에서도 6.8 tok/s에 TTFT 13초다. “소비자 하드웨어에서 744B가 돌아간다”는 참이지만, 대화형으로 쓸 수 있다는 뜻은 아니다. → 대시보드 캡션(54행)의 “744B at 4 tok/s, TTFT 1.6s, disk 0” 는 디스크 접근이 0인 풀 레지던시 조건이다. 이 수치만 인용하면 안 된다.

구조 — 병목은 연산이 아니라 전문가 캐시 적중률

README 561행: “…touches 301 of them, so the expert cache hit rate is what sets tok/s” → MoE 추론에서 토큰당 활성 전문가는 일부이므로, 문제는 FLOPs가 아니라 어느 전문가가 어느 계층에 있느냐다. colibri는 이걸 스케줄링 문제로 재정의했다.

  • GLM-5.2(744B) int4 기준: 상주 9.9GB / 디스크 ~370GB
  • 미러 SSD는 시작 시 검증(파일 크기 + safetensors 헤더가 바이트 단위 동일해야 함), 불일치 파일은 조용히 주 디스크로 폴백 → 부분 미러도 유효(231행)
  • CUDA VRAM 전문가 계층 실측: 1.44 → 10.05 tok/s (7.0배), 8GB 카드 2장, 출력이 CPU 경로와 비트 단위 동일(414·437행) → 마지막 항목이 중요하다. 가속을 붙여도 출력이 바뀌지 않음을 비트 동일성으로 증명한다 = 위의 “의미론 개런티”를 실제로 검증 가능한 형태로 내놨다.

도메인별 추출 (local-llm)

  • 실용성 판단: 조건부. 배치·비대화형 워크로드(야간 일괄 요약·대량 분류)에는 지금 쓸 수 있다. 대화형은 불가 — 최상급 구성에서도 TTFT 13초. 내 환경(단일 소비자 GPU)이면 1 tok/s 내외를 각오해야 한다.
  • 메모리 아키텍처: 디스크를 메모리 계층에 편입하는 방식. RAG/KV압축과 다른 축 — 모델 가중치 자체를 스트리밍한다. DeepSeek-V4.1-Flash 가 KV 캐시를 줄인 것과 대비되는 짝: 저쪽은 컨텍스트 비용, 이쪽은 가중치 상주 비용을 공격한다.
  • Hermes 적용: 직접 적용은 부적합(지연). 다만 “양자화가 라우터 시맨틱을 조용히 바꾸지 않는다” 는 검증 방식은 이식 가능 — 내가 쓰는 양자화 모델이 비트 동일성 테스트를 통과하는지 확인하는 습관.
  • 트레이드오프: 속도 ↔ 모델 크기를 정면으로 교환한다. 744B를 1 tok/s로 돌지, 27B를 60 tok/s로 돌지의 선택. “큰 모델이 느리게”가 “작은 모델이 빠르게”보다 나은 과제가 무엇인지는 사용자가 판단해야 하며, 저자는 그 판단을 대신해주지 않는다.
  • 오픈소스 구현체: ⭐27,617(당일 +98) · fork 3,018 · Apache-2.0 · C · 2026-07-01 개설 · 8개 모델 패밀리를 각각 단일 C 파일로 지원.

당장 할 것

속도를 재지 말고 개런티를 재라. 내 하드웨어에서 tok/s를 재는 건 위 4구간으로 이미 예측된다(느리다). 대신 CUDA 전문가 계층 on/off 출력이 비트 동일한지 확인하는 것이 이 저장소에서 배울 값. 통과하면 “가속은 출력을 바꾸지 않는다”를 검증한 첫 로컬 스택이 된다.

미해결 질문

--ram 설정과 전문가 캐시 적중률의 관계가 README에 정성적으로만 있다. 적중률 x%일 때 tok/s가 얼마인가의 곡선이 없어서, 내 하드웨어에서의 성능을 사전에 계산할 수 없다. 결국 직접 돌려봐야 안다.
