핵심 인사이트 — 심판을 모델 밖에 두는 네 번째 사례

이 도구가 푸는 문제는 좁고 분명하다: 모델의 학습 시점 이후 API가 바뀌면 문법을 그럴듯하게 지어낸다. 해법도 좁다 — 라이브러리 문서를 버전별로 끌어와 프롬프트에 주입한다. 볼트가 추적해 온 축과 정확히 맞는다. EarlyEval의 LightGBM 채점, humanizer의 Wikipedia 유지보수 목록, Random-Attention의 “선택 신호를 아예 안 쓴다”에 이어 정답을 모델 바깥에 고정하는 네 번째 형태다. 여기서 외부 기준은 버전 태그가 붙은 공식 문서다. 검사가능성-공사의 급소(검사기가 피검사자와 같은 실패 모드를 공유하면 거울이다)를 이 설계는 구조적으로 회피한다 — 문서는 모델이 쓰지 않았다.

오픈이슈 70건 · fork/star 0.048 — 배치 최저 마찰

issue/star = 0.0011, 이 배치에서 가장 낮다(spec-kit 0.0024의 절반). MCP 서버라는 표면적이 작은 형태가 이 숫자의 가장 그럴듯한 설명이다. 하는 일이 하나뿐인 도구는 깨질 곳도 적다.

⚠️ 문서가 최신이라고 모델이 그것을 따른다는 보장은 없다

이 도구가 보장하는 것은 문서 주입까지다. 모델이 주입된 문서를 무시하고 학습된 옛 API를 쓰는 빈도에 대한 수치가 레포 메타데이터에 없다. 즉 “환각을 막는다” 는 메커니즘의 주장이지 측정된 효과가 아니다. 또한 버전 판별을 누가 하는가 — 프로젝트가 실제로 쓰는 버전과 주입된 버전이 어긋나면 틀린 문서를 확신 있게 주입하는, 더 나쁜 실패가 된다.

도메인별 추출 (ai-news)

  • 신뢰도: ⭐⭐⭐⭐ high — API 실측. Firecrawl과 유사한 인프라형 오픈코어 벤더(Upstash) 배경.
  • 즉시 활용: YES — 이 배치에서 가장 즉시적이다. MCP 서버이므로 Claude-Code-워크플로우에 설정 한 줄로 붙는다. 볼트가 겪는 실제 문제(라이브러리 API 변경으로 인한 환각)에 직접 대응.
  • 6개월 영향력: 높음. MCP가 도구 접속 규격으로 굳어지는 중이라, “문서 주입”이 에이전트 기본 구성요소가 될 가능성이 크다.
  • 대체 관계: 범용 웹검색 MCP를 부분 대체. 웹검색은 최신이지만 버전 정합성이 없고, 이쪽은 버전이 고정된다.
  • 허와 실: 실은 문제 정의의 정확성과 설치 용이성. 허는 효과 수치 부재.
  • 액션: 설치 후 1주 사용, 환각 발생 빈도 전후 비교(높음) — 이 배치 15건 중 가장 낮은 비용으로 가장 확실한 이득이 예상되는 항목.

미해결 질문

  • 커버하는 라이브러리 범위와 갱신 주기 — 미확인. 커버리지 밖 라이브러리에서는 아무 효과가 없다.
  • Upstash 호스팅 의존도 — 셀프호스팅 가능 여부 미확인. 불가하면 외부 서비스 종속이 붙는다.
