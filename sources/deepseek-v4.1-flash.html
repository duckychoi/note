🎯 09-11에 세운 가설의 판정 — 맞았다

09-11에 이 페이지가 적었다: “♥는 기대치, 다운로드는 실사용” 규칙은 **성숙한 모델에만 적용된다. 공개 당일 + 초대형 모델에는 무효.*” 당시: 다운로드 6 · ♥1,583 → 비율 0.004 : 1 3일 후: 다운로드 244,457 · ♥2,303 → 비율 106 : 1 다운로드가 40,743배 늘 때 ♥는 1.45배 늘었다.

✅ 가설이 예측한 그대로다. 공개 당일 숫자로 “관심만 있고 실사용이 없다” 고 읽었다면 3일 만에 완전히 틀렸을 것이다. ♥는 공개 즉시 포화하고 다운로드는 며칠 뒤에야 실체를 얻는다 — 두 지표의 시간 상수가 다르다. 📌 볼트 규칙으로 승격한다: 공개 후 72시간 이내의 다운로드 수는 지표가 아니다. ♥/다운로드 비율은 공개 +7일 이후에만 계산한다. → 측정도구-먼저-반증 🎯 같은 배치 MiniCPM5-2B 에서 독립적으로 같은 역전이 관측됐다(2.9:1 → 110:1). 두 사례가 서로를 확증한다 — 단발 우연이 아니다.

📌 raw가 새로 가져온 벤치 데이터 — 양축을 같은 불릿에 적었다(채택)

✅ 이기는 축: Terminal-Bench 2.1 90.6(Opus-5.0 89.1 · GPT-5.6 Sol 88.8) · DeepSWE v1.1 74.2(Opus 74.0) · CyberGym 88.1 · AutomationBench 54.8 · HLE w/ tools 63.9 · Codeforces 3471 🔴 지는 축 — 같은 표에 있다: Terminal-Bench 3.0 = 30.0 vs Opus-5.0 43.3 · 4.0 = 31.2 vs 51.8 · HLE(도구 없음) 36.8 vs 56.3 · ProgramBench 20.3 vs 37.0 · NL2Repo-Bench 64.0 vs 75.3 · ExploitGym 15.3 vs GPT-5.6 33.7 🎯 벤치 세대가 최신·고난도로 갈수록 격차가 벌어진다. 이는 09-11 페이지가 “TB 2.1 vs TB 4.0 붕괴 = 과제 성격 전환” 으로 해석한 것과 일치하며, 이번에 6개 축으로 확장 확인됐다. 🔴 모든 instruct 수치의 성립 조건: reasoning_effort=100(최대). 코드 에이전트 벤치는 DeepSeek 자체 하네스 Minimal 모드 + 1M 컨텍스트, 시각 에이전트 벤치는 Claude Code 하네스 + 512k. 하네스가 벤치마다 다르다 — 같은 표 안에서 측정 환경이 바뀐다. 구조 재확인: Causal Encoder-Decoder(CED) — 40층 = 인과 인코더 20 + 디코더 20, 디코더 전역 KV를 인코더 최종 은닉상태에서 투영. 552B에서 prefill 8B · decode 16B만 활성. KV 캐시 V4-Flash 대비 ~4배, V1 대비 437배 축소(Figure 1b). 컨텍스트 100만. 🔗 같은 배치 SAS 가 직교 축을 다룬다 — 이쪽은 “KV를 얼마나 작게 저장하나”, SAS는 “주어진 예산으로 무엇을 볼까”. 합성 가능하다.

핵심 인사이트 — 이 모델이 산 것은 능력이 아니라 입력 단가다

552B 백본 MoE · 최대 1M 토큰 컨텍스트 · 멀티모달(pipeline_tag: image-text-to-text, 자체 학습 DeepSeek-ViT 비전 인코더). 구조의 핵심은 두 가지 압축이다:

  • CED 구조(20층 인과 인코더 + 20층 디코더) → 프리필 시 토큰당 8B, 디코딩 시 16B만 활성화
  • CSA2(Full/Reindex/Reuse 3모드) + FP4 메인 KV 캐싱 → 글로벌 KV 캐시 토큰당 890바이트
    • DeepSeek-V4-Flash 대비 약 1/4, V1 대비 437배 축소
  • 45T 멀티모달 토큰 사전학습 · 추론 노력도를 1~100 정수로 연속 조절 → 🎯 컨텍스트가 길수록 KV 캐시가 비용을 지배한다. 890B/token이면 1M 컨텍스트에서 KV가 ~890MB — 이게 이 모델의 전체 논지다.

🔴 파라미터 수를 인용할 때 — 552B ≠ 763B

카드는 “552B 백본” 이라 쓰고, safetensors 실측 총 파라미터는 763,205,315,794(≈763B) 다. 볼트 API 실측으로 확인. 차이의 원인: Engram 조건부 메모리 196B가 별도 희소 접근 파라미터다. 552B + 196B ≈ 748B, 나머지는 비전·임베딩. → 백본 파라미터와 체크포인트 파라미터는 다른 수다. 어느 쪽을 쓰든 어느 쪽인지 밝혀야 한다. → 이 사례로 단위-불일치 개념을 신설했다(같은 배치 Nex-N2.5-Pro 의 공용 카드 건과 짝).

다운로드 6 — 숫자를 그대로 읽으면 틀린다

다운로드 6(2회 측정 동일)인데 ♥1,583, 트렌딩 1위다. 비율 0.004:1. 이유는 단순하다 — 업로드가 2026-09-10 02:17, 공개 당일이다. 그리고 763B 체크포인트를 받을 수 있는 사람이 거의 없다. → 볼트가 어제 정립한 “♥는 기대치, 다운로드는 실사용” 규칙(Qwopus3.8-27B-Flash-GGUF 644:1)은 성숙한 모델에만 적용된다. 공개 당일 + 초대형 모델에는 무효. → 🎯 지표의 적용 조건을 함께 기록하지 않으면 지표가 함정이 된다.

도메인별 추출 (local-llm)

  • 실용성 판단: 로컬 불가. 763B 체크포인트는 소비자 하드웨어 범위 밖이다. 같은 배치 colibri 의 전문가 스트리밍을 쓴다 해도 0.05~1 tok/s 구간. → API로 쓸 모델이지 로컬 모델이 아니다. 볼트 local-llm 분류는 아키텍처 학습 가치 때문에 유지.
  • 메모리 아키텍처: 이 모델의 전부다. CSA2 3모드 + FP4 KV → 890B/token. 에이전트-메모리-레이어 관점에서 “컨텍스트를 외부화하지 않고 압축해서 안에 두는” 노선의 현재 최전선. RAG와 정면으로 다른 답.
  • Hermes 적용: 직접 불가. 단 설계 원칙은 이식 가능 — 긴 입력을 다루는 에이전트에서 KV가 비용을 지배한다는 진단은 내 파이프라인에도 해당한다. 컨텍스트를 줄이는 대신 압축률 높은 백엔드를 고르는 판단 기준이 생긴다.
  • 트레이드오프: 명확하고 측정돼 있다 — KV 890B/token·활성 8~16B ↔ HLE −19.5 · TB4.0 −20.6. 압축이 공짜가 아니라는 것을 벤치가 보여준다.
  • 오픈소스 구현체: MIT · gated=False · HF 공개. 파라미터 정밀도 BF16/F32/F8_E4M3/I8 혼합.

당장 할 것

“KV 캐시 비용”을 내 판단 기준에 추가한다. 지금까지 모델을 고를 때 파라미터·벤치만 봤다. 긴 컨텍스트를 쓰는 워크로드(이 위키 인제스트 포함)에서는 토큰당 KV 바이트가 실질 비용을 결정한다. 쓰는 API의 이 수치를 확인할 것.

미해결 질문

Engram 조건부 메모리 196B의 작동 방식이 카드 수준에서 불명확하다. 희소 접근이면 접근 패턴에 따라 실효 지연이 달라질 텐데 그 수치가 없다. 그리고 TB 2.1(90.6) → TB 4.0(31.2)의 붕괴 원인이 컨텍스트 압축 때문인지 학습 데이터 시점 때문인지 카드로는 구분 불가.
