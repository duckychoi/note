FoMo — Forking Moment in Generative Trajectory as a Perceptual Distance (HF 2609.25716)

핵심 인사이트 — 생성 과정 자체를 자로 쓴다

참조 기반 화질평가(IQA)는 사람 라벨에 묶여 있다 — MOS 는 비싸고 노이즈가 크고, 2AFC 는 상대비교만 준다. 점별(pointwise) 절대 라벨을 싸게 얻을 방법이 없었다. FoMo 의 착상: 두 이미지가 확산모델 생성 궤적에서 갈라지는 시점(forking moment) 을 거리로 쓴다.

  • 일찍 갈라진다 → 거친 구조만 공유 → 지각적으로 멀다
  • 늦게 갈라진다 → 세부만 다르다 → 가깝다 이렇게 사람 주석 0으로 점별 라벨을 자동 생성한다. 🎯 주장 구조가 오늘 5건 중 가장 도발적이다 — “사람 라벨 없이 만든 라벨이 사람 라벨을 이긴다”. 여러 백본에서 사람 주석 데이터셋보다 높은 성능을 보고한다.

🔴 그 도발적 주장에 수치가 0개다

“multiple benchmarks” 가 어느 벤치인지 없고, 얼마나 이겼는지 없고, 어떤 백본들인지 없다. 주장의 크기와 증거의 크기가 가장 벌어진 건이 오늘은 이것이다.

🟡 순환 위험 — 볼트가 독립적으로 제기한다

평가 대상이 대부분 생성 이미지인데 거리 라벨도 확산모델에서 나온다. 같은 계열 모델의 편향이 라벨과 평가 양쪽에 동시에 들어갈 수 있다. 초록은 이를 다루지 않는다. 구체적 실패 시나리오: 라벨 생성에 쓴 확산모델 A 와 평가 대상 생성기 B 가 같은 사전학습을 공유하면, B 의 아티팩트를 A 가 “정상 궤적” 으로 보고 거리를 짧게 매길 수 있다 → B 가 부당하게 좋은 점수를 받는다. 📌 반증 방법이 명확하다: 라벨 생성 확산모델을 계열이 다른 것으로 바꿔 재실험했을 때 순위가 유지되는가. 본문에 ablation 이 있을 수 있다 — 초록만으로는 모른다.

도메인별 추출 (video-saas)

🔀 도메인 재판정 — 수집기 ai-news → 볼트 video-saas

화질을 사람 없이 자동 채점하는 것은 영상 SaaS 의 직접 수요다. 생성 결과물을 대량으로 뽑는 서비스는 어느 출력을 사용자에게 보일지 자동으로 골라야 하고, 그게 정확히 pointwise IQA 다. ai-news 보다 video-saas 가 실사용 접점에 가깝다.

  • 기능 벤치마킹: 🎯 “생성 N개 중 자동 선별” 기능에 직결된다. 영상/이미지 생성 SaaS 가 4개 후보를 뽑아 보여줄 때, 사람 라벨 없이 순위를 매길 수 있다면 UX가 바뀐다. 난이도: 확산모델 추론을 평가마다 돌려야 하므로 비용이 관건이다(초록에 비용 수치 없음).
  • 크리에이터 인사이트: 사용자는 “어느 게 더 나은지” 를 매번 눈으로 고른다. 그 노동을 줄이는 것이 갭이다.
  • 프롬프트 패턴: 해당 없음 — 평가 방법론이지 생성 방법론이 아니다.
  • 워크플로우: 생성 → 자동 점수 → 상위 k개만 노출. 🔴 지연시간이 미지수라 실시간 UI에 넣을 수 있는지 불명.
  • 디자인 레퍼런스: 해당 없음.
  • 경쟁 우위 빈틈: 🎯 참조 기반(reference-based) 이라는 점이 제약이자 기회다 — 원본이 있는 편집·업스케일·복원 워크플로에는 바로 쓰이고, 순수 t2i 에는 참조가 없어 못 쓴다.
