HarnessDev: Can LLMs Create and Evolve Their Own Agent Harness?

HF 논문: https://huggingface.co/papers/2609.01437 지표(2026-09-06 API 실측): 업보트 240 · 저자 19인 · 공개 2026-09-01 · 데일리 2026-09-03 raw 수집값(09-06): 업보트 240 — 일치(증가 0). 제1저자: Yuhao Wu · Jingyuan Zhang · Jiajun Shi 외 16인 자매 논문: Aspire (2608.31111) — 제1저자 3인 동일, 8일 먼저 공개

핵심 인사이트 — 평가 단위를 산출물에서 인프라로 옮겼다

전제가 명확하다: “모델 가중치를 고정한 채 하네스만 바꿔도 태스크 성능이 상당히 달라진다.” 그런데 현재 에이전트 평가는 선택된 하네스 아래의 다운스트림 성능을 보고할 뿐, 모델이 하네스 자체를 개발하는 능력은 거의 안 본다. HarnessDev는 평가 단위를 태스크 출력 → 실행 가능한 인프라로 옮긴다. 2단계:

  • Creation — 최소 시드 + 소수 케이스에서 시작해 완전한 실행 시스템을 짓는다
  • Evolution — 자기가 만든 하네스에서 출발해 다운스트림 실행 피드백으로 반복 개정

그리고 능력(홀드아웃 태스크 성공률) 과 효율(실행 토큰 비용) 을 함께 잰다 — 성능만 재면 비용으로 성능을 사는 하네스가 이긴다.

결과가 영역별로 갈린다 — 이 논문의 가장 중요한 발견

생성된 하네스는:

  • 코드 · 검색/리서치 → 성숙한 사람 제작 레퍼런스에 크게 못 미친다
  • 글쓰기 · ML 실험 → 대등하거나 상회한다
  • 실행 비용은 편차가 크다

이 분열이 말하는 바가 있다. 사람이 오래 다듬은 레퍼런스가 존재하는 영역에서는 진다. 코드·검색은 도구 생태계가 성숙해 있고, 글쓰기·ML 실험은 상대적으로 표준 하네스가 약하다. 즉 LLM이 하네스를 잘 만드는 게 아니라, 사람이 안 만든 곳에서만 이긴다.

⚠️ Evolution이 불안정하고, 하네스 개선이 모델을 건너가지 못한다

초록이 스스로 두 겹의 한계를 적는다:

  1. “Evolution은 일부 성능 향상을 내지만 불안정하고 홀드아웃 태스크로 부분적으로만 전이된다.”
  2. 고정 런타임 모델 실험에서, 이득이 하네스를 실행하는 모델에 강하게 의존 — 모델 간 전이가 제한적이다.

두 번째가 특히 무겁다. 하네스는 모델 외부 인프라이므로 재사용 가능한 자산일 것 같지만, 실제로는 특정 모델에 맞춰 과적합된다. 볼트의 에이전트-스킬 자산 전체에 걸리는 경고다 — 스킬·하네스는 모델을 바꾸면 다시 검증해야 한다. ⚠️ 이건 LatentPress의 “reader-matched” 문제와 같은 형태다: 외부에 두었지만 실제로는 특정 디코더/모델에 결박된다. 같은 배치에서 두 소스가 독립적으로 같은 결박을 보고했다.

규모: 창작자 LLM 6종 · 4개 도메인 · 다운스트림 5개 벤치 2,207 인스턴스 · 히든 평가 태스크 분리

히든 태스크 분리는 Aspire와 공유하는 설계다. 개발 중 볼 수 없는 평가를 두어 자기평가 과적합을 차단한다 — 검사가능성-공사의 급소(검사기가 피검사자와 같은 실패 모드를 공유하면 거울이다)에 대한 구조적 방어.

도메인별 추출 (ai-news)

  • 신뢰도: ⭐⭐⭐ medium — HF API 실검증(업보트 240·저자 19인·날짜). 히든 평가 분리·능력/효율 이중 측정으로 설계 품질은 이 배치 상위. 제3자 재현은 없음.
  • 즉시 활용: 개념 YES. 벤치마크 자체는 못 돌리지만 판단 기준은 즉시 쓴다 — 볼트가 하네스/스킬 자산을 평가할 때 ①홀드아웃 성공률 ②실행 토큰 비용 ③모델 간 전이 세 축을 요구한다.
  • 6개월 영향력: 높음. “에이전트 성능” 을 모델 능력으로 귀속시키던 관행에 제동. Repo-To-Skill(스킬 층 통제 실험)에 이어 하네스 층도 실험 대상이 됐다.
  • 대체 관계: 기존 에이전트 벤치를 대체하지 않고 직교 축을 추가한다.
  • 허와 실: 실은 분열된 결과를 그대로 보고했다는 점(글쓰기·ML에서 이긴 것만 팔지 않았다). 허는 없음에 가깝다 — 오히려 자기 한계를 초록에 두 개 적은 드문 논문.
  • 액션: 에이전트-스킬에 “모델 간 전이 검증” 요구 항목 추가(높음). 볼트 스킬 자산이 모델 교체 시 재검증 대상임을 명시.

미해결 질문

  • “성숙한 사람 제작 레퍼런스”가 구체적으로 무엇인가 — 코드 영역 비교 대상이 무엇이냐에 따라 “크게 못 미친다”의 의미가 달라진다.
  • 모델 간 전이 실패의 원인 — 하네스가 모델의 특정 실패 모드에 맞춰졌기 때문인가, 프롬프트 형식 종속인가.
  • 효율(실행 토큰 비용) 편차의 범위 — “크다”만 있고 수치가 초록 범위 밖.
