JIT-Agent — 하네스를 사람이 짜지 않고 모델이 뽑는다

HF 논문: https://huggingface.co/papers/2608.25593 코드: https://github.com/bingreeky/JIT (raw 기재) 지표(2026-08-27): 업보트 39 · HF 데일리 5위 · 저자 16인 · 공개 2026-08-26 — HF API 실호출 + 초록 원문 대조(raw 표기 38 → API 39) 형식화: 하네스 = 고정 4모듈 프로토콜을 따르는 합성 가능·기계 생성 가능한 산출물 4모듈: 메모리 관리 · 계획 전략 · 행동 프로토콜 · 툴/스킬 오케스트레이션

핵심 인사이트 — "하네스 지능"을 모델 스케일링과 직교하는 축으로 선언

이 논문의 주장은 두 단계다. (1) 에이전트 능력은 모델만으로 결정되지 않으며, 하네스가 기반 모델의 기여를 압도할 수 있다. (2) 그런데 하네스 설계는 수작업·태스크 특화·본질적으로 확장 불가다 — 그래서 하네스를 만드는 모델을 학습시킨다. 결론 문장이 이 논문의 야심을 요약한다: 하네스 지능은 학습 가능(trainable)·이전 가능(transferable)·누적적(compounding) 이며 모델 스케일링과 직교(orthogonal) 하는 능력 차원이다. 이건 위키에 쌓인 에이전트-스킬 4층 구조에서 4층(진화)을 모델화한 첫 사례다.

위키 계보 안에서의 정확한 위치 — 오프라인 패치의 온라인·생성형 대응물

하네스 개선 축에 이미 세 사례가 있다. JIT-Agent는 네 번째이자 가장 상위 층이다.

  • AutoSaddler — 설계시점 하네스 코드 패치 (오프라인·수정형)
  • Recuris — 실행시점 메모리 진화 (온라인·부분 갱신)
  • SkillEvo — 멀티턴 피드백 기반 스킬 자가갱신
  • JIT-Agent — 즉석(just-in-time) 하네스 전체를 생성·수리·자가진화 ← 패치가 아니라 생성

앞의 셋이 기존 하네스를 고치는 방식이라면 JIT-Agent는 태스크마다 하네스를 새로 뽑는다. 그리고 이전 하네스 구성의 아카이브에서 성능 신호를 증류해 자가진화한다 — 누적성(compounding)의 근거가 여기다.

가장 도발적인 주장 — 생성 하네스가 성숙 런타임과 대등

JIT-Agent가 생성한 하네스가 OpenCode·anthropic-claude-code 같은 성숙 런타임과 성능상 경쟁력 있다고 주장한다. 사람이 오래 다듬은 런타임을 기계 생성물이 따라잡는다는 뜻이라 검증 부담이 큰 주장이다. 수치: DeepSeek-V4-Flash가 DeepSearchQA +9.1 · OdysseyBench +4.3 으로 GPT-5.6을 추월, 이미 강한 GLM-5.2는 최대 +20.2점 상승. 추가로 DeepSeek V4 · Mimo-V2.5 · Qwen3.6 다중 규모 모델 계열 전반에서 일관 개선(초록 명시 — raw 한줄요약에는 누락된 부분).

미확인 사항 — "경쟁력"의 판정 기준이 없다

  • 절대 점수 전면 미기재 — 전부 상대 증분(+9.1·+4.3·+20.2). 기준선이 없어 개선의 실질 크기를 알 수 없다
  • “성숙 런타임과 경쟁력 있다”의 판정 기준·비교 조건 미기재 — 이 논문에서 가장 큰 주장인데 근거 서술이 가장 얇다
  • 하네스 생성 비용 미기재 — 태스크마다 하네스를 뽑는다면 생성 자체의 시간·토큰 비용이 실용성을 좌우하는데 초록에 없다
  • 고정 4모듈 프로토콜이 표현할 수 있는 하네스의 범위(표현력 한계) 미논의
  • arXiv ID 2608.25593는 미래형 ID, 초록은 HF API 원문 대조

미해결 질문

FrontierChallenge가 같은 날 스캐폴드 3종을 바꿔도 Pass Rate 20.6%가 천장이었다고 보고했다. JIT-Agent는 하네스를 바꾸면 크게 오른다고 주장한다. 두 결과는 직접 모순은 아니지만(태스크·측정이 다름) 함께 읽으면 질문이 생긴다 — 하네스 개선은 어디까지 올리고 어디서 멈추는가? 하네스가 지배하는 구간과 모델 능력이 천장을 만드는 구간의 경계가 이 축의 다음 쟁점이다.

도메인별 추출 (ai-news)

  • 신뢰도: ⭐⭐⭐ (데일리 5위·업보트 39·저자 16인·초록 원문 대조·코드 레포 존재). 단 절대값 부재로 주장 크기 검증은 불가 — 지표 신뢰도는 high, 주장 신뢰도는 medium.
  • 즉시 활용: NO(직접) / YES(개념) — 모델 학습은 못 하지만 “하네스를 4모듈로 분해해 명시적으로 관리한다” 는 프레임은 지금 쓸 수 있다. 내 스킬들(위키·영상 파이프라인)을 메모리/계획/행동/오케스트레이션 4칸으로 점검하면 빠진 칸이 보인다.
  • 6개월 영향력: 큼. 스킬·플러그인 생태계가 “사람이 쓴 자산”에서 “모델이 뽑는 산출물” 로 넘어가는 분기점 주장. 실현되면 mattpocock-skills류 큐레이션 자산의 가치 근거가 바뀐다.
  • 대체 관계: 성숙 런타임(OpenCode·Claude Code)을 대체 주장하나 검증 미흡. 현실적으로는 보완(런타임 위에서 태스크별 구성을 뽑는 층).
  • 허와 실: 마케팅 걷어내면 = 하네스 구성을 출력하도록 학습된 모델 + 구성 아카이브 증류. “최초의 하네스 생성 전용 모델”이라는 자평은 그럴듯하나, 비용·판정 기준 부재가 실용성 판단을 막는다.
  • 액션: 내 에이전트 스킬 3~4개를 4모듈 프로토콜로 분해 점검 — 특히 “행동 프로토콜”과 “메모리 관리”가 암묵적으로만 존재하는 스킬을 찾아 명시화.
