llm_wiki

핵심 인사이트 — 이 저장소는 이 볼트가 하는 일을 제품으로 만든 것이다

PDF·오피스·EPUB·이미지를 2단계 CoT로 인제스트해 출처 추적 가능한 entity/concept 페이지를 생성하고, 페이지 간 관계를 가중 신호로 계산한다. LLM-Wiki 패턴의 두 번째 본격 구현체(claude-obsidian 다음). 🪞 그런데 이 소스의 진짜 값은 기능 목록이 아니라, 이 볼트에 없는 것을 정확히 짚어준다는 점이다.

🪞 볼트 자기점검 — llm_wiki에는 있고 여기에는 없는 것

README 146~170행이 제시하는 4-신호 관련성 모델(가중치 원문):

  • 직접 링크 · 출처 중첩 · Adamic-Adar ×1.5(공통 이웃을 이웃의 차수로 가중) · 타입 친화도 ×1.0(entity↔entity, concept↔concept 보너스)

그리고 결정적으로 Louvain 커뮤니티 탐지 + 응집도 점수화(162~170행): “each community scored by intra-edge density (actual edges / possible edges); low-cohesion clusters (< 0.15) flagged with warning”

→ 이 볼트는 소스 1,001개를 쌓는 동안 링크 구조를 한 번도 정량 측정한 적이 없다. grep과 [[wikilink]] 로 “연결됐다/안 됐다”만 봤다. 응집도·차수 가중·클러스터 자동 발견은 전부 없다. → 검사가능성-공사 가 말한 “검사기가 피검사자와 같은 실패 모드를 공유하면 계기판이 아니라 거울이다” 의 실물이다. 내 lint는 고아 페이지만 센다 — 그건 차수 0만 잡고 차수 1짜리 죽은 클러스터는 못 잡는다. → 게다가 llm_wiki는 cross-community edge·cross-type link·주변↔허브 결합을 “예상 밖 관계”로 따로 탐지한다(181행). 볼트가 synthesis/ 를 2건밖에 못 만든 이유가 여기 있다 — 교차 연결을 찾는 절차가 없어서 사람이 눈으로 볼 때만 생긴다.

구조

  • 2단계 CoT 인제스트 — 원문 → 구조화 → 페이지. entity/concept 페이지에 sources[] 배열 유지
  • 삭제 안전성(343행): 소스를 지워도 여러 소스에 걸린 entity/concept는 sources[] 에서 해당 항목만 제거하고 페이지 자체는 남긴다 → 볼트의 raw.md 항목 삭제 정책과 같은 사상, 다만 자동화돼 있다
  • Rust 백엔드 챗 에이전트 + 로컬 SKILL.md 스킬(48행) — /skill 로 선택, 에이전트가 필요 시 읽는다. 에이전트-스킬 규약을 지식베이스 앱이 채택한 사례
  • dataVersion 신호로 그래프·UI 자동 갱신(377행)

🔴 라이선스 정정 — NOASSERTION 이지만 실제는 GPL-3.0

GitHub API license.spdx_id = NOASSERTION. 그러나 LICENSE 원문(35,195바이트) 직접 확인 결과:

1행: LLM Wiki — Copyright (C) 2024-2026 Yong Su
3행:                     GNU GENERAL PUBLIC LICENSE
4행:                        Version 3, 29 June 2007

→ GPL-3.0 전문이 그대로 들어 있다. 자동탐지가 실패한 원인은 어제 teamai-cli 와 완전히 동일 — 전문 앞에 저작권 1줄이 붙어 정규식이 깨졌다. → 파생표기-함정 규칙이 이틀 연속 적중. 그리고 함의가 다르다: GPL-3.0이면 이 코드를 참고해 내 도구를 만들 때 전염성 조항이 걸린다. NOASSERTION 을 “라이선스 불명”으로 넘겼으면 이 판단을 못 했다.

  • 즉시 활용: YES — 단 앱이 아니라 알고리즘을. 데스크톱 앱을 설치해 볼트를 이관할 이유는 없다(내 볼트는 이미 Obsidian 포맷이고 에이전트가 직접 쓴다). 그러나 4-신호 관련성 모델과 Louvain 응집도 점수는 지금 이 볼트에 스크립트로 이식 가능하다. 입력([[링크]] 그래프)이 이미 있다.
  • 6개월 영향력: LLM-Wiki 패턴이 “프롬프트 규약 → 패키지 → 완제품 앱” 3단계를 다 채웠다. 남은 차별점은 무엇을 넣느냐(소스 선별)와 무엇을 묻느냐(쿼리)뿐 — 둘 다 이 볼트가 약한 지점이다(queries/ 0건).
  • 대체 관계: claude-obsidian 과 같은 층. 다만 저쪽은 Claude Code 스킬 패키지, 이쪽은 자체 그래프 엔진을 가진 독립 앱. 그래프 분석은 llm_wiki 우위.
  • 허와 실: “자동으로 조직화된다”는 문구는 마케팅이지만, 응집도 <0.15 경고처럼 실패를 표면화하는 장치를 넣은 건 마케팅이 아니다. 자기 산출물을 의심하는 기능은 팔기 어렵기 때문이다.

당장 할 것 — 볼트 lint 업그레이드

현재 lint(고아 페이지 카운트)를 차수 분포 + 커뮤니티 응집도로 교체한다. 필요한 건 외부 앱이 아니라 스크립트 1개:

  1. 전 페이지 [[링크]] 인접행렬 추출 (이미 grep -roh 로 하고 있음)
  2. Adamic-Adar 로 “연결됐어야 하는데 안 된 쌍” 상위 20개 출력 → synthesis/ 후보
  3. 커뮤니티별 intra-edge density 계산, <0.15 경고 → 죽은 클러스터 탐지 → 이게 검사가능성-공사 가 요구한 “외부 정답 고정”의 6번째 형태 = 자기 그래프의 정량 지표다. 1,001개 소스는 이미 있다. 측정만 없다.

미해결 질문

4-신호 가중치(Adamic-Adar ×1.5, 타입 친화도 ×1.0)의 근거가 README에 없다. 튜닝 결과인지 임의값인지 불명 — 이식할 때 가중치를 그대로 베끼면 안 되고 내 그래프에서 재조정해야 한다.
