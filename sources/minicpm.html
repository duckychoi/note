MiniCPM (레포)

핵심 인사이트 — 이 레포는 모델이 아니라 배포 허브다. 따라서 ★11,078은 어느 모델의 지표도 아니다

레포 하나가 4개 모델 계열을 담는다: MiniCPM5-2B · MiniCPM5-1B · MiniCPM-SALA · MiniCPM4/4.1. 🎯 그래서 “★11,078” 을 어느 모델에도 귀속시킬 수 없다. 스타는 허브에 달렸고 모델은 4개다. 📌 README 1,373행 · 마크다운 표 19개 · ### Evaluation Results 섹션 4개(169·457·678·868행) — 각 섹션은 서로 다른 모델 소유다. 표를 인용할 때 어느 섹션에서 왔는지 밝히지 않으면 표-부분인용 이 아니라 귀속 오류가 된다.

⚖️ 판정 요청 3에 답한다 — (c)다. 그리고 이건 파생저장소-식별 이 아니라 새 유형이다

수집기 질문: (a) MiniCPM5-2B 부분은 중복 처리하고 신규분만 허브 페이지로 / (b) 전건 중복 기각 / (c) 레포 페이지를 따로 두고 모델 페이지와 상호링크

답: (c). 근거는 볼트가 09-17에 세운 기준을 그대로 적용한 것이다.

파생저장소-식별 의 판정 절차: “새 축이 문서화됐으면 (b)독립채택 · 파일만 있으면 (c)병합 · 순수 재포장이면 (a)중복”. MiniCPM-SALA·MiniCPM4 는 새 축이 문서화됐다 — 아키텍처(희소+선형 하이브리드 비율), 수치(3.5배·2.5배·38.97·81.6), 성립조건(하드웨어·베이스라인)까지 본문에 있다. 파일만 있는 Comfy-Org-YuE2 사례와 결정적으로 다르다. → 독립 페이지 성립. 🔴 그러나 레포 페이지를 두는 이유는 “신규분이 있어서”가 아니다 — 단위가 다르기 때문이다.

🆕 이건 파생 중복이 아니라 컨테이너 중복이다 → 컨테이너-중복 신설

09-17 파생 중복:  원본 1 → 파생 N   (같은 지식, 다른 이름)  → base_model 로 잡는다
09-18 컨테이너:   레포 1 ⊃ 모델 N   (한 이름, 여러 지식)    → 🔴 잡을 키가 없다

🎯 org/name 리터럴 필터는 여기서 올바르게 통과시켰다. github.com/OpenBMB/MiniCPM 은 레포로서 실제로 미수집이었다 — 필터가 틀린 게 아니라, 수집 단위(레포)와 지식 단위(모델)가 1:1이 아니다. 🔴 그리고 base_model 3차 키도 여기서는 무력하다 — GitHub 레포에는 cardData.base_model 이 없다. 09-17에 세운 2·3차 키가 채널을 넘으면 적용되지 않는다. 📌 볼트 판정: 교차유형 중복은 필터로 못 잡는다. 자진신고가 유일한 탐지 경로다. → ✅ 그리고 수집기가 실제로 자진신고했다. 이번 배치에서 가장 잘한 일이다.

🔴 중복분은 여기에 옮기지 않는다 — 볼트가 더 많이 갖고 있다

수집기가 이번에 옮긴 평균 53.9 · 4B급 51.1 은 볼트 보유분의 부분집합이다. MiniCPM5-2B 페이지는 이미 갖고 있다: 4B급 5종 개별값(51.1·42.7·32.6·31.2·28.4) · SWE-bench V 46.4 · SWE-bench Pro 14.4 vs 28.2 · IFEval 86.7 vs 93.4 · NoLiMa 68.1 · 벤더측정/제3자측정(†) 구분. 🎯 그러므로 이 페이지는 그 수치를 재서술하지 않는다. 재서술하면 같은 사실이 두 곳에서 갈라질 위험만 생긴다. → MiniCPM5-2B 를 보라. 이것이 (c) 채택의 실질 내용이다: 상호링크는 장식이 아니라 중복 서술 금지 규약이다. 📌 볼트 규칙 신설: 컨테이너 페이지는 이미 개별 페이지가 있는 구성원의 수치를 복제하지 않는다. 구성원 목록 + 링크 + 컨테이너 고유 사실(여기서는 표 19개·섹션 4개·귀속 구조)만 적는다.

✅ 실제 신규분 — MiniCPM-SALA (2026-02)

희소 25% + 선형 75% — 비율이 설계의 전부다

층의 25% InfLLM-V2(희소 어텐션) + 75% Lightning Attention(선형 어텐션). 🎯 풀 어텐션 층이 0이다. 수치 전건(텍스트에 존재하는 것만):

  • A6000D 256K 길이에서 Qwen3-8B 대비 추론 속도 최대 3.5배 · TTFT 최대 2.5배
  • 장문 평균 38.97 — RULER·NoLiMa에서 128K까지 전 구간 최고
  • 🎯 520K까지만 학습했는데 2048K에서 81.6 유지 — YaRN 등 보조기법 없이. 저자 추정 원인: 희소층 NoPE 구성
  • Transformer→하이브리드 전환 학습으로 총 학습예산을 처음부터 학습 대비 약 25% 로 축소

🔴 3.5배·2.5배의 성립 조건 — 일부는 실패 대비 성공이다

비교는 Qwen3-8B 단일 베이스라인이고 하드웨어가 A6000D·RTX 5090 고정이다. 🔴 결정적 한정어: “Qwen3-8B fails at this length due to out-of-memory” — 실패 대비 성공은 배수로 환산되지 않는다. 256K에서 상대가 OOM이면 “3.5배 빠르다”가 아니라 “상대는 못 한다”다. 두 진술은 다른 종류이고, 후자를 배수로 적으면 단위-불일치 다. → 🎯 그리고 이 구조가 DeepSeek-V4.1-Flash 와 정확히 같은 축이다 — 양쪽 다 “긴 컨텍스트에서 메모리가 비용을 지배한다” 는 진단에서 출발하고, 답이 갈린다: V4.1-Flash는 KV를 압축(890B/token), SALA는 어텐션 자체를 희소·선형으로 교체. 저장을 줄이나 vs 계산을 줄이나 — 직교하므로 합성 가능하다. 🔴 이미지 안의 수치는 옮기지 못했다: SALA의 효율·장문·초장문 평가가 전부 PNG(inference_speed_a600d.png 등)다. ✅ 수집기가 09-17 볼트 지적을 반영해 .svg/.png 를 구분했고, 이번엔 실제로 래스터라 못 읽는 게 맞다 — 자산 확장자 확인 후 못 읽는다고 적은 것은 올바른 처리다. → 메타데이터-부재-추론

📌 MiniCPM4/4.1 — 이름만 확인됐다

리터럴 grep 0히트로 신규 확인. 🔴 그러나 볼트도 수집기도 이 계열의 수치를 하나도 갖고 있지 않다. README 4개 평가 섹션 중 어느 것이 4/4.1 소유인지 귀속 미확인. → 다음 배치 필수 확인 항목.

도메인별 추출 (local-llm)

  • 실용성 판단: 🎯 SALA가 배치에서 가장 실용적이다. A6000D·RTX 5090 수치가 명시돼 있고 소비자·준전문가 하드웨어 대역이다(DeepSeek-V4.1-Flash 의 763B는 범위 밖이었다). 단 SALA 체크포인트 자체의 크기·공개 여부를 볼트가 확인하지 않았다.
  • 메모리 아키텍처: 희소+선형 하이브리드 — RAG도 KV압축도 아닌 제3노선. 에이전트-메모리-레이어 분류에 “어텐션 구조 자체를 바꾼다” 칸이 필요하다. 🎯 2048K에서 81.6은 외부화 없이 도달한 값이다.
  • Hermes 적용: 🔴 직접 불가(체크포인트 미확인·추론 스택 미확인). 단 판단 기준은 얻는다 — 긴 입력을 다룰 때 “풀 어텐션 층이 몇 개인가” 가 지연시간을 지배한다.
  • 트레이드오프: ✅ 측정돼 있다 — 학습예산 25% + 속도 3.5배 ↔ 🔴 품질 비용이 명시되지 않았다. 장문 평균 38.97이 최고라지만 단문·지식 벤치에서 무엇을 잃었는지 텍스트에 없다(PNG 안일 가능성). 희소화가 공짜일 수 없다 → 에이전트축-분기 가 예측하는 형태의 손실이 어딘가 있어야 한다.
  • 오픈소스 구현체: Apache-2.0 · OpenBMB. 레포 자체는 즉시 사용 가능.

당장 할 것

SALA 체크포인트가 HF에 공개됐는지 확인한다. 공개됐으면 2048K 컨텍스트를 준전문가 하드웨어에서 쓸 수 있다는 뜻이고, 이건 내 긴-컨텍스트 워크로드(이 위키 인제스트 포함)에 직접 해당한다. → 확인 후 actionable 승격 판단.

미해결 질문

① SALA의 품질 비용이 어디에 있는가 — 장문에서 최고인 모델이 단문에서 무엇을 내줬는지 텍스트에 없다. PNG 안이면 볼트도 못 읽는다. ② MiniCPM4/4.1 수치 전부 미확인 — 4개 평가 섹션의 귀속을 풀지 않았다. ③ 희소층 NoPE 가 2048K 외삽의 원인이라는 것은 저자 추정이다(“저자 추정” 이라고 카드가 밝혔다). 검증된 인과가 아니다.
