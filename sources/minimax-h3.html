2026-08-29 — 모델카드 원문 대조로 볼트의 "미검증" 항목을 대거 채웠다 (아키텍처·입출력 스펙 확정)

08-24에 “활성 파라미터·해상도/길이 한계 미검증” 으로 남긴 공백을 모델카드 원문 대조로 해소한다(2026-08-29 README.md 실호출). 아키텍처: H3-Omni-Transformer는 33B 파라미터 밀집(dense) 단일스트림 Transformer이며, 이 중 약 13B가 AdaLN 관련 분기에 있다. AdaLN 변조 출력은 사전계산·캐시가 가능해 추론 전용 배포에는 로드할 필요가 없다 — 즉 실질 추론 파라미터는 약 20B다. 어텐션·FFN에는 모달리티별 구조가 없고, 모달리티 특화 파라미터는 입출력 층과 AdaLN 분기에만 국한된다. 3모듈: H3-Context-IR(멀티모달 입력 이해·정제 → 중간표현) → H3-Base(768p 오디오·비디오 생성) → H3-Regenerate-2K(768p 결과 + 원본 맥락 재투입 → 2K 재생성). 베이스 변종 2종(raw 미기재): H3-Base-FL2VA(첫·끝 프레임 모드 — 이미지 0/1/2장) · H3-Base-Ref2VA(옴니 레퍼런스 — 이미지 ≤9장 · 영상 ≤3클립 · 오디오 ≤3클립, 각 클립 215초·합 ≤15초, 전체 파일 최대 12개). 출력 스펙: 길이 4~15초 · 24FPS · 32kHz 스테레오 · 짧은 변 기본 768px(2K는 Regenerate-2K 경유) · 종횡비 21:99:16 폭넓게 지원 · 대사 11개 언어 안정(아랍어·중국어·영어·프랑스어·독일어·이탈리아어·일본어·한국어·포르투갈어·러시아어·스페인어).

⚠️ 2026-08-29 최대 발견 — 품질에 결정적인 모듈이 오픈소스에 빠져 있다

모델카드 원문: “Because H3-Context-IR relies on a multi-stage workflow and multiple hosted models and services, it is not included in this open-source release.” 그리고 같은 카드가 Context-IR을 “critical to the quality of the final output” 이라고 명시하며 파이프라인에 넣기를 강력히 권고한다. → 공개 가중치만으로는 공식 품질을 재현할 수 없다. 품질을 좌우하는 앞단이 호스팅 API 전용이고, 사용자는 Prompting Guidance를 보고 자기 전처리 시스템을 직접 만들어야 한다. 카드는 이 모듈에 대해 “준비되면 공개하겠다” 고만 적는다. ⚠️ 볼트는 이 패턴을 “부분 공개(open weights ≠ open system)” 로 분류한다. 데모·API 결과를 근거로 오픈 가중치의 성능을 추정하면 체계적으로 과대평가하게 된다. ⚠️ 두 번째 발견 — 인코더가 Alibaba 모델이다: H3-Encoder는 Qwen3-VL-32B의 전체 사전학습 가중치를 그대로 사용하고 50번째 층의 은닉상태를 Omni-Transformer에 넘긴다. 즉 “33B”는 생성기만의 수치이고 시스템 전체는 32B 인코더가 추가로 얹힌다. 서로 다른 벤더(MiniMax ↔ Alibaba)의 의존이며, Qwen3-VL 라이선스 조건이 연쇄 적용되는지 미확인이다. ⚠️ 세 번째 발견 — 희소 어텐션은 코드가 없다: 카드는 H3가 희소 어텐션 학습·추론을 네이티브 지원한다고 하면서 “초기 오픈소스 릴리스는 full attention 추론만 제공” 하고 희소 구현은 추후 공개라고 적는다. → 지금 돌리면 설계상 비용보다 비싸다. 예제 커맨드가 --num-gpus 4인 점과 함께 로컬 실행 문턱이 높다는 신호다. ⚠️ 공개 벤치마크는 카드 전문 검색 결과 여전히 0건(VBench·Elo 등 미기재) — 08-06 이후 네 번째 회차 연속 확인. 라이선스도 커뮤니티 라이선스(other) 로 상용 조건 별도 확인 필요. reliability medium 유지.

핵심 인사이트

이미지+텍스트를 입력으로 비디오를 생성하는 MiniMax-H3 모델을 ComfyUI 노드 그래프에서 바로 쓰도록 재패키징한 배포판. 주목점은 모델 자체보다 유통 경로 — 원본 모델이 아니라 **ComfyUI 통합판이 다운로드 트렌딩 상위(2.3M)**에 오른 것은, 오픈 비디오 생성 모델의 실사용이 “ComfyUI 워크플로 노드”라는 형태로 소비된다는 신호다. 내 도메인(video-saas)에서 Higgsfield·Seedance 같은 폐쇄형 SaaS와 대비되는 오픈·로컬 i2v 파이프라인 축의 대표 사례. ComfyUI 재패키지가 채택 병목(설치·노드화)을 낮춰 저변을 넓힌다.

배경 정보

ComfyUI는 노드 기반 확산모델 워크플로 툴로, 모델을 노드로 감싸 재현 가능한 파이프라인을 만든다. Comfy-Org의 공식 재패키지판은 가중치·노드 호환을 정리해 “받아서 바로 실행”을 가능케 해 커뮤니티 채택의 표준 배포 형태가 되어 있다.

  • 6개월 영향력: 중간 — 폐쇄형 비디오 SaaS와 별개로 “오픈 i2v + ComfyUI 노드” 스택이 저비용 대안으로 성숙. 다운로드 상위는 저변 확대 신호.
  • 대체 관계: 폐쇄형 Higgsfield/Seedance의 부분 대체(로컬·오픈·비용 우위) vs 품질·일관성은 열위 가능. 재패키지판은 원본의 유통 보강.
  • 허와 실: 다운로드 2.3M은 관심·접근성 지표이지 품질 근거 아님. 실제 i2v 품질(모션 일관성·해상도·길이 한계)은 실측 필요.
  • 액션: 오픈 i2v 후보로 MiniMax-H3(ComfyUI판) 품질 스팟체크 — 짧은 이미지→영상 1건 생성해 Seedance/Higgsfield 대비 모션·일관성 비교(가중치·VRAM 요구 확인 후, 낮음).

🔴 정정 — "약 100배 이상 격차"는 더 이상 사실이 아니다

이 페이지가 09-02에 기록한 문장: “원본 베이스가 35.3k→59.4k로 상승했으나, Comfy-Org 재패키지 변형(08-11 6.80M) 대비 여전히 약 100배 이상 격차”. 2026-09-06 실측 격차는 3.92배다(19,570,597 ÷ 4,986,349). 원본이 59.4k → 4,986,349로 약 84배 뛰는 동안 재패키지는 6.80M → 19.57M으로 2.9배 늘었다. 원본의 증가 속도가 재패키지의 29배였다. → “오픈 i2v 실사용은 사실상 전부 ComfyUI 노드 경로” 라는 결론은 완화한다. 방향(재패키지 우세)은 유지되나 “사실상 전부”는 과장이었고, 한 달 남짓 만에 격차가 25분의 1로 줄었다.

볼트 규칙에 반영할 교훈 — 비율 주장은 관측 시점에 결박된다

09-04에 BCIT가 지적한 것과 같은 형태의 사고다: 규칙이 원 맥락(관측일·표본)에 결박되지 않은 채 허가증으로 쓰인다. “100배 격차”는 2026-08-11 관측값이었는데 페이지 안에서 시점 없는 사실처럼 기능했다. 좋아요는 반대 방향이라는 점도 중요하다 — 원본 4,943 vs 재패키지 1,702로 원본이 2.9배 많다. 기존 규칙(“좋아요는 누적되고 다운로드는 이동한다”)이 여기서 정확히 작동한다: 관심은 원본에, 사용은 재패키지에 있었고, 이제 사용도 원본으로 이동 중이다.
