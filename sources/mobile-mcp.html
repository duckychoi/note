핵심 인사이트 — 스크린샷을 폴백으로 내린 것이 이 레포의 논지다

에뮬레이터·시뮬레이터·실기기(iOS/안드로이드)를 플랫폼 무관 단일 도구셋으로 구동하는 MCP 서버. 그런데 기능 목록보다 중요한 것은 경로 우선순위다: 네이티브 접근성 트리를 먼저 읽고, 스크린샷+좌표 탭은 폴백으로만 쓴다. 🎯 이 선택이 세 가지를 동시에 해결한다 — ① 비전 모델·이미지 토큰 불필요 → 비용 감소 ② 좌표 대신 구조화된 UI 요소 → 모호성 감소 ③ 요소에 이름·역할이 붙어 있어 → 에이전트 추론이 짧아진다. 📌 이것은 에이전트-웹접근 에서 볼트가 이미 만난 축과 같은 축의 모바일판이다: “픽셀을 볼 것인가 구조를 읽을 것인가.” 웹에서는 DOM/접근성 트리 대 스크린샷이었고, 여기서는 네이티브 접근성 트리 대 스크린샷이다. 두 플랫폼에서 같은 답이 나왔다 — 구조가 먼저다. GitHub description 실측: “Model Context Protocol Server for Mobile Automation and Scraping (iOS, Android, Emulators, Simulators and Real Devices)” — Scraping 을 자기 용도로 명시한다.

기능 표면 — 제어 항목

탭·스와이프·제스처 · 앱 설치·실행·종료 · 화면 녹화 · 하드웨어 버튼 · 딥링크 · 화면 회전. 호환 클라이언트로 Claude Code · Codex · Gemini · Copilot · Antigravity 를 명시한다 — 🎯 사용자 본인 하니스(Claude Code)가 첫 번째로 적혀 있다. 배포: npm @mobilenext/mobile-mcp — 설치가 1줄이다.

당장 할 것 — 이 배치에서 설치 문턱이 가장 낮다

npm i -g @mobilenext/mobile-mcp 1줄 + MCP 설정 1블록이면 붙는다. 🔴 그런데 볼트는 09-24 agent-browser(동일하게 npm i -g 1줄)를 ★최우선으로 등록하고 3일째 실행하지 않았다. 같은 형태의 항목을 또 쌓는 것은 의미가 없다 → 📌 판단: 이 항목은 actionable 에 추가하지 않는다. agent-browser 를 먼저 실행하거나 그 항목을 폐기하는 것이 순서다. 실행 안 할 항목을 늘리는 것은 목록의 신호를 죽인다 — 09-20 검사가능성-공사 actionable 이 8일째 대기인 것에서 이미 배웠다. ⚠️ 단 실기기 자동화는 비가역 부작용이 있다(앱 설치·삭제·설정 변경). 붙일 때 에뮬레이터부터.
