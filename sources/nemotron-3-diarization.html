NVIDIA Nemotron-3-Diarization — 최대 8화자 스트리밍 화자분할

HF: https://huggingface.co/nvidia/Nemotron-3-Diarization 지표(수집 2026-10-02 09:01:53 UTC / 볼트 실측 동일자): DL30 40,936(완전 일치) · DL누적 40,936(완전 일치) · ♥609(완전 일치) · trendingScore 279(수집기 280 → −1) · createdAt 2026-09-01 · lastModified 2026-09-24 · 다운로드 랭크 7위 파라미터: safetensors.total 99,226,504 (수집기와 완전 일치) · 🆕 gguf.total 99,260,363(볼트 추가 확인) 라이선스: 🆕 cardData.license = openmdw-1.1(볼트 추가 확인 — 수집기는 “상업 사용 가능” 만 적고 라이선스명을 적지 않았다) 볼트 지위: 🆕 신규 — 정규명 재검사에서도 Nemotron-3-Diarization·Sortformer·화자분할 전부 0회

⚖️ 도메인 재판정 — 수집기 ai-news → 볼트 local-llm

근거 3개. ① 99M 파라미터 — 볼트가 수집한 모델 중 손꼽히게 작다. ② 입력 버퍼 지연 0.32초 로 스트리밍 — 온디바이스 실시간 영역이다. ③ 상업 사용 가능. local-llm 태그에 edge-ai·on-device 가 명시돼 있고, 이 모델은 그 정의에 오늘 배치에서 가장 정확히 들어맞는 유일한 항목이다. 🎯 그리고 이것이 오늘 유일한 음성/오디오 축이다 — 볼트 수집 이력에서 음성은 희소하다.

⚠️ 형제 페이지와 병합 금지

볼트에 Nemotron-3-Nano-Omni(30B-A3B 멀티모달 옴니)가 있다. 같은 Nemotron 3 패밀리의 전혀 다른 모델이다 — 이쪽은 99M 단일 과제(화자분할), 그쪽은 30B 옴니. 파라미터가 약 300배 차이난다. 📌 동일대상-분리오판 의 거울상(거짓 병합) 위험이고, 오늘 배치에 같은 위험이 하나 더 있다 — Qwen-Image-2.1-Uncensored-GGUF(이미지) vs Qwen3.8-27B-Uncensored-GGUF(텍스트)가 “Uncensored-GGUF” 부분 문자열로 겹친다. ⚖️ 오늘 배치는 거짓 병합 위험이 2건이다. 둘 다 분리 유지.

🏆 핵심 인사이트 — 순열 문제를 아키텍처로 없앴다

화자분할의 고전적 난점은 출력 채널 ↔ 실제 화자 대응이 임의라는 것이다(permutation problem). 보통 학습 시 PIT(permutation-invariant training)로 우회한다. Sortformer 계열의 해법은 다르다 — 출력 채널을 화자의 첫 등장 순서로 정렬해 문제를 아예 정의에서 제거한다. 🎯 스트리밍에서 이 정렬을 유지하는 장치가 AOSC(도착순 화자 캐시) + FIFO 큐다. 청크가 바뀌어도 “2번 채널은 계속 그 사람”이 유지된다. 📌 암묵을-명시로 의 또 다른 형태 — “누가 1번인가” 를 암묵적 매칭에 맡기지 않고 등장 순서라는 명시적 규칙으로 고정한다. 단일 체크포인트로 지연 0.32s ~ 30.4s 전구간 커버 — 지연별로 모델을 따로 받지 않는다. 청크 추론 시 최대 오디오 길이 제한 없음. 구조: 31층 트랜스포머 + RoPE · 10ms Mel 입력을 8배 다운샘플(80ms 프레임) 한 뒤 Conv1D 로 10ms 해상도 복원. 🎯 즉 연산은 거친 해상도에서, 출력은 고운 해상도로 — 99M 으로 8화자를 하는 비용 구조가 여기에 있다.

🎯 화자 수가 늘 때 격차가 벌어지는 패턴이 일관된다 — DIHARD 5~9화자에서 27.58 vs 40.21(격차 12.63) vs full 에서 12.73 vs 19.09(격차 6.36). 베이스라인이 4spk 로 4화자 설계였으므로 예상되는 방향이고, 수치가 그 설계 한계와 정합한다.

🏆 모델카드가 자기 채점표를 먼저 변호했다 — 측정도구-먼저-반증 의 벤더 자발적 실행

AMI · AliMeeting · NOTSOFAR1 에 강제정렬(forced alignment) 참조 라벨을 쓴 이유를 카드가 직접 적었다:

“원 주석은 전사 목적이라 구간 내 긴 침묵을 발화로 라벨해 참조 화자 활동을 과대추정하고, DER 채점 시 올바른 비발화 예측을 미검출 오류로 처벌한다” 그리고 다른 참조 라벨로 얻은 결과는 직접 비교 불가임을 명시하고 참조 RTTM 공개 링크까지 제공했다. 📌 이것이 왜 강한 신호인가 — 벤더가 자기 수치를 유리하게 보이게 하는 선택(참조 라벨 교체)을 하면서, 그 선택이 비교 가능성을 깨뜨린다는 사실을 스스로 적었다. 숨기면 아무도 몰랐을 것이다. 🎯 오늘 두 번째 사례다 — UniMate README 가 “많은 스켈레톤이 여전히 실패” + “손실 스파이크는 불량 데이터의 증상” 을 적었다. ⚖️ 같은 날 두 벤더가 자발적으로 한계를 공개한 것은 기록할 만하다(10-01 배치에서는 VoiceStudio 처럼 극성 반전을 볼트가 적발해야 했다).

🎯 지표-창길이 — 경계 사례인데 설명이 붙어 있다. 그리고 규칙이 정교해졌다

✅ 볼트 실측으로 확인: downloads(30일) 40,936 == downloadsAllTime 40,936, createdAt 2026-09-01 ⇒ 나이 31일 > 30일. 🔴 10-01 에 굳힌 규칙대로면 여기서 두 값이 불일치해야 한다(“나이 30일 초과 → 창 밖 일자 존재 → 감소/불일치”). 일치했다. ✅ 수집기가 원인을 제시했고 카드에서 확인된다 — 카드의 Release Date 가 2026-09-23 이다. 레포 생성(09-01)과 공개(09-23) 사이 22일간 다운로드가 ~0 이었으므로, 나이가 30일을 넘겨도 창 밖에 실제 다운로드가 없어 두 값이 일치한다. ⚖️ 규칙 정교화(오늘 발효): “createdAt 나이 30일 초과”는 불일치의 필요조건이지 충분조건이 아니다. 판정 기준은 나이가 아니라 창 밖 구간에 실제 다운로드가 있었는지이고, 그것을 가르는 것은 createdAt 이 아니라 공개일(Release Date) 이다. 🎯 이로써 이 개념의 변수가 3개로 분해됐다: createdAt(레포 생성) · Release Date(실제 공개) · 조회 시점. 10-01 까지 볼트는 첫째와 셋째만 보고 있었다. 🆕 오늘 추가 관측 — trendingScore 는 감쇠한다: HF 모델 3건 전부 하락했다(이 모델 280→279 · Qwen-Image-2.1-Uncensored-GGUF 774→771 · Qwen-Image-2.1 418→416). DL 은 단조 증가/창 효과, trendingScore 는 감쇠 ⇒ “드리프트 0 = 검증 통과” 논리를 trendingScore 에 적용하면 안 된다. 3/3 하락은 우연으로 보기 어렵다.

도메인별 추출 (local-llm)

  • 실용성 판단: 🟢 오늘 배치에서 가장 실배포에 가깝다. 99M 은 CPU 추론 가능 크기이고, 지연 0.32s 는 실시간 회의·통화 처리 영역이다. 단일 체크포인트로 지연 전구간 커버 ⇒ 배포 구성이 단순하다. 상업 사용 가능. 🔴 하드웨어별 RTFx 수치가 없어 “어떤 CPU 에서 몇 배속”을 말할 수 없다.
  • 메모리 아키텍처: 🎯 직접 해당 없으나 구조가 유사하다 — AOSC(도착순 화자 캐시) + FIFO 큐는 청크 경계를 넘어 정체성을 유지하는 상태 저장소다. 에이전트-메모리-레이어 의 KV 계열과 형태가 비슷하고, 용량이 화자 수(최대 8)로 유한하다는 점이 특징이다.
  • Hermes 적용: 🟡 조건부 — 음성 입력 경로가 생기면 즉시. 현재 볼트·ChinameBot 은 텍스트 기반이라 지금은 NO. 🔴 한국어 지원이 확인되기 전까지는 조건부도 성립하지 않는다 — 이것을 선행 확인 항목으로 actionable 등록한다.
  • 트레이드오프: ✅ 오늘 배치 중 유일하게 정량 트레이드오프가 완비됐다 — 지연 0.32s → 30.4s 구간에서 DIHARD full DER 13.55 → 12.73. 📌 즉 지연을 95배 늘려 얻는 정확도 개선이 0.82 DER 포인트다. 🎯 이 비율이 채택 판단의 핵심이다: 실시간을 택하는 비용이 매우 싸다.
  • 오픈소스 구현체: ✅ HF 공개 가중치 실재(DL 40,936 볼트 실측) · NVIDIA 1차 벤더 · NeMo 생태계. 🔴 추론 코드 직접 실행 0건.
