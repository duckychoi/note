핵심 인사이트 — 교육 AI의 단위가 콘텐츠에서 참여자로 바뀐다

기존 AI 교육 도구의 산출물은 자료였다 — 슬라이드, 퀴즈, 요약본. 사람이 그것을 읽는다. OpenMAIC의 산출물은 교실이라는 실행 중인 장면이다: AI 교사가 강의하고, AI 동료 학습자가 먼저 질문을 던지고, 화이트보드에 수식이 실시간으로 써지고, 학습자가 지목당한다. 결정적 설계는 AI 동료(AI classmates) 다. 교사 에이전트만 두면 그것은 더 나은 강의 영상에 불과하다. 동료 에이전트를 넣는 순간 “질문하지 않아도 대화가 굴러가는” 상태가 만들어진다 — 온라인 학습 이탈의 주원인이 막혔을 때 물어볼 사람이 없음이라는 점을 겨냥한 구조적 대응이다. MOOC의 실패를 콘텐츠 품질이 아니라 사회적 맥락의 부재로 진단한 것. 즉 이 레포는 교육 콘텐츠 생성기가 아니라 다중 에이전트 상호작용의 응용 시연장이다. 같은 구조는 회의·상담·훈련 시뮬레이션으로 그대로 이식된다.

이번 배치에서 유일하게 동료심사를 통과한 GitHub 레포

볼트가 반복 기록해 온 패턴은 “레포 설명의 성능·효과 주장은 거의 전량 자체 서술” 이었다(archify의 “verifiable”, scientific-agent-skills의 “190,000+ 과학자”, OpenMontage의 “World’s first”). OpenMAIC는 그 계열에서 벗어난다 — JCST(Journal of Computer Science and Technology) 2026 게재 논문이 붙어 있고 DOI가 실재한다. 단 논문이 검증하는 것은 MAIC 개념 프레임이지 이 레포 v1.0.0의 학습 효과가 아니다. 논문 존재는 연구 계보의 신뢰도를 올리지만 제품 효과의 증거로 승격시키면 안 된다. 볼트는 이 둘을 분리해 기록한다.

저자진이 THUNLP 핵심 — OpenBMB와 같은 계보

저자 23인에 Zhi-Yuan Liu(刘知远)·Mao-Song Sun(孙茂松)·Juan-Zi Li(李涓子) 가 포함된다. 이들은 칭화대 THUNLP를 이끌며 OpenBMB(MiniCPM 계열)의 모체이기도 하다. 볼트에 이미 OpenBMB 엔티티가 있으므로 같은 연구 그룹의 다른 출력물로 연결한다. 이는 신뢰도 판단에 실질적으로 작동한다: 이 그룹은 레포를 띄우고 방치하는 패턴이 아니라 장기 유지보수 이력을 가진다. 실제로 최종 푸시가 당일(08-30)이고 v1.0.0이 사흘 전(08-27) 릴리스됐다.

오픈이슈 210건 — 이 규모에서 높다. 그리고 학습 효과 수치는 레포에 없다

포크 4,371 대비 이슈 210 = 0.0480건/포크. 08-29~08-30 배치 비교군에서 상위권이다(scientific-agent-skills 0.0042 · archify 0.0325 · OpenMontage 0.0486 · OpenMAIC 0.0480 · claude-plugins-official 0.2667). OpenMontage와 거의 동률로, 둘 다 “실행되는 소프트웨어” 라는 공통점이 있다 — 실행체는 자산(스킬 목록·인덱스)보다 이슈가 많이 난다는 볼트의 기존 관찰과 정합적이다. ⚠️ 레포에 학습 성과 측정치가 제시되지 않는다. “몰입형 학습 경험”은 경험 주장이지 성과 주장이 아니다. AI 동료가 실제로 완주율·이해도를 올리는지는 레포 근거로는 판단 불가이며, JCST 논문 본문 확인이 필요하다(미확인). ⚠️ 사이즈 약 148MB로 무겁고, LLM API 키 · 선택적 PostgreSQL · TTS · 렌더 서비스 등 부속 구성요소가 많다 — “원클릭”은 데모 기준이고 자체 호스팅은 원클릭이 아니다.

스킬 생태계의 소비자이자 공급자라는 이중 위치

OpenMAIC는 내부적으로 내장 스킬 20개(슬라이드·퀴즈·인터랙티브·PBL·이미지·영상·음성·.pptx 임포트)를 굴리는 동시에, 외부에는 ClawHub에 설치 가능한 하나의 스킬로 노출된다(clawhub install openmaic). 채팅앱에서 “양자역학 가르쳐줘” 라고 하면 교실이 생성된다. 에이전트-스킬 층위 모델로 보면 이것은 1층(자산)도 3층(레지스트리)도 아닌 새 칸이다 — 스킬로 포장된 애플리케이션. archify가 출력 형식을 규정하고 OpenMontage가 제작 지식을 번들했다면, OpenMAIC는 완제품 서비스 자체를 스킬 인터페이스 뒤에 숨긴다. 스킬이 프롬프트 묶음에서 서비스 호출 규약으로 넘어가는 사례다. 로컬 제공자(Lemonade)·로컬 STT(FunASR)·자체호스팅 TTS(VoxCPM2)를 옵션으로 두어 완전 로컬 구성 경로를 남긴 점도 기록해 둔다 — local-llm 도메인과의 교차점.

도메인별 추출 (ai-news)

  • 신뢰도: ⭐⭐⭐⭐ high — ⭐22,701 · MIT · 당일 푸시 · 동료심사 논문 실재(DOI 확인) · GitHub API 실호출 검증. 단 학습 효과 정량치는 레포 미제시로 제품 효과는 미검증.
  • 즉시 활용: 부분 YES — 교육 목적이 아니라 다중 에이전트 상호작용 구현 레퍼런스로서 값이 있다. 특히 페르소나가 다른 에이전트들이 사람 없이도 대화를 진전시키는 오케스트레이션과 실시간 화이트보드 공동 편집은 그대로 참고 대상이다. TypeScript/Next.js 스택이라 코드 열람 비용도 낮다.
  • 6개월 영향력: 중간~큼. “AI가 자료를 만들어 준다” → “AI가 상대역을 맡는다” 로 옮겨가는 흐름의 대표 사례. 이 축이 서면 튜터링·면접 연습·상담·롤플레이 훈련이 전부 같은 템플릿을 쓴다.
  • 대체 관계: 슬라이드 생성기(Gamma류)를 부분 대체하되, 산출물이 .pptx/.html로 나오므로 기존 파이프라인과 충돌하지 않는다. LMS를 대체하지 않는다(성적·이수 관리 없음).
  • 허와 실: 마케팅 걷어내면 = LLM 오케스트레이션 + TTS + 화이트보드 렌더링을 교실 메타포로 묶은 Next.js 앱. “원클릭”은 호스팅 데모 한정. 진짜 자산은 AI 동료라는 역할 설계이며 이건 모델이 아니라 프롬프트·상호작용 설계의 성과다.
  • 액션: 라이브 데모(open.maic.chat)에서 1개 주제로 교실을 생성해 AI 동료의 발화가 실제로 학습을 밀어붙이는지 vs 분위기만 채우는지 스팟체크(중간 우선순위). 코드에서는 다중 에이전트 턴 관리 로직만 발췌 열람.
