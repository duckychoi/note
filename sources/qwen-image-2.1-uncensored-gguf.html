HF: https://huggingface.co/abenzerps/Qwen-Image-2.1-Uncensored-GGUF 지표(수집 2026-10-02 09:01:53 UTC / 볼트 실측 동일자): DL30 1,303,476(완전 일치) · DL누적 1,303,476(완전 일치) · ♥2,746(수집기 2,745 → +1) · trendingScore 771(수집기 774 → −3) · createdAt 2026-09-20 · lastModified 2026-09-28 · 다운로드 랭크 4위 라이선스: license = other · license_name = qwen-research(✅ 수집기 일치) · license_link = None 볼트 지위: 🆕 독립 페이지 신설 — 기존에는 Qwen-Image-2.1 내부 파생 항목으로만 존재했다(아래 참조)

🔴 이 페이지가 존재하는 이유는 중복검사 실패다 — 정규명-우선-중복검사 가 경고한 바로 그 형태

수집기 1차 검사는 이것을 “볼트 언급 0회 → 신규” 로 적었고, 스스로 정정했다. 정정 근거: 이 레포는 Qwen-Image-2.1 페이지 안에 파생으로 수록돼 있었다(index.md 370·394행 abenzerps/…UC-GGUF), 그리고 actionable.md 410행에도 기록돼 있었다. 🔴 그러나 “갱신”으로 처리하는 것도 정확하지 않다 — 독립 페이지가 없는 것이 문제의 원인이었다. ⚖️ 볼트 판정: 파생을 베이스 페이지 안에 묻어 두는 관행 자체가 탐지 실패를 만든다. DL 1,303,476 은 오늘 HF 랭크 4위이고 베이스의 16.9배다. 그 규모의 대상이 다른 페이지의 한 줄로 존재하면, 어떤 검사 경로로도 안정적으로 잡히지 않는다. ⇒ ✅ 독립 페이지로 승격한다. 이것이 이 배치에서 볼트가 내리는 구조적 조치다. 🎯 같은 실패가 두 축에서 반복됐다:

시점실패 형태결과

📌 두 번 다 “대상이 없다”가 아니라 “내 조회 방식이 못 찾았다”였다 → 무응답-오귀속 과 같은 뿌리. ⚖️ 중복검사 4경로 규칙(① 슬래시 ② 하이픈 정규명 ③ 소유자명 단독 ④ actionable.md 포함)이 수집기 쪽에 추가됐고, 볼트는 여기에 ⑤ “베이스 페이지 본문 내 파생 표기” 를 더한다.

🏆 볼트 자체 발견 — 수집기의 "파라미터 API 대조 불가"는 틀렸다

수집기 기록: “safetensors.total 이 None(GGUF 레포라 파라미터 API 대조 불가)” ✅ safetensors.total 이 None 인 것은 사실이다. 그러나 결론이 틀렸다.

abenzerps/Qwen-Image-2.1-Uncensored-GGUF
  safetensors.total = None
  gguf.total        = 7,115,124,736   ← 여기 있다

Qwen/Qwen-Image-2.1 (베이스)
  safetensors.total = 7,115,124,736   ← 자릿수까지 완전 일치

🏆 파생의 gguf.total 이 베이스의 safetensors.total 과 완전히 같다. 즉 대조는 가능했고, 결과는 일치였다. 양자화가 파라미터 수를 보존한다는 것이 두 레포의 서로 다른 필드를 통해 교차 확인됐다. ⇒ ⚖️ 개념 신설: 대체필드-대조 — 한 필드가 None 이면 “대조 불가”가 아니다. 같은 양을 담는 다른 필드를 찾는다. 포맷이 다르면 필드 이름이 다를 뿐 양은 남아 있다. 📌 이것은 무응답-오귀속 의 세 번째 하위유형이다:

유형원인사례
누락형필요한 파라미터를 안 보냄09-30 expand[]=downloadsAllTime
무효형오타 파라미터로 요청 전체 거부10-01 expand[]=license
대체필드형맞는 필드를 안 봄(요청은 정상)오늘 gguf.total
🎯 셋의 공통점: 응답은 정상이었다. 가장 발견하기 어려운 유형이 이것이다 — 에러도 없고 빈 값도 아니고, 그냥 다른 칸에 들어 있다.
⚠️ 단 일반화하지 않는다 — 같은 날 Nemotron-3-Diarization 은 safetensors.total 99,226,504 vs gguf.total 99,260,363 으로 0.034% 불일치했다. ⇒ 두 필드가 항상 같지는 않다. 대조는 가능하지만 일치를 전제할 수는 없다.

🎯 원본-파생-역전 — 배수의 시계열이 3점으로 확보됐다

관측베이스 DL이 파생 DL배수
볼트 1차28,407350,67812.3배
볼트 2차42,469715,90616.9배
오늘(실측)76,9381,303,47616.9배
✅ 볼트 독립 계산: 1,303,476 / 76,938 = 16.936 → 소수 첫째 자리 16.9배.
🎯 배수가 2회 연속 안정됐다 — 원본과 파생이 거의 같은 비율로 커졌다(베이스 +81% · 파생 +82%, 2차→오늘). 📌 즉 역전은 일시적 유행이 아니라 구조적 격차다. 양자화 수요가 베이스 수요에 비례해 따라오는 것이 아니라, 처음부터 다른 규모의 모집단(ComfyUI 로컬 사용자)이 존재한다.
⚠️ 09-27 Qwen-Image-2.1-viggle-turbo(오늘 217,638)까지 합치면 같은 베이스의 파생 2종이 베이스를 각각 16.9배·2.8배 앞선다.
✅ 배수 규약(09-28 개정)이 여기서 유효하게 작동했다 — 소수 첫째 자리까지만 적기로 한 덕분에 16.9 → 16.9 “안정” 이라는 판독이 나왔다. 더 적었으면 12.34 → 16.9 → 16.94 로 계속 변하는 것처럼 보였다.

✅ 파생저장소-식별 — 선언 관계가 가장 강한 형태로 확보됐다

📌 태그 파싱 추론이 아니라 HF 의 구조화된 선언이다. 09-30 동일대상-분리오판 은 이 1회 조회로 처음부터 막을 수 있었다 — 볼트가 10-01 에 이미 적은 교훈이고, 오늘 같은 필드가 또 결정적이었다(위 gguf.total 발견도 같은 호출에서 나왔다). 🎯 재현 경로가 문자로 고정돼 있다: 소스 리비전 b3179ad355be050328e483a9dfdd9e60cd62adfa · 변환 도구 stable-diffusion.cpp 커밋 1330cebae8f2ba99249df846cc0c9444fcbd4308 · SHA256SUMS 제공. ⚖️ 볼트 수집 이력에서 재현 경로가 이 정도로 명시된 파생 레포는 드물다 — 신뢰도 가산. 🔴 단 license_link 가 None 이다 — 베이스는 LICENSE 링크를 제공하는데 파생은 license_name 만 선언하고 파일을 동봉하지 않았다. 메타데이터-부재-추론 경계 사례(라이선스명은 있고 본문은 없다).

📌 내용물 — ComfyUI 단독 구동이 설계 목표다

Qwen/Qwen-Image-2.1 상류 가중치를 BF16 14.23GB ~ Q4_0 4.15GB 범위로 양자화한 12종 파일(GGUF·FP8·INT8 ConvRot·NVFP4·MLX 4/6/8bit). 권장 Q4_K_M(4.60GB). 🎯 핵심은 동봉 구성이다 — 텍스트 인코더(qwen3vl_8b)와 VAE 까지 같은 레포에 넣어 ComfyUI 단독 구동을 가능케 한다. 📌 DL 1,303,476 의 상당 부분이 “모델 1개”가 아니라 “작동하는 세트”에 대한 수요로 보인다 — 베이스 레포만으로는 ComfyUI 에서 바로 돌지 않는다. ✅ 카드가 제시하는 VRAM 절감 구성: 디퓨전은 VRAM, 텍스트 인코더는 시스템 RAM 오프로드 — 프롬프트당 1회만 돌아 9~17GB VRAM 절감, 속도 영향 미미. 🎯 이것이 이 레포에서 가장 실용적인 정보다(수치가 붙은 유일한 운영 지침).
