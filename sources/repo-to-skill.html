Repo-To-Skill: Distilling GitHub Repositories Into AI4AI Skills

HF 논문: https://huggingface.co/papers/2609.02749 지표(2026-09-03): 업보트 334 · HF 데일리 1위 · 저자 11인 · 공개 2026-09-02 — HF api/papers 실호출 검증(raw 표기와 완전 일치) 제1저자: Jianlyu Chen · Yuyang Hu · Hongjin Qian · Jiawei Liu 외 7인

핵심 인사이트 — 스킬이 "쓰는 것"에서 "증류하는 것"으로 넘어갔다

이 논문의 주장은 에이전트 아키텍처에 빠진 층이 하나 있다는 것이다. 저자들은 그것을 운영지식(operational knowledge) 이라 부르고 이렇게 정의한다 — “방법을 아는 것과 그것을 작동시키는 것을 가르는 노하우”(the know-how that separates knowing a method from making it work). 핵심은 이 지식이 없는 게 아니라 잘못된 형태로 있다는 진단이다: 레포와 논문 안에 사람이 읽도록 쓰여 있고, 한 태스크에 로드하기엔 너무 크다. 그래서 매 실행마다 재발견된다. 해법이 DisCo(스킬을 만들고 쓰는 연구 에이전트)이고, 증류를 두 방향으로 돌린다:

  • 태스크 비의존 증류 → 생태계 전체에 적용 → AREX-Skill Library: 널리 쓰이는 ML 레포 1,000개 → 검증된 스킬 5,000+개, 20개 영역·178개 역량군으로 조직
  • 태스크 지향 증류 → 지금 이 과제가 요구하는 스킬을 그 자리에서 생성

통제 설계가 이 논문의 진짜 기여다

초록이 명시적으로 적는다 — GPT-5.5 백본, 연구 하네스, 다운스트림 실행 예산을 전부 고정(held fixed) 한 채 스킬 유무만 바꿨다. 그 결과:

  • MLE-bench +134.3%
  • PaperBench +34.4%
  • FrontierCS +9.2%
  • PassNet +14.0%

볼트가 에이전트-스킬에 축적해 온 자산들(ponytail·scientific-agent-skills·academic-research-skills)은 전부 스타 수가 근거의 자리를 대신하고 있었다. 이 논문은 처음으로 백본·하네스·예산을 고정한 대조 실험을 내놓았다 — 스킬 층이 독립적으로 기여한다는 주장이 처음으로 실험 설계의 형태를 갖췄다.

⚠️ 전부 상대 증가율이고 절대 점수가 없다

+134.3%는 상대 개선이다. MLE-bench의 무스킬 baseline이 얼마인지 초록에 없다. 2%→4.7%도 +134.3%이고 30%→70%도 +134.3%다. 두 해석의 실무 함의는 완전히 다르다. 볼트 규칙을 여기에 적용한다 — “개선폭은 분모를 모르면 크기를 모른다.” MLE-bench 계열은 통상 절대 성공률이 낮은 벤치이므로 낮은 분모 위의 큰 상대 증가일 가능성을 배제할 수 없다. 본문 확인 전까지 이 수치를 “스킬이 성능을 2.3배로 만든다”로 인용하지 않는다. 그 외 미확인: “검증된(verified)” 스킬의 검증 절차, 5,000개의 중복도, AREX 라이브러리 공개 여부, 백본을 GPT-5.5 외 모델로 바꿔도 유지되는지(백본 일반화 미검증).

같은 배치 안에 스킬 생산의 세 층위가 동시에 있다

이번 회차는 우연히 스킬의 전 스펙트럼을 한 배치에 담았다:

  1. 수작업 단일 규범 — ponytail: 사람이 쓴 규범 1개, ⭐122,495
  2. 경험 기반 자동생성 — hermes-agent: 실행 경험에서 스킬을 만들고 사용 중 개선, ⭐240,408
  3. 코퍼스 증류 — 본 논문: 레포 1,000개 → 스킬 5,000개, 정량 근거 보유

셋의 관계가 이번 배치의 축이다. 1은 스타를, 3은 근거를 가졌다. 2는 둘 다 주장하지만 오픈이슈 38,696건이 그 주장에 붙어 있다. → 에이전트-스킬에 생산 방식 축(수작업/경험/증류) 을 새로 추가한다.

도메인별 추출 (ai-news)

  • 신뢰도: ⭐⭐⭐ medium — HF API 실검증(업보트·저자·날짜 high) · 데일리 1위 업보트 334는 최근 배치 최상위권(Agentic-Game-Development 136 대비 2.5배). 단 절대 점수 부재로 효과 크기 판정 불가.
  • 즉시 활용: 부분 YES. 라이브러리 공개 여부와 무관하게 “레포 → 스킬 증류”라는 절차 자체는 지금 복제 가능하다. 볼트는 이미 레포를 소스 페이지로 인제스트하고 있는데, 그것은 “무엇이 존재하는가” 를 적는다. 이 논문이 요구하는 건 “어떻게 작동시키는가” 다 — 같은 레포에서 다른 것을 뽑는다.
  • 6개월 영향력: 높음. 스킬 층이 실험으로 방어되는 첫 사례이므로, 이후 스킬 자산은 “스타” 가 아니라 “고정 백본 대조 실험” 을 요구받게 될 가능성이 크다. 볼트의 에이전트-스킬 평가 기준도 여기에 맞춰 올린다.
  • 대체 관계: ponytail류 수작업 규범을 대체하지 않는다 — 상보적이다. ponytail은 “하지 마라”(억제)이고 AREX는 “이렇게 하면 된다”(운영지식)다. 억제 규범은 증류로 안 나온다 — 레포에는 실패 사례가 안 적히기 때문이다.
  • 허와 실: 실은 “5,000개의 검증된 스킬”이라는 숫자보다 “고정 통제 아래 스킬만 토글”이라는 설계다. 숫자는 재현 불가하지만 설계는 누구나 복제할 수 있다.
  • 액션: 본문에서 MLE-bench 절대 점수를 확인한다(높음). AREX-Skill Library 공개 URL 확인(높음). 볼트 스킬 문서에 운영지식 층을 명시적으로 분리(중간).

미해결 질문

  • 절대 점수는 얼마인가 — 이 배치에서 가장 중요한 미확인 값.
  • “검증된(verified)“의 절차는? 스킬이 작동함을 무엇으로 확인했나. 자기검증이면 검사가능성-공사의 급소(검사기가 피검사자와 같은 실패 모드를 공유하면 거울이다)에 그대로 걸린다.
  • 178개 역량군의 경계는 누가 그었나 — 사람인가 모델인가. 모델이면 분류 자체가 백본 편향을 물려받는다.
  • 스킬 5,000개를 어떻게 검색하나 — 태스크마다 5,000개를 다 로드할 수 없다. 선택 메커니즘이 곧 성능인데 초록에 없다. (CoGR의 “아이템 측 표현을 생성해 색인한다” 와 같은 문제다.)
  • hermes-agent의 경험 기반 스킬과 품질 비교가 가능한가?

📊 2026-09-06 재관측 (HF API 실측) — 업보트가 56% 늘었다

업보트 520 — 볼트 09-03 기록 334 대비 +186(+55.7%). raw 09-06 수집값 520과 일치. 09-05·09-06 배치 통틀어 업보트 1위.

이 논문이 세운 기준이 이번 배치의 평가 잣대로 실제 사용됐다

“백본·하네스·실행예산을 고정한 채 변수 하나만 토글” 이라는 설계 기준으로 09-05·09-06 배치를 채점한 결과:

  • 충족: Qwen3.8-27B-GSQ-RCO-GGUF — 동일 파일 크기(8.4GB) 고정 후 양자화 기법만 비교(vs Unsloth UD-IQ2_S: AIME25 +10.00 · GPQA-D +8.59 · LCB +4.57). 모델 카드가 이 기준을 충족한 첫 사례.
  • 충족: Minima — 496개 선형층 전부를 NVFP4로 내리고 BF16과 대조(5과제 평균 -0.52)
  • 미충족: spec-kit · ECC · hermes-agent · Qwen3.8-27B-GGUF — 전부 정량 대조 없음

미해결 질문(MLE-bench 절대 점수)은 여전히 미확인이며, 업보트 520은 그 공백을 메우지 않는다.
