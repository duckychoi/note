Rufus-Air: An Open LLM Post-Training Recipe

핵심 인사이트 — 기여가 모델이 아니라 순서다

GLM-4.5-Air-Base(106B-A12B) 위에서 SFT → Reasoning RL → Coding RL → Instruction-Following RL → General Agent → Coding Agent → Search Agent → RLHF 를 8단계 직렬로 돌린 재현 가능 레시피다. 🎯 네 주장 중 세 번째가 핵심이고 실무적이다: “리워드 신뢰도가 단계 순서를 정하는 실용 원칙이다.” 즉 순서는 임의가 아니라 검증 가능한 리워드를 먼저, 애매한 리워드를 나중에 둔다는 뜻으로 읽힌다 — 실제로 목록이 그 순서다(reasoning/coding = 검증 가능 → agent = 중간 → RLHF = 사람 선호로 가장 애매). 📌 이것은 볼트가 검사가능성-공사 에서 누적한 축과 정확히 만난다: “검사 가능한 것과 아닌 것을 구분하라” 가 여기서는 학습 파이프라인의 배치 원칙으로 나타난다. 지금까지 볼트 사례는 전부 결과 표기(4상태 어휘·3값 등급)였고, 이건 그 구분을 공정 설계에 쓴 첫 사례다. 나머지 주장: (i) 다양·고품질 SFT 가 능력 하한선을 만든다 (ii) 난이도 필터링이 RL 프롬프트를 생산적 구간에 유지한다 (iv) 인프라·엔지니어링 선택이 구현 세부가 아니라 레시피의 일부다.

🎯 부차 — 무엇을 쓰지 않았는지를 명시한다

“새 사람 주석도 사내 증류 교사 모델도 쓰지 않고, 공개 구성요소와 공개 데이터를 대체로 released 상태 그대로 사용했다.” 이 문장이 레시피의 재현 가능성을 실질적으로 결정한다 — 사내 교사 모델이 끼면 외부인은 재현할 수 없다. 부재를 명시한 것은 자기제한-명시 이면서 동시에 재현성 주장의 핵심 근거다. 🔴 단 “대체로(largely)” 라는 한정어가 있다. 전부가 아니다. 어디가 예외인지는 초록에 없다.

🔴 초록에 정량 수치가 0개다 — 대조 불가 상태로 수록

성능 주장 전문: “공식 GLM-4.5-Air 포스트트레이닝 릴리스를 improves over 하고, 유사 규모 공개 모델과 competitive”. 벤치마크 이름·점수·표가 초록에 하나도 없다. ✅ 수집기가 “수치 0개” 를 0개라고 밝힌 것은 정확하며(볼트 재확인 일치), “competitive with” 를 SOTA 로 승격하지 않은 것도 옳다 → 한정어-탈락 방지 11배치 연속. 🔴 그러므로 이 페이지의 reliability 는 low 다. 방법론 서술은 풍부하나 주장을 검사할 수단이 볼트에 없다. 8단계가 실제로 이득을 냈는지, 단계 순서가 정말 중요한지 확인되지 않았다 — 논문이 그렇게 말한다는 것만 확인됐다. 📌 이것이 검사가능성-공사 의 재귀적 아이러니다: 검사가능성을 원칙으로 내세운 논문의 주장을 볼트가 검사할 수 없다.
