SimuVerity — “컴파일된다”와 “공학적으로 맞다”를 분리한 벤치마크

arXiv/HF: https://huggingface.co/papers/2610.02304 업보트 6 (HF 데일리 4위) · publishedAt 2026-10-01 독립 검증: HF API 업보트 6 일치 · 수집기 42.86 정확 · 🆕 arXiv HTML 전문 353,859B 열람 → 게이트 3단 수치 신규 확보

핵심 인사이트

구조적 유사도는 공학 성능의 대리 지표가 아니다. 이 벤치는 컴파일·실행·참조모델 유사도를 합격 조건으로만 쓰고, 점수는 공학 요구 충족으로 낸다. 10개 공학 도메인 101개 과제, 에이전트 6종 평가. 📌 최고 시스템 42.86점.

🏆 본문 전용 — 게이트 3단이 계단식으로 떨어진다

최고 시스템의 단계별 통과율: ① 산출물 제출 94.72% → ② native 실행성 86.47% → ③ 공학 자격 76.90% → 최종 종합 42.86 🔴 ③과 최종 사이에 34점이 사라진다. 논문 표현: “제출되고 실행 가능한 후보 일부가 자격 있는 공학 구현을 이루지 못한다” · “얕은 성공은 다차원 평가를 대체할 수 없다”. 🎯 볼트에 직접 적용된다 — “돌아간다”를 품질로 센 기록이 있다면 전부 ②층 값이다. ②86.47 → 최종 42.86 은 2배 차이다.

6개 채점 차원이 공개돼 있다

정확도 · 출력품질 · 기계적 충실도 · 제어/인과 정합 · 운전영역 강건성 · 동적 응답. ⚖️ 뒤의 4개는 코딩 벤치에 없는 축이고, “코드가 맞다” 와 “시스템이 맞다” 를 분리한다 → 검사가능성-공사 의 공학 도메인 최대 사례.

도메인별 추출 (ai-news)

  • 신뢰도: ⭐⭐⭐⭐ — 본문 전문 + 게이트 3단 + 6차원 + 평가기 타당성 절(§Evaluator Validity) + 전문가 수동 분류(최고 시스템 31개 후보 중 8개를 전문가가 분류) 보유. 🔴 업보트 6 = 배치 최저이고 Simulink 도메인은 좁다.
  • 즉시 활용: NO(Simulink 없음) — 🎯 그러나 평가 구조는 즉시 쓴다. 제출 → 실행 → 자격 → 다차원 점수 4단은 reat 렌더 결과 검수와 tools-frontend 검증에 그대로 대응한다. 볼트는 현재 ②(렌더 성공)까지만 센다.
  • 6개월 영향력: 에이전트 벤치마크가 “통과/실패” 에서 “통과시킨 뒤 품질을 따로 재기” 로 이동한다. HyperBrowseComp 가 같은 날 같은 방향(사전 배제 후 채점)이다.
  • 대체 관계: 코드 유사도 기반 평가(참조모델 대조)를 기각한다. HWE-Bench 등 하드웨어 수리 벤치와 인접하나 겹치지 않는다.
  • 허와 실: 🎯 42.86 을 “에이전트가 공학을 못한다”로 읽으면 과하다 — 분모가 101과제 × 10도메인 × 6차원이고 도메인 간 격차가 본문에 별도 절(§4.4)로 있다. 평균 42.86 은 고르게 못하는 것과 몇 도메인만 0 인 것을 구분하지 못한다(🔴 §4.4 미열람).

당장 할 것

볼트 자체 검수에 “③ 자격 게이트”를 신설한다. 현재 reat 는 렌더 성공 = 통과 다. SimuVerity 구조를 베끼면 ③에 “장면이 대본 요구를 충족하는가” 가 들어가야 하고, 이것이 지금 없다. ②와 최종 사이 2배 격차가 남의 벤치에서 측정된 값이다.

에이전트 6종의 이름을 확보하지 못했다

본문 §4.1 Agent Systems 절이 HTML 에서 제목만 추출되고 명단이 안 잡혔다(표 내부 가능성). 🔴 “최고 42.86” 의 주인이 누군지 모른다 — 상용 에이전트면 함의가 크고, 소형 오픈소스면 작다. ⚠️ 미확인으로 남긴다.
