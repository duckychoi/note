debpalash/VoiceStudio — 모델이 아니라 하네스다

2026-09-14 갱신 — ⭐ 27,850(11일 +12,396 · +80.2%) · 이 배치 최대 성장 · 🔴 중복 재배달

GitHub API 실호출(2026-09-14): ⭐27,850(raw 27,835 대비 +15) · fork 3,427(raw 3,423, +4) · 이슈 52 · AGPL-3.0(일치) · Python · created 2026-04-09(일치) · pushed 2026-09-11 🔴 신규 아님. 이 페이지는 2026-09-03 생성(당시 ⭐15,454). raw가 “볼트 미보유” 로 오판 → 백필-우회 📈 11일 만에 ⭐15,454 → 27,850 (+12,396 · +80.2%) — 볼트가 추적 중인 레포 중 기간 대비 최고 증가율. raw는 당일 증분을 +2,632(당일 AI/ML 최대) 로 보고했다. 🔴 raw가 새로 가져온 한정어 — 채택한다: “646개 언어” 는 TTS 카탈로그 엔진들의 합계이고, 같은 표가 바로 옆 칸에 “실제 커버리지와 품질은 선택한 엔진에 의존” 이라고 적는다. 엔진 무관 646언어가 아니다. ⚠️ 추가 확인: 전체가 액티브 베타 표기 · main은 릴리스 간 변경 가능 명시 · GPU 선택(CUDA/MPS/ROCm, VRAM 4GB) · CPU 모드 지원 · 앱은 AGPL-3.0이나 내려받는 모델은 각자의 상위 라이선스(카드 명시) · 구 이름 OmniVoice-Studio. ✅ 09-03 페이지의 “27개 엔진” 표기와 raw의 “TTS 16 + ASR 11” 이 정확히 일치(16+11=27). 구성 내역이 이번에 처음 분해됐다. 🎯 GitHub description이 646을 무조건적으로 광고한다 — “in 646 languages”. README 표의 한정어가 description에는 없다. 같은 레포의 두 표면이 다른 강도로 말한다 → 한정어-탈락 의 전형.

핵심 인사이트 — TTS 모델이 아니라 27개 엔진 위의 껍데기다

raw는 이것을 “ElevenLabs 대체 스택” 으로 기록했으나, README 실물을 열자 성격이 달라진다: 16개 TTS 엔진 · 11개 ASR 엔진을 카탈로그에서 단축키(Ctrl/Cmd+E)로 갈아 끼우는 데스크톱 앱이다. → 이 레포의 자산은 음성 모델이 아니라 “27개 엔진을 하나의 워크플로로 통일한 통합층” 이다. 볼트가 SolarWM에서 같은 날 기록한 “백본 네이티브 표현을 보존한 채 공통 인터페이스로 묶는다” 와 구조적으로 같은 패턴이다 — 하나는 비디오 월드모델, 하나는 음성 엔진. 실행 범위: CUDA · Apple Silicon MPS/MLX · ROCm · CPU · 원격 워커 옵션, macOS 13.3+/Windows 10·11/Linux(glibc 2.39+)/Docker.

⭐ MCP 서버와 OpenAI 호환 오디오 API를 내장한다 — 내 파이프라인에 바로 붙는다

인터페이스가 넷이다: 데스크톱 앱 · 로컬 REST/SSE/WebSocket API · OpenAI 호환 오디오 API · MCP 서버. 이게 이번 배치에서 나에게 가장 직접적인 항목이다. 내 reat-voice 워크플로(대본 → 음성 MP3 + 자막 SRT)는 현재 외부 TTS에 의존하는데, 이 레포는:

  • OpenAI 호환 오디오 API → 기존 호출 코드를 엔드포인트만 바꿔 로컬로 전환 가능
  • MCP 서버 → 에이전트가 음성 생성을 툴로 직접 호출
  • ASR 11종 내장 → 자막(SRT) 생성까지 같은 스택에서
  • “로컬 워크플로에는 계정·API 키·구독·사용량 미터가 없다”(README 원문) → actionable 등재(우선순위 높음). 이번 배치 13건 중 내 기존 작업에 그대로 꽂히는 유일한 항목이다.

⚠️ "646개 언어"는 레포 자신이 이미 한정하고 있다

raw는 “646개 언어 지원 범위와 음질 비교는 근거 미확인” 으로 적었다. README를 열자 레포가 스스로 단서를 달아 뒀다:

“646 TTS languages; actual coverage and quality depend on the selected engine”

즉 646은 통합된 엔진들의 언어 카탈로그 합집합이지 이 소프트웨어가 보증하는 품질 범위가 아니다. 과장 주장이 아니라 명시적으로 한정된 주장이었다. → 볼트 규칙 확인: 자체 주장을 의심할 때 README 원문을 먼저 연다. 이번 배치에서 GLM-5.3은 원문을 열어도 자체 표뿐이었지만, 여기서는 원문이 raw의 의심을 해소했다. 09-02의 “배지를 근거로 쓰지 않는다” 규칙의 역방향 적용 사례 — 원문이 주장을 약화시키는 쪽으로 정확했다. 추가로 README가 스스로 붙인 경고: > [!WARNING] Active beta. — main은 릴리스 간 변경될 수 있으니 최신 릴리스를 쓰라고 명시.

라이선스는 두 층이다 — AGPL-3.0은 앱에만 걸린다

README 원문: “AGPL-3.0 application; downloaded models keep their upstream terms.”

  • 앱 층: AGPL-3.0 → 네트워크 서비스로 제공하면 소스 공개 의무가 걸린다. 개인 로컬 사용은 무관하나 SaaS에 임베드하면 정면으로 걸린다.
  • 모델 층: 내려받는 16+11개 엔진은 각자의 상위 라이선스를 유지한다. 상업적 사용 가부는 엔진마다 따로 확인해야 한다. → 볼트 09-02 규칙(NOASSERTION은 “정보 없음”이 아니다)의 확장 케이스다. 여기는 SPDX가 깨끗한 AGPL-3.0인데도 실질 조건은 2층이다. 개인 워크플로 = 문제없음 / 제품 임베드 = 엔진별 심사 필요.

이슈 12건 — 이번 배치 최저 부채, 그런데 해석이 갈린다

포크당 이슈 0.0056건(12/2,157)으로 chrome-devtools-mcp(0.0261)의 4.7분의 1, hermes-agent(0.786)의 140분의 1이다. 그러나 “활발한 베타”를 자칭하는 5개월 된 앱에 이슈가 12건이라는 것은 성숙의 증거로만 읽히지 않는다. 대안 해석 둘:

  1. 실사용자가 아직 적다(⭐15,454 대비 워치 73은 배치 내 최저 관심 밀도 — hermes-agent 939·ponytail 304)
  2. 문제 보고가 Discord로 흡수된다(README에 Discord 커뮤니티 배지 명시) → 볼트의 08-30 규칙(이슈는 사용 깊이의 대리 지표이나 단조 증가를 가정한다)에 세 번째 단서를 추가한다: 이슈 트래커 밖에 채널이 있으면 이슈 수는 사용량을 잰 것이 아니다.

도메인별 추출 (ai-news · 교차 video-saas)

  • 신뢰도: ⭐⭐⭐⭐ high — GitHub API + README 원문 실검증. 주장이 스스로 한정돼 있고 베타 경고·라이선스 2층 구조를 레포가 먼저 밝힌다. 이번 배치에서 서술 정직성이 가장 높은 레포.
  • 즉시 활용: YES — 배치 유일. OpenAI 호환 API + MCP 서버 조합으로 reat-voice 파이프라인의 로컬 대체 후보. 설치 비용도 낮다(플랫폼별 패키지 배포).
  • 6개월 영향력: 중~높음. 음성 스택이 “어느 모델을 쓸까” 에서 “어느 껍데기에 꽂을까” 로 옮겨간다면, 개별 TTS 모델의 교체 비용이 0에 수렴한다. 이는 kyutai-labs 같은 단일 모델 배포자에게 불리한 방향이다.
  • 대체 관계: ElevenLabs(상용 API) 대체를 표방하고, 내 워크플로에서는 외부 TTS 호출을 대체할 수 있다. 반대로 개별 엔진을 대체하지는 않는다 — 엔진을 소비한다.
  • 허와 실: 마케팅을 걷어내면 “27개 엔진 런처 + 워크플로 UI” 다. 그런데 그게 정확히 필요한 물건이다. 음질은 이 레포가 아니라 고른 엔진이 결정한다.
  • 액션: 로컬 설치 후 reat-voice 대체 스팟체크(높음). 엔진 목록 16+11종 확인 후 한국어 품질 상위 엔진 특정(높음). 제품 임베드 검토 시 엔진별 라이선스 심사(보류 — 개인 사용에는 불필요).
